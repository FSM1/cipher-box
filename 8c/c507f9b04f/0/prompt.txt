<result># Security review: PR #2145 (`git diff main...HEAD`)

None of these findings is a vulnerability that an attacker can exploit. No row is ever adopted under the wrong seed, so data stays fail-closed. Finding 1 is a defect in trust reporting: it can send a false abuse report against an honest writer.

## Finding 1, MEDIUM: the item 3 fix is narrowed, not complete

**Where:** `crates/engine/src/sync/pass.rs:483`, `crates/engine/src/facade.rs:8686`

**Mechanism:** `walk_scopes` sets `boundary_walk_ran` to true before it does its work. `descendant_scope_roots` is filled only after the walk's awaits finish, and only when the walk returns `Ok`. Three paths leave the flag true while the set stays empty:

- **(a) A pass is mid-walk.** The tick loop is a spawned task and does not take the command write lock (`crates/wasm/src/host.rs`). A `SetFocus` that arrives while the first pass awaits inside `descendant_scope_roots` sees the flag as true and skips the inline walk.
- **(b) The walk fails.** The walk returns `Err`, which includes `WalkFailure::Unavailable` on a cold network.
- **(c) The walk never starts.** `held_root` or `sweep_keys` is `None`, and `walk_scopes` returns at once.

**Failure:** In each case `navigation_file_legs` gives a shared folder's rows to the root scope. It reads them under the vault seed, the child gate rejects them, and the engine emits a false attributable-abuse event. This is the bug that item 3 sets out to fix.

**Fix:**
1. Set the flag only after `install_descendant_scopes`, on `Ok`. Rename it to state that meaning, for example `boundary_walk_landed`.
2. In `refresh_focus_on_access`, do not run the inline walk again while that flag is false. Skip the folder and file legs and keep the rows queued for the tick. A retry on each `SetFocus` would run a full root adopt and walk on every navigation, with no `stale_after` damping.

## Finding 2, LOW: the inline walk can overlap a pass's root adopt

**Where:** `crates/engine/src/sync/pass.rs:222-229`

**Mechanism:** If a pass that a cadence or an earlier command started has not yet reached `walk_scopes`, the inline walk runs `refresh_floors`, `adopt_root` and `walk_scopes` at the same time as that pass.

**Failure:**
- The inline adopt is `CacheFirst`. If it reads sequence N after the pass has committed floor N+1, `resolve.rs` reports a strictly older sequence as a `TrustViolation`. That is a false trust event on the vault root.
- `deposit_seed` overwrites without a check. The `Current` arm can therefore write back an older read seed that has a lower stamp. This heals itself: the next `refresh_seed_floor` evicts it.

**Fix:** Skip the inline walk while a pass is in flight. `sync_status.reconcile_started` is a candidate in-flight marker. The fix for finding 1 removes most of this window.

## Finding 3, LOW (freshness, not security): on desktop, root rows push out the rows of folders in use

**Where:** `crates/engine/src/sync/tick.rs:128`, `crates/engine/src/sync/pass.rs:688`

**Mechanism:**
- Desktop never sets `open_folder`, so the root now always takes navigation's slot.
- `in_view.rev()` queues the root's rows last, which makes them the newest.
- A full queue and `leg_file_share` both drop the oldest bulk rows first.

**Failure:** On a desktop cold start over a root with many files that have no size yet, each pass spends its 64 resolves on root rows. The bulk rows of the touched folder wait about one pass for each 64 root files.

**Fix:** Put the root in the slot only when `touched_folders` is empty, or queue it first so it has the lowest priority.
