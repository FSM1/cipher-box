Plan 67-01, Tasks 1 and 2 use the pattern:
```
npx tsc --noEmit -p tsconfig.json 2&gt;&amp;1 | grep -E "republish-schedule.entity" || echo "entity-file-clean"
```
The plan explicitly states the slimmed entity intentionally breaks service callers until 67-07. This means `tsc` will emit errors for OTHER files, and `grep` will not match the entity filename in those unrelated error lines — causing `|| echo "entity-file-clean"` to print, exiting 0 unconditionally. The verify passes whether or not the entity file was correctly modified. The file-content grep checks in `&lt;acceptance_criteria&gt;` are the real gate here.
