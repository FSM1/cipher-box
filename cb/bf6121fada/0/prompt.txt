## PR

**#1118** — https://github.com/FSM1/cipher-box/pull/1118 — `feat/fuse-ranged-read-and-plaintext-chunk-cache`, **left as DRAFT**. Two commits: the feature, then the review-gate fixes.

## What I implemented

- **`OperationCore::read(handle, offset, size)`** (`crates/fuse/src/ops.rs`) over `Engine::read_stream`. The engine would serve any window in one call; the loop exists to frame the window into cache-aligned blocks, so a hit answers from memory and a miss costs exactly the sealed chunks it covers. Short block = EOF; a window past the end is empty, not an error.
- **Per-handle stream lifetime** (`handle.rs`): `OpenFile` carries `Option&lt;StreamHandle&gt;`, attached lazily on first read (a write-only handle and an unread file pay neither a resolve nor a slot against `MAX_OPEN_STREAMS`). `release` closes the stream and drops its plaintext; new `unmount()` does it for every open handle. Reading through a write-only handle is `BadHandle`.
- **`crates/fuse/src/cache.rs`** — the bounded plaintext LRU. Byte-bounded, LRU-evicted, block size matched to the content chunk framing. Every block is `Zeroizing&lt;Vec&lt;u8&gt;&gt;`, so zeroization rides `Drop` on every exit path — eviction, re-insert, oversized refusal, release, unmount, and a teardown that never calls `unmount` (v1's only zeroization point was a `destroy()` callback, so a forced unmount left plaintext in RAM).
- **`Invalidation::Data { ino }`** is now constructed: opening a stream verifies a head version the kernel's page cache may predate.

**The design question the issue required settling:** the cache sits **above** the facade. ## #1063 — idle body ends on a signal, not a deadline

`bodies` now maps a request id to `{ port, controller, pull }`, the controller captured in the stream's `start` (which runs synchronously inside the `ReadableStream` constructor, so the body is registered before `respond` returns). A private `takeBody` drops everything keyed to a request — entry, armed deadline, sink, and the resolver of any in-flight pull — and returns `null` if another path already ended it. ## #1097 — killed worker reclaimed by a signal

`MediaPipe.requestPorts()` asks every window client to re-broker; `installServiceWorker` calls it at script evaluation — the only signal available, since a restarted worker fires no `install` and no `activate` (the same reason the app-shell precache already re-learns there). ## What I implemented

The **conditional edit** rule — the write-plane sibling of the conditional delete, and the edit-vs-edit row `blueprint/engine.md`'s rebase table was missing.

`OpKind::UpdateContent` now carries `base_version_cid`: the `contentCid` of the head version the edit was formed against, minted when the write handle opens (not at commit — the whole upload sits between the two). `rebase_update_content` dead-letters `BaseSuperseded` when the base's projected head is not that one; `publish_update_content` re-checks against the freshly resolved live record twice, once before spending the upload and once with the upload behind it. The loser keeps its staged version (preserved, openable) and surfaces as `Event::DeadLetter`; it retires nothing, because its own CIDs may already be registered from a halted upload of the version now at the name. A device with no projected head resolves one at `beginWrite` before anything is spent. The drain projects the head its own publishes established via `project_child_version`, so a device never reads its own landed publish as a concurrent writer.

**Key correction during review:** my first cut anchored on the version *count*. That is broken two ways — a queued predecessor and a concurrent writer advance a count identically (so the second of two queued edits published straight over the writer that beat the first: the original bug, reached with two local edits), and `RetentionPolicy::KeepLatest` moves a count backwards. The identity anchor is immune to both, and makes a queued successor inherit its predecessor's dead letter for free.
