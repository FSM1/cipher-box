<objective>
Route the web shared-write hook through the new SDK client methods from plan 48-03 and turn `useSharedNavigation`'s `folderChildrenRef`/`sequenceNumberRef` into event-fed projections (REQ-3 / #8). Purpose: Completes REQ-3 — the SDK is the single source of truth for shared-folder state; the web can no longer drift the refs out of sync with the SDK.
Output: A projection-only `useSharedWriteOps`, an event subscription in `useSharedNavigation`, and a web unit test proving the hook reads nothing back.
</objective>

## Trust Boundaries

| Boundary | Description |
| -------- | ----------- |
| web ref ↔ SDK shared state | Refs must be write-only-by-event; never read back into the SDK |
| per-share event routing | A sharedFolder:updated event must only update the matching active share's projection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --------- | -------- | --------- | ----------- | --------------- |
| T-48-09 | Tampering | useSharedNavigation refs | mitigate | Refs written only by the sharedFolder:updated subscription filtered on `event.shareId === currentShareId`; write hook reads nothing back — eliminates web/SDK shared-state drift (Tasks 1-2, asserted Task 3) |
| T-48-10 | Tampering / Elevation | cross-share projection | mitigate | Subscription ignores events whose shareId != active share — no cross-share state bleed at the projection layer (Task 3 mismatch case) |
| T-48-11 | Information Disclosure | revocation handling | accept | withRevocationGuard retained for 403 detection; no key material newly exposed; addShareKeysFn passed into the SDK is the same callback as today |

</threat_model>
