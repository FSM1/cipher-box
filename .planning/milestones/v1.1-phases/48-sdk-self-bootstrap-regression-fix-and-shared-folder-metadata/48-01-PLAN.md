| IPNS network → SDK in-memory folderTree | A stale IPNS-resolved snapshot crosses into authoritative in-memory state on the self-bootstrap path |
| prior local write → subsequent self-bootstrap (same session) | A just-written (fresher) sequence must survive a later resolve that lags it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --------- | -------- | --------- | ----------- | --------------- |
| T-48-01 | Tampering | `loadFolder` folderTree.set (client.ts ~385) | mitigate | Sequence-guard: never overwrite `existing` when `existing.sequenceNumber >= result.sequenceNumber`; stale IPNS snapshot cannot resurrect deleted items or revert a restored version (Task 2) |
| T-48-02 | Denial of Service | `ensureFolderLoaded` self-bootstrap | mitigate | Guard suppresses only the SET when an entry exists AND is fresher; a genuinely-absent folder still resolves — prevents re-introducing the #498 "Folder not loaded" failure (Pitfall 1, verified by ensure-folder-loaded.test.ts) |
| T-48-03 | Information Disclosure | folderTree key material | accept | No new key paths; FolderTree.set/delete/clear already zero key material (CLAUDE.md rule 9); this plan only changes the set/skip decision, not key handling |
