<objective>
Teach the SDK client to OWN shared-folder state (REQ-3 / #8), mirroring the Phase-47 owned-path single-ownership model. Per D REQ-3 (research Pattern 2, decision A4): add a SIBLING `sharedFolderTree` keyed by `shareId` (NOT extend `folderTree` — shared folders carry a distinct `SharedWriteContext` and can collide on `ipnsName`). Add a `sharedFolder:updated` event and client methods that own publish + sequence bookkeeping, delegating the actual write to the existing `share/shared-write.ts` functions (which already route through `publishWithCas`).

Purpose: This is the contract-defining plan for the share path. It defines the new client method signatures, the `SharedFolderState` type, and the `sharedFolder:updated` event so plan 48-04 can wire the web hook against a stable contract without exploring the codebase.
Output: `SharedFolderTree`, `SharedFolderState`, `sharedFolder:updated`, and five client methods + a `loadSharedFolder` loader, all unit-tested.
</objective>

## Trust Boundaries

| Boundary | Description |
| -------- | ----------- |
| per-share context isolation | Each shareId carries distinct owner+recipient pubkeys, IPNS key, and addShareKeys callback — must not bleed across shares |
| web write hook → SDK client | Shared writes now route through client methods that own state, not web refs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --------- | -------- | --------- | ----------- | --------------- |
| T-48-06 | Information Disclosure | sharedFolderTree key material | mitigate | Keyed by shareId; SharedFolderTree.delete()/clear() zero folderKey + ipnsPrivateKey (CLAUDE.md rule 9); set() clones buffers so caller buffers aren't zeroed (Task 1) |
| T-48-07 | Tampering / Elevation | cross-share state bleed | mitigate | Separate sibling map keyed by shareId (NOT ipnsName) prevents owned/shared collision and cross-share context mixing (A4); isolation test asserts two shareIds with same ipnsName stay independent (Task 2) |
| T-48-08 | Tampering | shared publish CAS | mitigate | Delegate to shared-write.ts → publishWithCas (the one CAS engine); no second retry loop in client methods (Don't-Hand-Roll, Task 3) |

</threat_model>
