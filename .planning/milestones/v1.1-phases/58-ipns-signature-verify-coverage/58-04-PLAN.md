<objective>
Add a single shared cross-language IPNS verify test-vector fixture consumed by BOTH the
Rust and the sdk-core test suites, so any drift between the Rust and JS byte-construction
of the signed IPNS record (the "ipns-signature:" prefix + CBOR data) fails an already-
required CI check (D-11/D-12).

Purpose: Each language's verify tests today independently hard-code the signed-bytes
construction. Without a shared vector, byte-construction drift passes both suites while
making Rust and JS silently disagree on which records are valid — the exact cross-language
interop bug class this phase must defend against. The expanded 7-case set (beyond the
ROADMAP's original 4) pins every posture decision from 58-01, including the
security-load-bearing partial-fields (downgrade) and seq-mismatch cases.

Output: A generated `tests/vectors/ipns/verify.json` (7 cases), a Rust consumer test in
`crates/fuse/tests/` (NOT the crypto crate — see the dependency-cycle note below), and an
sdk-core vitest consumer loading the same JSON.
</objective>

<threat_model>

## Trust Boundaries

| Boundary | Description |
| -------- | ----------- |
| Rust verify construction ↔ JS verify construction | The two languages independently build the signed bytes ("ipns-signature:" prefix + CBOR data) and the binding comparison. The shared vector is the contract that keeps them byte-identical. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --------- | -------- | --------- | ----------- | --------------- |
| T-58-16 | Tampering | silent Rust↔JS byte-construction drift (one side accepts a record the other rejects) | mitigate | D-11/D-12 single shared fixture consumed by both cargo test and sdk-core vitest; a divergence fails an already-required CI check. |
| T-58-17 | Tampering | regression of the partial-fields downgrade defense (PR #529) | mitigate | The `partial-fields` vector asserts "invalid" on both sides; any relaxation breaks the gate. |
| T-58-18 | Tampering | regression of the CID/sequence binding (58-01) on either side | mitigate | `cid-swapped` + `seq-mismatch` vectors carry VALID signatures over mismatching data, so only the binding can reject them — they fail loudly if the binding is removed/weakened. |
| T-58-SC | Tampering | npm/cargo installs (cborg dev-dep if added in 58-01; no new packages here) | accept | No new package installs in this plan; the generator uses existing @cipherbox/core. RESEARCH.md Package Legitimacy Gate: SKIPPED (no new installs). |

## Residual Risk

These are test-only artifacts (fixture + two consumers + a committed generator). The fixture
is generated offline and committed; the only residual risk is a fixture that does not
actually pin the real construction (e.g. mocking the binding away) — explicitly prevented by
the acceptance criteria requiring the REAL verify/decode path and REAL `data` bytes. No
runtime/product behavior changes; no HIGH-severity path.
</threat_model>
