<objective>
De-duplicate the web vs sdk-core IPNS resolve/verify implementations (D-13): the web
imports `resolveIpnsRecord` from `@cipherbox/sdk-core`, threading the web axios instance
via the SdkContext/ctx arg, and deletes its local `verifyIpnsSignature` +
`resolveIpnsRecord` duplicates — while preserving the `withPerf('ipns:resolve', …)`
timing and keeping the existing call signature so no consumer changes.

Purpose: The web has carried a hand-maintained near-identical copy of the sdk-core
verify/resolve path, kept in lockstep manually — a divergence risk every time the
verify logic changes. 58-01 just added CBOR cid/sequence binding to the sdk-core copy
and converged the Rust↔JS posture (D-05), making the two implementations behaviorally
identical and the collapse safe. Removing the web copy eliminates the lockstep liability
and ensures the web automatically gets the 58-01 binding.

Output: apps/web/src/services/ipns.service.ts with the local verify/resolve duplicates
removed and a thin delegating wrapper to the sdk-core function, axios injected via ctx,
withPerf preserved, all 14 callers unchanged.
</objective>

## Trust Boundaries

| Boundary | Description |

| Web service layer → sdk-core resolve chokepoint | The web previously had its own verify path; after dedup it crosses into sdk-core's single chokepoint, which now carries the 58-01 CBOR binding. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --------- | -------- | --------- | ----------- | --------------- |
| T-58-13 | Tampering | divergence between the web verify copy and the sdk-core chokepoint (lockstep drift) | mitigate | D-13 collapses the two into one path; future verify changes (e.g. binding) apply everywhere automatically. The unified D-05 posture makes the collapse behaviorally identical. |
| T-58-14 | Spoofing / wrong-context call | web delegating without threading its axios instance (calls would route through the wrong/unauthenticated client) | mitigate | Thread `apiAxios` via ctx.axiosInstance (D-13); the api-client singleton is already registered to apiAxios, so the singleton fallback is also correct — explicit ctx makes it unambiguous. |
| T-58-15 | Tampering | accidentally dropping the partial-fields/CBOR-binding checks during deletion (downgrade) | mitigate | The web copy is DELETED, not relaxed — the sole remaining path is the sdk-core chokepoint that retains partial-fields fail-closed (PR #529) + the new 58-01 binding. Typecheck proves the delegation compiles; 58-04 cross-language vectors pin the behavior. |

## Residual Risk

No behavior change is intended — this is a dedup. The risk is a mechanical regression
(wrong axios, lost perf, a caller signature break). All are covered by typecheck + the
unchanged-signature acceptance gate. Security posture is strictly non-decreasing: the web
inherits the 58-01 binding it did not previously have. No HIGH-severity path introduced.
