Create `.github/workflows/build-desktop.yml` with the following content:

```yaml
name: Build Desktop

on:
  release:
    types: [published]

permissions:
  contents: write

jobs:
  build:
    strategy:
      fail-fast: false
      matrix:
        include:
          - platform: macos-latest
            args: '--target aarch64-apple-darwin'
            rust_target: 'aarch64-apple-darwin'
          - platform: macos-latest
            args: '--target x86_64-apple-darwin'
            rust_target: 'x86_64-apple-darwin'
          - platform: ubuntu-22.04
            args: ''
            rust_target: ''
          - platform: windows-latest
            args: '--no-default-features --features winfsp'
            rust_target: ''

    runs-on: ${{ matrix.platform }}
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 10

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm

      - name: Install Rust stable
        uses: dtolnay/rust-toolchain@stable
        with:
          targets: ${{ matrix.rust_target }}

      - name: Rust cache
        uses: swatinem/rust-cache@v2
        with:
          workspaces: '. -> target'

      - name: Install Linux dependencies
        if: matrix.platform == 'ubuntu-22.04'
        run: |
          sudo apt-get update
          sudo apt-get install -y \
            libwebkit2gtk-4.1-dev \
            libappindicator3-dev \
            librsvg2-dev \
            patchelf \
            libfuse3-dev \
            fuse3

      - name: Install WinFsp (Windows)
        if: matrix.platform == 'windows-latest'
        shell: pwsh
        run: |
          # Download and install WinFsp MSI (needed for winfsp crate build)
          $winfspUrl = "https://github.com/winfsp/winfsp/releases/download/v2.0/winfsp-2.0.23075.msi"
          $winfspMsi = "$env:TEMP\winfsp.msi"
          Invoke-WebRequest -Uri $winfspUrl -OutFile $winfspMsi
          Start-Process msiexec.exe -ArgumentList "/i", $winfspMsi, "/qn" -Wait

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build frontend
        working-directory: apps/desktop
        run: pnpm vite build

      - uses: tauri-apps/tauri-action@v1
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}
          TAURI_SIGNING_PRIVATE_KEY_PASSWORD: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY_PASSWORD }}
        with:
          projectPath: apps/desktop
          releaseId: ${{ github.event.release.id }}
          updaterJsonPreferNsis: true
          tauriScript: pnpm tauri
          args: ${{ matrix.args }}
```

Key design decisions in this workflow:

1. **Trigger:** `release: types: [published]` -- fires when Release Please publishes a GitHub Release. The `github.event.release.id` provides the release to attach artifacts to.

2. **Matrix:** 4 builds -- macOS ARM64, macOS Intel, Ubuntu 22.04 (AppImage + deb), Windows (NSIS). Windows uses `--no-default-features --features winfsp` to build with WinFsp instead of FUSE.

3. **WinFsp install:** Windows build needs WinFsp SDK for the winfsp crate to compile. Download the MSI from GitHub releases and install silently.

4. **Frontend build:** Run `pnpm vite build` explicitly before tauri-action. The `beforeBuildCommand` in tauri.conf.json also does this, but running it separately gives clearer CI output.

5. **`updaterJsonPreferNsis: true`:** On Windows, prefer NSIS installer format in the updater manifest. This is the correct Windows format.

6. **`projectPath: apps/desktop`:** Since the desktop app is in a subdirectory of the monorepo, point tauri-action to it.

7. **Ed25519 signing:** `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` are read from GitHub Secrets at build time. If not set, updater artifacts will NOT have `.sig` files (builds succeed but updates cannot be verified).

8. **`releaseId`:** Attaches artifacts to the existing Release Please release instead of creating a new one. This means updater `latest.json` download URLs point to the same release.

  <action>
User must generate the Ed25519 signing keypair and configure GitHub secrets for the CI workflow to produce signed update bundles. Steps:

1. Generate keypair: `npx @tauri-apps/cli signer generate -w ~/.tauri/cipherbox.key`
2. Copy the PUBLIC KEY string from output into `apps/desktop/src-tauri/tauri.conf.json` replacing `"REPLACE_WITH_ED25519_PUBLIC_KEY"`
3. Add PRIVATE KEY CONTENT from `~/.tauri/cipherbox.key` as GitHub secret `TAURI_SIGNING_PRIVATE_KEY`
4. Add the password as GitHub secret `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`
5. Commit updated tauri.conf.json with real public key

This is a non-blocking checkpoint -- the desktop app compiles and the CI workflow exists without the real keys, but update signature verification will not work until this step is completed.
