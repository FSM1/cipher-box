<objective>
Close the TypeScript half of finding S3 (D-05): establish and enforce the caller-owns-key zeroization convention (T-47-01: `.fill(0)` in a `finally` at the buffer-owning boundary) across the unprotected sdk-core paths, reconciling the Phase-44 contradiction where `updateFileMetadata` zeroizes its key but the sibling sdk-core publish paths do not.

In scope: `createAndPublishIpnsRecord` (`ipns/index.ts` — zeroize its `ipnsPrivateKey` param), `publishVaultKeyBlob` (`vault/index.ts` — zeroize the derived `vaultKeyKeypair.privateKey`), and `updateFolderMetadataAndPublish` (`folder/index.ts` — zeroize its terminal keys ONLY if `client.ts` callers do not reuse them; otherwise document the skip). Plus the D-05 enforcement guard: regression tests asserting the convention on the touched paths so it cannot silently re-drift. Includes the S2 sdk-core regression guard (resolveIpnsRecord already throws — lock that in).

Purpose: stop Ed25519/folder private keys from persisting in the JS heap after their owning function returns, defense-in-depth alongside the Rust S3 work (51-03) and the verification work (51-01/02/03).
Output: `finally { ...fill(0) }` blocks on the confirmed-terminal paths, a documented decision for the folder path, and zeroization guard tests in three sdk-core test files.
</objective>
