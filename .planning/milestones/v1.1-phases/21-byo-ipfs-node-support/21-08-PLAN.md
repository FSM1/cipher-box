<objective>
Wire BYO pinning config into SDK client lifecycle and add source unpin to migration worker

Purpose: Two critical gaps prevent BYO-IPFS from working end-to-end: (1) the SDK client is created at login without pinningConfig, so pinWithMode() always uses cipherbox-only mode regardless of saved BYO settings, and (2) the TEE migration worker copies CIDs but never unpins from the source provider, leaving orphaned pins.

Output: SDK client initialized with BYO config at login, duplicate uploads respect pinning mode, migration cleans up source pins after verified transfer.
</objective>

    **Fix -- Add unpinFromProvider function and call after CID verification:**

    1. Add a new `async function unpinFromProvider(cid: string, config: ProviderConfig): Promise<void>` after the existing `pinToProvider` function:

    ```typescript
    async function unpinFromProvider(cid: string, config: ProviderConfig): Promise<void> {
      const token = authTokenString(config);

      if (config.protocol === 'kubo') {
        const headers: Record<string, string> = {};
        if (token) headers['Authorization'] = `Basic ${token}`;
        const response = await fetch(
          `${config.endpoint}/api/v0/pin/rm?arg=${encodeURIComponent(cid)}`,
          {
            method: 'POST',
            headers,
            signal: AbortSignal.timeout(30_000),
          }
        );
        if (!response.ok) {
          throw new Error(`Unpin from Kubo failed: ${response.status}`);
        }
        return;
      }

      if (config.protocol === 'psa') {
        // PSA requires finding the requestid first, then deleting
        const listResponse = await fetch(
          `${config.endpoint}/pins?cid=${encodeURIComponent(cid)}&status=pinned,pinning,queued`,
          {
            method: 'GET',
            headers: { Authorization: `Bearer ${token}` },
            signal: AbortSignal.timeout(30_000),
          }
        );
        if (!listResponse.ok) return; // Best-effort: if list fails, skip unpin
        const listResult = (await listResponse.json()) as { results: Array<{ requestid: string }> };
        for (const pin of listResult.results) {
          await fetch(`${config.endpoint}/pins/${encodeURIComponent(pin.requestid)}`, {
            method: 'DELETE',
            headers: { Authorization: `Bearer ${token}` },
            signal: AbortSignal.timeout(30_000),
          });
        }
        return;
      }

      // 'cipherbox' protocol: unpin via CipherBox API -- not handled in TEE worker.
      // CipherBox unpins are handled by the API-side MigrationProcessor.
    }
    ```

    2. In the `migrateBatch()` function, after `succeeded.push(cid)` (line 188), add a best-effort source unpin:

    ```typescript
    succeeded.push(cid);

    // Best-effort source unpin after verified transfer
    // Failure here is non-fatal -- the CID is already on the destination
    try {
      if (sourceConfig.protocol !== 'cipherbox') {
        await unpinFromProvider(cid, sourceConfig);
      }
    } catch {
      // Source unpin failure is non-fatal; CID is safely on destination
    }
    ```

    The `sourceConfig.protocol !== 'cipherbox'` guard ensures we don't try to unpin from CipherBox via the TEE worker -- CipherBox unpins are handled separately by the API-side MigrationProcessor which has direct access to the IPFS provider.

    3. Do NOT unpin CIDs from the `failed[]` array -- those were not successfully transferred and must remain on the source.
