<objective>
Route the three folder-state-mutating web file paths through the new SDK client methods (from Plan 03), strip their direct sdk-core publishes and direct Zustand folder-state writes, and remove the `reconcileFolderState` call in `ensureFolderRegistered`.

Purpose: This is the consumer half of REQ-1. With `useFileOperations.updateFile` and `useFileVersions` restore/delete now calling `client.replaceFile` / `client.restoreFileVersion` / `client.deleteFileVersion`, the SDK `folderTree` is updated synchronously and emits `folder:updated` — the store projects it. The hooks stop writing `children`/`sequenceNumber` to Zustand directly, closing the PR #489 desync race. With the bypass paths gone, the `reconcileFolderState` call is dead — remove it (the method itself was deleted in Plan 03).

Per locked decision 2: the web hook resolves `fileIpnsPrivateKey` (via getFileIpnsPrivateKey) BEFORE calling the client method; the existing finally-block zeroing of that key stays at the call site (T-47-01).

Output: three hooks rewired; direct store folder-state writes removed from them; reconcileFolderState call removed from sdk-provider.ts; owner-path prunedCids unpin retained in the web hook; web typecheck + web tests green.
</objective>
