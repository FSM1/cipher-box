<objective>
Extract the duplicated 409-CAS-retry skeleton from `updateFolderMetadataAndPublish` (folder/index.ts) and `updateFileMetadata` (file/index.ts) into one generic `publishWithCas<TData>` helper in sdk-core, and encapsulate the baseChildren snapshot inside `updateFolderMetadataAndPublish`.

Purpose: One CAS-retry engine means retry count, backoff, sequence handling, and 409 merge live in one place — closing the drift (folder 4-attempt+backoff vs file 2-attempt/no-backoff) the todo flagged as accidental. Reconciled UP to 4 attempts + backoff for BOTH paths (locked decision 1). The base-snapshot encapsulation removes the foot-gun where a caller forgets `baseChildren` and resurrects deletes (REQ-3, sdk-core half).

Output: New `packages/sdk-core/src/cas.ts` with `publishWithCas`; `updateFolderMetadataAndPublish` and `updateFileMetadata` become thin delegating wrappers with UNCHANGED public signatures; sdk-core rebuilt; existing folder/file test suites stay green; new `cas.test.ts` covers the generic helper.
</objective>
