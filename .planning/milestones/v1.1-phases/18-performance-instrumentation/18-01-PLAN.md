    2. In `resolveRecord()`: Use `startTimer()` pattern. Start timer at method entry with `{ operation: 'resolve' }`. Track `result` ('success'/'error'/'timeout') and `source` ('db'/'network'). The `source` is determined by: if `result` from delegated routing has `signatureV2`, source is 'network'; if falling back to DB cache, source is 'db'. In the `finally` block, call `end({ result, source })`. For the existing BAD_GATEWAY catch, set result to 'error'. For the case where delegated routing returns null but DB has a cache, source is 'db'. When both sources available and DB is preferred (higher seq), source is 'db'.

    3. In `publishRecord()`: Use `startTimer()` pattern. Start timer with `{ operation: 'publish', source: '' }`. Track result: 'success' if DB save + delegated routing both succeed, still 'success' if delegated routing fails (it's best-effort), 'error' only if DB save fails (which throws). In the `finally` block, call `end({ result })`.

    4. In `publishBatch()`: Do NOT add per-record timing (would create excessive observations). The existing single-publish timing inside `publishRecord()` already covers individual record timing. The batch method itself is timed by the HTTP interceptor.

Place the startTimer BEFORE the pinFile call and end AFTER it returns (not around the entire upload method -- quota check and recordPin are not IPFS operations). The timing wraps ONLY the pinFile call.

    6. In `get()`: Wrap `this.ipfsProvider.getFile(cid)` with timing. Use `startTimer({ operation: 'cat', source: '' })`. Result is 'success' or 'error'.

Result is 'success' if batch completes (even with partial failures), 'error' only if processRepublishBatch throws.
