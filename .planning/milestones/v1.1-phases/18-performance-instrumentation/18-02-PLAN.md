  <files>scripts/baseline-benchmark.sh, .planning/baselines/18-performance-baselines.md</files>

    **Baseline benchmark script (scripts/baseline-benchmark.sh):**

    1. Create a bash script that exercises the CipherBox staging API to generate Prometheus histogram observations. The script should be reusable in Phase 22 for "after" comparison (per user decision).

    Usage: `./scripts/baseline-benchmark.sh <api-url> <jwt-token>`

    The script should:
    - Accept API_URL and JWT_TOKEN as positional arguments
    - Define ITERATIONS=20 and WARMUP=3 (per Claude's discretion)
    - Print section headers and timing summaries
    - Use `curl` with `-w "%{time_total}\n"` for client-side timing (not for Prometheus -- this is for the baselines doc)
    - Exercise these operations:

    a. **IPNS Resolve** (20 iterations): `GET /ipns/resolve?ipnsName=<ipnsName>` -- use the user's root IPNS name (must be provided or discovered via `GET /vault`).

    b. **File Upload** (20 iterations): `POST /ipfs/upload` with a small test file (generate a 10KB random blob inline with `dd if=/dev/urandom bs=10240 count=1`). Collect the CID for use in download test.

    c. **File Download** (20 iterations): `GET /ipfs/<cid>` using a CID from the upload test.

    d. **IPNS Publish** (5 iterations, lower count since it mutates state): This is harder to test synthetically because it requires a signed IPNS record. Skip this operation in the script and note that publish timing will be captured from organic staging usage. Or: if a test IPNS name exists from E2E, use it.

    2. After all iterations, compute and print p50/p95/p99 from curl timing using `sort -n` + `awk` to extract percentiles. Print results in a copy-pasteable markdown table format.

    3. Add `#!/usr/bin/env bash`, `set -euo pipefail`, and make the script executable.

    4. Add a header comment explaining: purpose, usage, how to obtain a JWT token (via the web app or E2E test credentials), and that results feed into `.planning/baselines/18-performance-baselines.md`.

    **Baselines document (.planning/baselines/18-performance-baselines.md):**

    5. Create a template document with sections:
    - Capture date, environment (staging URL, Kubo version), methodology
    - Table: Operation | p50 | p95 | p99 | Notes
    - Operations: IPNS Resolve, IPNS Publish, IPFS Pin (upload), IPFS Cat (download), HTTP API (from existing dashboard), TEE Republish Batch
    - Values filled as `TBD -- run baseline-benchmark.sh on staging after deploy`
    - Section for Kubo Health observations: peer count, bandwidth, datastore size
    - Note that this document will be updated with actual values after Phase 18 code is deployed to staging

    Per user decision: baselines documented as markdown in `.planning/` with p50/p95/p99 values. Captured from staging using synthetic test script -- reproducible and comparable with Phase 22.
