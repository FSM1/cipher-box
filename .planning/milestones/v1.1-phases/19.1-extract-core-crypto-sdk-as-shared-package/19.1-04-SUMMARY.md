## Decisions Made

- Bin/share operations take explicit context objects (BinOperationContext, ShareOperationContext) instead of reading Zustand stores -- maintains zero-framework-dependency constraint
- Share module accepts callback functions for API calls (revokeShareFn, addShareKeysFn) rather than importing api-client directly -- keeps the module decoupled from transport layer
- BinState is tracked as client-internal field and not exposed directly -- consumers receive bin:updated events
- createShareKey wraps the folder key for a recipient but does not make the API call to create the share record -- actual API share creation is left to the consumer for flexibility
