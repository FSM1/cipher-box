## Decisions Made

- **Kept ipns/derive-name.ts in crypto:** The `deriveIpnsName` function is used by `vault/derive-ipns.ts` which stays in crypto. Rather than create a circular source-level import (crypto -> core -> crypto), we kept the function in crypto and export it from both packages. Core's `ipns/derive-name.ts` is a simple re-export from `@cipherbox/crypto`.
- **Circular workspace dependency is intentional:** crypto depends on core (for transitional re-exports) and core depends on crypto (for primitives). pnpm handles this at the workspace level. Build order requires staging: first build crypto without re-exports (DTS only), then core, then rebuild crypto with re-exports.
- **deriveIpnsName classified as crypto primitive:** Since it takes a raw Ed25519 public key and derives an IPNS name using libp2p crypto libraries, it belongs in the primitives layer despite being in the ipns/ directory.
