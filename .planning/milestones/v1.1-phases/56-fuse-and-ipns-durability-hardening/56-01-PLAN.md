<objective>
Add the missing FUSE write-path safety guards that the PR #538 / Phase 55 refactor surfaced byte-identical to main: reject negative write offsets (EINVAL), guard offset+length overflow (EFBIG), reject duplicate child names on create/mknod and mkdir (EEXIST), and replace the unchecked `seq + 1` in `next_file_publish_sequence` with a checked/saturating add (D-05, D-06, D-07). Mirror each guard into the winfsp siblings so macOS and Windows stay in lockstep (D-15).

Purpose: These are pure input-validation/arithmetic guards in the write path — V5 Input Validation. Without them a malformed write can produce an arbitrary file offset (Tampering), a duplicate dirent can shadow an inode (Tampering), and a sequence wrap silently breaks IPNS CAS. No durability decision is left to a swallowed condition.

Output: Bounds-checked `handle_write`, existence-checked `handle_create`/`handle_mkdir`, overflow-safe `next_file_publish_sequence`, plus the winfsp counterparts, with Rust unit tests for the deterministic arithmetic/existence paths.
</objective>

<threat_model>

## Trust Boundaries

| Boundary | Description |
| -------- | ----------- |
| OS kernel → FUSE handler | The OS passes attacker/process-controlled `offset`, `data.len()`, and child names across the FUSE syscall boundary into `handle_write`/`handle_create`/`handle_mkdir` — untrusted input. |
| FUSE publish path → IPNS CAS | `next_file_publish_sequence` feeds the `expected_sequence_number` used for compare-and-swap; a wrapped sequence breaks the CAS invariant. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --------- | -------- | --------- | ----------- | --------------- |
| T-56-02 | Tampering | `handle_write` (file_data.rs / winfsp write_ops.rs) | mitigate | D-05: reject `offset < 0` → EINVAL and `checked_add` overflow → EFBIG before `write_at`, so a malformed write cannot produce an arbitrary file offset (Task 2 macOS, Task 3 winfsp). |
| T-56-02 | Tampering | `next_file_publish_sequence` (publish.rs) | mitigate | D-07: `checked_add` so a u64 wrap cannot silently break IPNS CAS (Task 1). |
| T-56-04 | Tampering | `handle_create`/`handle_mkdir` (file_data.rs, mkdir.rs / winfsp) | mitigate | D-06: `find_child` existence guard → EEXIST before inode allocation, preventing a duplicate dirent from shadowing an inode (Task 2 macOS, Task 3 winfsp). |
| T-56-SC | Tampering | npm/cargo installs | accept | No packages added this phase (RESEARCH Package Legitimacy Audit: zero new crates/packages). No install task exists; nothing to gate. |
