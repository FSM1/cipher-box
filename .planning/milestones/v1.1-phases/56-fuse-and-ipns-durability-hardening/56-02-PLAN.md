<objective>
Close the per-file and bin IPNS Conflict-as-success durability bugs and the FUSE FS-state correctness gaps surfaced by the PR #538 / Phase 55 review. Extract one shared `publish_with_cas_retry` helper (D-03) generalizing the already-correct folder retry loop, route the per-file (content_ops) and bin (metadata) CAS publishes through it so a `Conflict` re-resolves+retries instead of being recorded as a local success (D-01/D-02). On retry exhaustion the per-file/bin sites return `Err` → `EIO` (a surfaced, non-swallowed failure per D-01a — the durable journal-on-exhaustion path is deferred because no `JournalOp::FilePublish`/`BinPublish` variant exists today). Fix the stale-completion unpin scope (D-08), the silently-dropped FilePointer overflow (D-09), the unbounded metadata refresh (D-10), the inode display-name-fallback identity reset (D-11), and zeroize the one remaining plain-`Vec<u8>` publish helper (D-12).

Purpose: "No durability decision left to a swallowed warning." A Conflict acked as success drifts the IPNS sequence (Repudiation). A superseded write unpinning live CIDs loses data. A hung refresh blocks all future refreshes. A stale inode identity serves stale keys (Information Disclosure). Plain `Vec<u8>` key params leak key material on drop (Information Disclosure).

Output: A single CAS durability decision point; per-file/bin publishes that retry-then-Err-to-EIO on exhaustion (surfaced, not swallowed); generation-guarded unpin; a FP-resolve continuation queue; a timeout-bounded refresh; identity-reset inode lookups; Zeroizing publish key params — with new Rust unit tests for the helper and the inode identity paths.
</objective>
