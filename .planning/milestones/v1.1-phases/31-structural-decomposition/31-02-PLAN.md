# Plan 31-02: Web Layer Barrel Re-Exports and SDK Adoption

<objective>
Redirect web app files (folder.service.ts, bin.service.ts, folder-helpers.ts) to use SDK exports where logic was extracted in Plan 01. For folder.service.ts: re-export tree utilities from SDK-core so consumers (MoveDialog, useFolderMutations) keep working without import changes. For useSharedNavigation.ts: adopt SDK error utilities and share context builder. The key constraint is backward compatibility -- no consumer import changes.
</objective>

<must_haves>

- `folder.service.ts` re-exports `getDepth`, `calculateSubtreeDepth`, `isDescendantOf` from `@cipherbox/sdk-core` so existing `import { getDepth } from '../services/folder.service'` still resolves
- `folder-helpers.ts` imports `withConflictRetry` from `@cipherbox/sdk` instead of its local implementation, and re-exports it for consumers
- `useSharedNavigation.ts` uses `isForbiddenError` and `withRevocationGuard` from `@cipherbox/sdk` instead of local definitions
- `useSharedNavigation.ts` uses `ShareKeyCache` from `@cipherbox/sdk` for its share key caching
- All existing consumers compile without import changes
- `pnpm build` passes for the entire monorepo
</must_haves>

<action>
1. In `apps/web/src/hooks/folder-helpers.ts`:

   a. Replace the local `withConflictRetry` implementation with a re-export from SDK. Remove lines 38-80 (the function implementation) and add:
   ```typescript
   // Re-export from SDK — framework-agnostic conflict retry logic
   export { withConflictRetry } from '@cipherbox/sdk';
   ```

   b. Remove the `isConflictError` import from `'../lib/errors'` since it's no longer used locally (the SDK version has its own).

   c. Keep the rest of folder-helpers.ts unchanged:

      - `calculateFolderDepth()` stays (reads Zustand stores)

2. Update callers that relied on the sync banner side-effect:

   In each file that calls `withConflictRetry`, the `resync` callback should include:

   Read each caller to determine if they already have this or if the old withConflictRetry was setting it for them.

### Task 3: Adopt SDK utilities in useSharedNavigation.ts

<read_first>

- apps/web/src/hooks/useSharedNavigation.ts (full file — 1206 lines, focus on: lines 116-120 isForbiddenError, lines 169-230 shareKeysCache + getShareKeys, lines 798-852 buildSharedWriteCtx + withRevocationGuard)

- packages/sdk/src/share/context.ts (buildSharedWriteContext — created in Plan 01)
- packages/sdk/src/share/key-cache.ts (ShareKeyCache — created in Plan 01)
</read_first>

<action>
1. Add SDK imports at the top of `apps/web/src/hooks/useSharedNavigation.ts`:
   ```typescript
   import {
     isForbiddenError as sdkIsForbiddenError,
     withRevocationGuard as sdkWithRevocationGuard,
     ShareKeyCache,
     buildSharedWriteContext,
   } from '@cipherbox/sdk';
   ```

2. Remove the local `isForbiddenError` function (lines 116-120). Replace any calls to `isForbiddenError(...)` with `sdkIsForbiddenError(...)`.

3. Replace the `shareKeysCache` ref (lines 169-195) with a `ShareKeyCache` instance:

   Replace:
   ```typescript
   const shareKeysCache = useRef<
     Map<
       string,
       {
         keys: Array<{...}>;
         fetchedAt: number;
       }
     >
   >(new Map());
   ```

   With:
   ```typescript
   const shareKeysCacheRef = useRef(new ShareKeyCache(30_000));
   ```

4. Update the `getShareKeys` function (around lines 196-230) to use the new cache:

   Replace the manual TTL check logic:
   ```typescript
   const cached = shareKeysCache.current.get(shareId);
   if (cached && Date.now() - cached.fetchedAt < CACHE_TTL) {
     return cached.keys;
   }
   ```

   With:
   ```typescript
   const cached = shareKeysCacheRef.current.get(shareId);
   if (cached) return cached;
   ```

   And replace the cache set:
   ```typescript
   shareKeysCache.current.set(shareId, { keys: mapped, fetchedAt: Date.now() });
   ```

   With:
   ```typescript
   shareKeysCacheRef.current.set(shareId, mapped);
   ```

   And replace cache invalidations (search for `shareKeysCache.current.delete`):
   ```typescript
   shareKeysCacheRef.current.invalidate(sid);
   ```

5. Replace the `withRevocationGuard` useCallback (lines 839-852) with a wrapper that uses the SDK version:

   Replace:
   ```typescript
   const withRevocationGuard = useCallback(
     async <T>(operation: () => Promise<T>): Promise<T> => {
       try {
         return await operation();
       } catch (err) {
         if (isForbiddenError(err)) {
           handleRevocation(true);
           throw new Error('> write access revoked -- folder is now read-only');
         }
         throw err;
       }
     },
     [handleRevocation]
   );
   ```

   With:
   ```typescript
   const withRevocationGuard = useCallback(
     async <T>(operation: () => Promise<T>): Promise<T> => {
       return sdkWithRevocationGuard(operation, () => handleRevocation(true));
     },
     [handleRevocation]
   );
   ```

6. Replace the `buildSharedWriteCtx` useCallback (lines 798-833) to use the SDK builder. The hook still does null-checking, but delegates the construction:

   The `buildSharedWriteCtx` function checks for null on ipnsKey, folderKey, ipnsName, sequenceNumber, vaultKeypair, and shareItem. Keep all those checks. Replace the object literal return with:
   ```typescript
   return buildSharedWriteContext({
     ctx: {
       apiUrl,
       getAccessToken: async () => useAuthStore.getState().accessToken || '',
       axiosInstance: apiAxios,
     },
     folderKey,
     ipnsPrivateKey: currentIpnsKey,
     ipnsName,
     sequenceNumber: currentSequenceNumber,
     children: folderChildrenRef.current,
     ownerPublicKey: ownerPubKey,
     recipientPublicKey: auth.vaultKeypair.publicKey,
     shareId: currentShareId!,
     addShareKeysFn: async (sid, keys) => {
       await addShareKeys(sid, keys);
       shareKeysCacheRef.current.invalidate(sid);
     },
   });
   ```
</action>
