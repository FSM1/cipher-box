# Plan 38-01: Migrate folder.service callers to SDK imports

<objective>
Replace all imports of `folder.service.ts` functions in hooks and components with equivalent SDK-core or SDK-client functions, eliminating all consumers of the deprecated service. This includes extracting `addFileToFolder`, `addFilesToFolder`, and `replaceFileInFolder` into `@cipherbox/sdk-core` since no SDK equivalent currently exists.
</objective>

<must_haves>

- Zero imports of `folder.service` remain in any hook or component file
- All tree utilities (getDepth, isDescendantOf, calculateSubtreeDepth) import from `@cipherbox/sdk-core`
- `fetchAndDecryptMetadata` callers use the SDK-core version (with SdkContext from getSdkClient())
- `loadFolder` callers construct FolderNode inline using SDK-core's `loadFolderMetadata` or equivalent
- `addFileToFolder`, `addFilesToFolder`, `replaceFileInFolder` extracted to `@cipherbox/sdk-core` and callers updated
- `pnpm typecheck` passes
  </must_haves>

<action>
1. In `packages/sdk-core/src/folder/index.ts`, add three new exported functions:

**`addFileToFolder`** — Takes explicit params (no FolderNode, no Zustand):

```typescript
export async function addFileToFolder(params: {
  children: FolderChild[];
  folderKey: Uint8Array;
  ipnsPrivateKey: Uint8Array;
  ipnsName: string;
  sequenceNumber: bigint;
  fileId: string;
  name: string;
  fileIpnsRecord: {
    ipnsName: string;
    recordBase64: string;
    metadataCid: string;
    encryptedIpnsPrivateKey?: string;
    keyEpoch?: number;
  };
  ipnsPrivateKeyEncrypted: string;
  ctx: SdkContext;
}): Promise<{ filePointer: FilePointer; newSequenceNumber: bigint }>;
```

Logic:

- Check name collision in `children`
- Create FilePointer with id, name, fileMetaIpnsName, ipnsPrivateKeyEncrypted, timestamps
- Encrypt updated folder metadata (children + new FilePointer) using `encryptFolderMetadata` from `@cipherbox/core`
- Upload encrypted metadata to IPFS via `addToIpfs` from sdk-core
- Create IPNS record for the folder using `createIpnsRecord` + `marshalIpnsRecord` from `@cipherbox/core`
- Batch publish both the file IPNS record and the folder IPNS record using `batchPublishIpnsRecords` from sdk-core (already available at `packages/sdk-core/src/ipns/index.ts`)
- Return filePointer and newSequenceNumber

**`addFilesToFolder`** — Batch variant (same pattern, multiple files):

```typescript
export async function addFilesToFolder(params: {
  children: FolderChild[];
  folderKey: Uint8Array;
  ipnsPrivateKey: Uint8Array;
  ipnsName: string;
  sequenceNumber: bigint;
  files: Array<{
    fileId: string;
    name: string;
    fileIpnsRecord: {
      ipnsName: string;
      recordBase64: string;
      metadataCid: string;
      encryptedIpnsPrivateKey?: string;
      keyEpoch?: number;
    };
    ipnsPrivateKeyEncrypted: string;
  }>;
  ctx: SdkContext;
}): Promise<{ filePointers: FilePointer[]; newSequenceNumber: bigint }>;
```

**`replaceFileInFolder`** — Publishes file IPNS record only (folder metadata untouched):

```typescript
export async function replaceFileInFolder(params: {
  children: FolderChild[];
  fileId: string;
  fileIpnsRecord: {
    ipnsName: string;
    recordBase64: string;
    metadataCid: string;
    encryptedIpnsPrivateKey?: string;
    keyEpoch?: number;
  };
  ctx: SdkContext;
}): Promise<void>;
```

2. The `batchPublishIpnsRecords` function is already available in sdk-core at `packages/sdk-core/src/ipns/index.ts` and exported from `packages/sdk-core/src/index.ts`. Use it for publishing.

3. The folder metadata encrypt + IPFS upload + IPNS record creation logic is similar to `updateFolderMetadataAndPublish` in `packages/sdk-core/src/folder/index.ts` (lines 170-232). Reuse or reference that pattern, but adapt for batch publish (file + folder records together).

4. Add exports to `packages/sdk-core/src/index.ts`:

   ```typescript
   export { addFileToFolder, addFilesToFolder, replaceFileInFolder } from './folder';
   ```

5. Ensure `FilePointer` type is available (it's from `@cipherbox/core`).

6. Run `pnpm --filter @cipherbox/sdk-core build` to verify compilation.
   </action>
