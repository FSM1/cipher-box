<objective>
Replace the stringly-typed `e.to_lowercase().contains("not found")` match in the replay per-file publish path (#19) with a typed `IpnsResolveOutcome` enum and a `resolve_ipns_for_replay` wrapper that classifies the resolve result once. Behavior is identical: NotFound → first-publish/seq-0; Error → retain entry and return the error.

Purpose: The brittle substring match at `lib.rs:1397` is duplicated logic that breaks if the API client's error wording changes. Centralizing classification in one wrapper removes that fragility while preserving the exact two-way branch.
Output: `pub enum IpnsResolveOutcome` in `crates/fuse/src/error.rs`; `async fn resolve_ipns_for_replay(...)` + a `match` on it in `replay_upload_entry`; T-45-05 test asserting NotFound drives the first-publish path.

Scope guard (per RESEARCH §Item #19 "Scope note"): ONLY the replay per-file-publish call site is changed. The separate bin-publish path `spawn_bin_entry_publish` at lib.rs:482 keeps its existing string match — do NOT touch it this phase.
</objective>
