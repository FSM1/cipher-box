# Plan 30-03: Source Map Upload and Staging Deploy Configuration

<objective>
Configure the Vite build to upload source maps to Grafana Cloud via the Faro Rollup plugin so that production stack traces are readable with original TypeScript source locations. Add the VITE_FARO_URL environment variable to the staging deploy workflow so Faro is active in staging builds.
</objective>

## Background

Production builds minify and bundle JavaScript, making stack traces unreadable without source maps. The `@grafana/faro-rollup-plugin` integrates with the Vite/Rollup build pipeline to upload source maps to Grafana Cloud at build time. Source maps are NOT served to the browser — they're uploaded directly to Grafana's backend for server-side symbolication.

The staging deploy workflow already injects VITE\_\* environment variables at build time (VITE_WEB3AUTH_CLIENT_ID, VITE_API_URL, VITE_ENVIRONMENT, VITE_GOOGLE_CLIENT_ID). VITE_FARO_URL follows the same pattern.

## must_haves

- `@grafana/faro-rollup-plugin` installed as a dev dependency
- Vite build config conditionally adds the Faro source map plugin when `VITE_FARO_URL` is set
- Source maps uploaded during build but NOT served to the browser
- `VITE_FARO_URL` added to the staging deploy workflow's web build step
- `GRAFANA_FARO_URL` and `GRAFANA_FARO_API_KEY` documented as required GitHub secrets/vars

### Task 2: Add Faro source map plugin to Vite config

<read_first>

- apps/web/vite.config.ts (current config — plugins array, define, server, resolve sections)
- apps/web/scripts/build-sw.mjs (to understand the full build pipeline: tsc -> vite build -> build-sw)
  </read_first>

<action>
Update `apps/web/vite.config.ts` to conditionally include the Faro source map upload plugin:

1. Add the import at the top:

   ```typescript
   import faro from '@grafana/faro-rollup-plugin';
   ```

2. Modify the config to conditionally include the plugin. Since `defineConfig` is used, the plugins array needs to conditionally include the Faro plugin only when the Faro URL is available AND we're building (not in dev server mode):

   ```typescript
   export default defineConfig(({ mode }) => {
     const faroUrl = process.env.VITE_FARO_URL;
     const faroApiKey = process.env.GRAFANA_FARO_API_KEY;

     return {
       plugins: [
         react(),
         // Upload source maps to Grafana Faro in production/staging builds
         ...(faroUrl && faroApiKey && mode === 'production'
           ? [
               faro({
                 appName: 'cipherbox-web',
                 appId: 'cipherbox-web',
                 endpoint: faroUrl,
                 apiKey: faroApiKey,
                 stackId: process.env.GRAFANA_STACK_ID ?? '',
                 // Upload source maps but don't emit them in the output
                 keepSourcemaps: false,
                 gzipContents: true,
               }),
             ]
           : []),
       ],
       // ... rest of config unchanged
     };
   });
   ```

   Key decisions:
   - `keepSourcemaps: false` ensures source maps are uploaded to Grafana but NOT included in the deployed output (security: don't expose source to browser)
   - Plugin only activates when both `VITE_FARO_URL` and `GRAFANA_FARO_API_KEY` are present AND mode is `production`
   - `gzipContents: true` reduces upload size
   - Check the actual plugin API — the option names may differ (e.g., `outputFiles` vs `keepSourcemaps`). Read the plugin's TypeScript types or README for exact config.

3. Ensure the existing build configuration is preserved. The current `defineConfig` call is not using a function form — it's a plain object. Convert to the function form `defineConfig(({ mode }) => ({...}))` while keeping all existing options intact:
   - `resolve.alias`
   - `define.global`
   - `server` (port, headers, proxy)

4. Enable source map generation for production builds by adding:

   ```typescript
   build: {
     sourcemap: 'hidden',  // Generate .map files but don't reference them in output JS
   },
   ```

   The `'hidden'` option generates source map files (needed for upload) but doesn't add `//# sourceMappingURL` comments to the JavaScript output, so browsers never request them.
   </action>

### Task 3: Add VITE_FARO_URL to staging deploy workflow

<read_first>

- .github/workflows/deploy-staging.yml (lines 106-113, to see existing VITE\_\* env var injection pattern in the web build step)
  </read_first>

<action>
1. In `.github/workflows/deploy-staging.yml`, find the "Build web app with staging env vars" step (around line 106) and add `VITE_FARO_URL` and `GRAFANA_FARO_API_KEY` to the env block:

```yaml
- name: Build web app with staging env vars
  run: pnpm --filter @cipherbox/web build
  env:
    VITE_WEB3AUTH_CLIENT_ID: ${{ vars.VITE_WEB3AUTH_CLIENT_ID }}
    VITE_API_URL: ${{ vars.STAGING_API_URL }}
    VITE_ENVIRONMENT: staging
    VITE_GOOGLE_CLIENT_ID: ${{ vars.GOOGLE_CLIENT_ID }}
    VITE_FARO_URL: ${{ vars.VITE_FARO_URL }}
    GRAFANA_FARO_API_KEY: ${{ secrets.GRAFANA_FARO_API_KEY }}
    GRAFANA_STACK_ID: ${{ vars.GRAFANA_STACK_ID }}
```

Use `vars.VITE_FARO_URL` (not secret — it's a public collector endpoint URL).
Use `secrets.GRAFANA_FARO_API_KEY` (secret — API key for source map upload).
Use `vars.GRAFANA_STACK_ID` (not secret — Grafana Cloud stack identifier).

2. Also add the same env vars to the desktop build steps (macOS and Windows) that build the web app via Tauri, around lines 181-188:

   ```yaml
   VITE_FARO_URL: ${{ vars.VITE_FARO_URL }}
   GRAFANA_FARO_API_KEY: ${{ secrets.GRAFANA_FARO_API_KEY }}
   GRAFANA_STACK_ID: ${{ vars.GRAFANA_STACK_ID }}
   ```

   Note: Desktop builds also compile the web app, so they need the same Faro configuration.
   </action>
