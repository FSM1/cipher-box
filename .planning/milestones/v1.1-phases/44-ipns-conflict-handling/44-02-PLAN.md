<objective>
Replace the broken 2-attempt seq-only retry in `updateFolderMetadataAndPublish` (folder/index.ts:200-237) with a 4-attempt merge-and-republish loop. On each 409 it re-resolves the authoritative seq, re-fetches+decrypts the remote folder, three-way-merges via `mergeChildren` (Plan 01), re-encrypts and re-uploads the MERGED children to a new CID, then CAS-publishes. After 4 failed attempts it throws the typed `ConflictError` (Plan 01).

Purpose: This is the folder half of the lost-update fix. Today the loop republishes the stale CID with a bumped seq, silently erasing the concurrent writer's children. This plan makes the 409 path re-fetch+merge so no child is lost, and surfaces unresolved conflicts as a typed error the web conflict UI can route.
Output: Modified `updateFolderMetadataAndPublish` with `baseChildren?` param and the merge loop; expanded `folder.test.ts` covering merge-on-409, union-fallback warning, and ConflictError-after-4-attempts.
</objective>

## Trust Boundaries

| Boundary | Description |
| --- | --- |
| client → CipherBox IPNS publish API | CAS (expectedSequenceNumber) is the only server-side lost-update guard; server self-increments seq and does not verify IPNS signatures (RESEARCH line 483) |
| remote writer's metadata → local merge | Concurrent writer's decrypted FolderChild[] re-fetched on 409 and merged into the republished blob |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-44-04 | Tampering (data loss) | updateFolderMetadataAndPublish 409 path | mitigate | Re-fetch + mergeChildren before republish (never republish stale CID); unit test asserts remote-only child survives the merge |
| T-44-05 | Denial of Service (livelock) | retry loop | mitigate | Hard cap of 4 attempts with exponential backoff + ±50% jitter — bounded retries, no unbounded loop against the API; concurrent write-share writers de-correlated by jitter so they do not stampede in lockstep (D-04) |
| T-44-06 | Repudiation / replay | sequence number | accept | Server self-increments DB seq (known protocol divergence, ipns.service.ts:543) — we re-resolve authoritatively and re-sign with the resolved seq; correcting the divergence is the protocol-hardening thread, out of scope (CONTEXT line 16) |
| T-44-07 | Tampering (wrong key) | re-encrypt merged metadata | mitigate | Merged children re-encrypted with `params.folderKey` (the same folder key) via encryptFolderMetadata before upload — never plaintext to IPFS (D-03, V6 crypto) |
| T-44-08 | Information Disclosure | ConflictError on exhaustion | mitigate | Thrown error carries only ipnsName + attempts + lastRemoteSeq (Plan 01 guarantee) — no plaintext child data |

</threat_model>
