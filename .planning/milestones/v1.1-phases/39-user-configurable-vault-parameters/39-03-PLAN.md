<objective>
Wire vault settings into all consumer locations, replacing hardcoded values with user-configurable settings from the Zustand store.

Purpose: This is the integration plan that makes user settings actually take effect. Currently, retention days come from an API env var, max versions and cooldown are hardcoded constants, and delete always tries soft-delete first. After this plan, all four behaviors respect the user's stored preferences.

Output: Modified useAuth (load/clear), useFolderMutations (delete behavior), file-metadata.service (version limits), useBin (retention).
</objective>

Updated logic:

```typescript
if (deleteBehavior === 'permanent') {
  // User prefers permanent deletion — skip bin entirely
  await client.deleteItem(parentFolder.ipnsName, itemId);
} else {
  // Default: soft-delete to bin, fall back to hard delete if bin not loaded
  try {
    await client.deleteToBin(parentFolder.ipnsName, itemId, parentPath);
  } catch (binErr) {
    if (binErr instanceof BinNotLoadedError) {
      await client.deleteItem(parentFolder.ipnsName, itemId);
    } else {
      throw binErr;
    }
  }
}
```
