# Plan 29-02: SDK IPNS Unenrollment on Delete + Legacy TODO Cleanup

<objective>
Wire IPNS unenrollment into the SDK's deletion paths (deleteItem, deleteToBin, permanentDelete) so that deleting files/folders triggers fire-and-forget batch unenrollment of their IPNS records from the TEE republish schedule. Clean up legacy TODO comments in folder.service.ts and delete.service.ts that reference this deferred work.
</objective>

<must_haves>

- Deleting a file via SDK triggers unenrollment of its fileMetaIpnsName from TEE republishing
- Deleting a folder via SDK collects all nested file IPNS names and batch-unenrolls them
- Permanent delete from bin triggers unenrollment of the item's IPNS name(s)
- Unenrollment is fire-and-forget (does not block deletion UX)
- Legacy TODO comments referencing Phase 14 / unenrollment are removed
  </must_haves>

```typescript
/**
 * Fire-and-forget IPNS unenrollment for deleted items.
 * Collects IPNS names from removed items and calls the batch unenroll API.
 * Failures are logged but never block the caller.
 */
private fireAndForgetUnenroll(ipnsNames: string[]): void {
  if (ipnsNames.length === 0) return;

  // Import the generated API client function for unenroll
  // Use the ctx's axiosInstance for per-client token isolation
  const unenroll = async () => {
    try {
      const { ipnsControllerUnenrollBatch } = await import('@cipherbox/api-client');
      await ipnsControllerUnenrollBatch({ ipnsNames }, {
        ...(this.ctx.axiosInstance ? { axios: this.ctx.axiosInstance } : {}),
      });
    } catch (err) {
      // Fire-and-forget: log but never throw
      console.warn(
        `[CipherBox] IPNS unenroll failed for ${ipnsNames.length} name(s):`,
        err instanceof Error ? err.message : err
      );
    }
  };

  unenroll();
}
```

Note: The exact import name for the generated function depends on what `pnpm api:generate` produces. async permanentDelete(entryId: string): Promise<void> {
```typescript
  return this.withOperation('permanentDelete', async () => {
    if (!this.binState) throw new BinNotLoadedError();

    // Capture entry before deletion for IPNS unenrollment
    const entry = this.binState.entries.find((e) => e.id === entryId);

    const { updatedBinState } = await binOps.permanentDeleteFromBin({
      entryId,

      binCtx: this.getBinContext(),
```

<action>
For folder deletions, the `deleteItem` and `deleteToBin` calls only remove the top-level child from the parent folder. But the deleted folder may contain nested files, each with their own fileMetaIpnsName that should be unenrolled.

Add a private helper to `CipherBoxClient`:

```typescript
/**
 * Recursively collect all IPNS names from a folder subtree.
 * Walks the in-memory folderTree to find file IPNS names and subfolder IPNS names.
 * Only collects from loaded folders — unloaded subtrees are skipped.
 */
private collectSubtreeIpnsNames(folderIpnsName: string): string[] {
  const names: string[] = [folderIpnsName]; // The folder itself
  const folder = this.folderTree.get(folderIpnsName);
  if (!folder) return names;

  for (const child of folder.children) {
    if (child.type === 'file' && 'fileMetaIpnsName' in child) {
      names.push(child.fileMetaIpnsName);
    } else if (child.type === 'folder' && 'ipnsName' in child) {
      names.push(...this.collectSubtreeIpnsNames(child.ipnsName));
    }
  }
  return names;
}
```

Update the folder deletion case in `deleteItem()` to use this:

```typescript

}
```
