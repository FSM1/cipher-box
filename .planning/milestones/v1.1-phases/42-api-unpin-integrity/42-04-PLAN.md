<objective>
[BLOCKING] Apply the two additive migrations created in 42-01 (`1749000000000-AddPendingUnpins`, `1749100000000-AddPinnedCidCidIndex`) to the live (developer) Postgres and verify the `pending_unpins` table and `idx_pinned_cids_cid` index physically exist. This gate de-risks every downstream plan that queries the live tables: the guarded-unpin path (42-03) inserts into `pending_unpins`, the outbox/drift processor (42-06) selects from it, and the backfill script (42-07) reads `pinned_cids` via the new index.

Purpose: TypeORM runs migrations automatically on app start (`migrationsRun: true`, app.module.ts:103) and on the staging/production deploy via `run-migrations.ts`. This plan exercises that exact path early, in a controlled blocking step, so a malformed migration (class-name/name mismatch, bad DDL) surfaces here rather than crashing app boot mid-wave-3 with `relation "pending_unpins" does not exist`.
Output: No source files changed — this is a verification gate that runs the migrations against the live DB and confirms the schema objects exist.
</objective>
