<objective>
Build the durability + observability half of the outbox pattern (D-05 retry, D-06 drift report). A `PendingUnpinModule` registers a BullMQ queue with two repeating schedulers; a `PendingUnpinProcessor` (WorkerHost) drains the `pending_unpins` outbox by retrying `ipfsProvider.unpinFile(cid)` (deleting the row on success or "not pinned") and runs a read-only drift report that diffs Kubo `pin ls` against `pinned_cids ∪ pending_unpins`, reporting orphans via `driftOrphanedPinsTotal` + warn log and NEVER deleting. The drain also publishes outbox depth to `pendingUnpinsGauge`. The module is registered in `app.module.ts` imports.

Purpose: The inline post-commit Kubo call in `guardedUnpin` (42-03) is best-effort; without this worker, a transient Kubo failure orphans a pin forever. The drift report (D-06) is the detection mechanism for the accepted D-13 race and for pre-quota-tracking pins — read-only because auto-GC of unknown pins is forbidden (would destroy ops/legacy pins).
Output: `pending-unpin.module.ts`, `pending-unpin.processor.ts`, processor spec, and `PendingUnpinModule` added to `app.module.ts` imports.
</objective>

<threat_model>

## Trust Boundaries

| Boundary | Description |
| -------- | ----------- |
| BullMQ scheduler to Kubo pin/rm | background retry of physical unpins; external service, best-effort, idempotent |
| drift report to Kubo pin/ls | read-only enumeration of all server pins; no write authority |
| drift report to Postgres | builds the accounted-set from pinned_cids ∪ pending_unpins; comparison only, never deletes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --------- | -------- | --------- | ----------- | --------------- |
| T-42-18 | Tampering | drift report auto-GC destroying legitimate pins | mitigate | runDriftReport is strictly read-only — it only increments a counter and warn-logs; no `.delete` / `pin rm` path exists in the drift handler (D-06). Pins predating quota tracking are reported, never removed. |
| T-42-19 | Denial of Service | outbox row never drained (advisory-row over-retention) | accept | Equal-refcount semantics (D-07): a stuck row only over-retains disk, never destroys content; self-heals when the last referencing user deletes; gauge surfaces growth for ops. |
| T-42-20 | Denial of Service | poisoned retry queue from external-only BYO "not pinned" | mitigate | Drain calls `LocalProvider.unpinFile`, which swallows "not pinned" (local.provider.ts:94) and resolves → the row is deleted, not retried forever (D-08). |
| T-42-21 | Information Disclosure | NDJSON parse failure crashing the drift job | mitigate | Kubo `pin ls` parsed line-by-line with per-line tolerance and a fetch try/catch (Pitfall 6); a Kubo outage logs and skips rather than throwing out of the scheduler. |
| T-42-SC | Tampering | npm installs | accept | No new packages; @nestjs/bullmq, typeorm, prom-client already installed (RESEARCH audit). |

</threat_model>
