<objective>
Rewrite the in-memory `WriteQueue` in `crates/sdk/src/queue.rs` into a persist-backed
durable write journal, and extend `SyncStatus` with a `WriteParked` variant. This is the
shared foundation both platform wiring plans (fuser and WinFsp) and the mount-replay plan
depend on.

Purpose: The journal is the durability ack barrier. Every FUSE write must fsync a journal
entry to disk before acking the OS; a crash after the fsync is recoverable on next mount.
The current memory-only queue loses everything on app quit (the root cause of the
release-data-loss and mkdir-orphan todos).

Output: `JournalOp` (UploadFile | MkdirPublish), `JournalEntryStatus` (Pending |
InProgress | Failed), `JournalEntry`, and a path-backed `WriteQueue` with `put`, `remove`,
`load_all_for_vault`, `update_status`, and a replay-ordering helper — all unit-tested via
RED→GREEN→REFACTOR. Plus `SyncStatus::WriteParked { pending: u32, failed: u32 }`.
</objective>

<threat_model>

## Trust Boundaries

| Boundary | Description |
| -------- | ----------- |
| in-memory plaintext → on-disk journal | Encrypted write content crosses from RAM into a persisted file; must be ciphertext only |
| journal file → other local processes | Journal files sit in app-data; other OS users/processes must not read them |
| on-disk journal → deserialize on load | Untrusted/corrupt bytes are parsed back into Rust types at replay time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --------- | -------- | --------- | ----------- | --------------- |
| T-43-01 | Information Disclosure | `JournalOp::UploadFile`/`MkdirPublish` serialization | mitigate | D-05: store only `ciphertext_b64`, ECIES-`wrapped_key_hex`, `iv_hex`, and metadata strings — no plaintext, no raw key bytes; enforced by `journal_no_plaintext` test |
| T-43-02 | Information Disclosure | journal file on disk | mitigate | `0o600` permissions on every `put()` (file_handle.rs:88-92 pattern); journal dir itself `0o700` (set by Plan 04 mount) |
| T-43-03 | Tampering / DoS | `load_all_for_vault` deserialize | mitigate | `serde_json::from_slice` returns `Err` on malformed input; skip-with-warn, never `unwrap`/panic (V5) |
| T-43-04 | Tampering | parked entries | mitigate | D-09: failed entries kept on disk with `Failed` status, never silently dropped — no data loss, manually retryable |

</threat_model>
