<objective>
Mirror the fuser durability wiring (Plan 43-02) into the WinFsp callback path so Windows
gets the same crash safety. Reorder `handle_cleanup` (the Windows release equivalent) to
journal-fsync-before-spawn, and journal the `MkdirPublish` entry + signal a real retry on
parent-publish conflict in `handle_create` (the Windows mkdir path), replacing the existing
"v2" TODO.

Purpose: Without this, the two data-loss bugs remain on Windows even after the fuser fix —
integration tests would pass on macOS CI but Windows crash-recovery would still lose data
and orphan folders (Pitfall 2 in RESEARCH.md). D-12 mandates Windows be fixed in this same
phase, in its own plan.

Output: `handle_cleanup` journals the ciphertext `UploadFile` entry and fsyncs before
spawning the upload thread; `handle_create`'s directory branch journals the `MkdirPublish`
entry and, on conflict, sends `FsEvent::MkdirConflict { parent_ino }` instead of warning
only. Uses the same `WriteQueue` (Plan 01) and `FsEvent` (Plan 02) types via
`ctx.inner.lock().unwrap()`.
</objective>

<threat_model>

## Trust Boundaries

| Boundary | Description |
| -------- | ----------- |
| WinFsp `handle_cleanup` (no explicit reply) → background upload thread | Implicit ack occurs after callback returns; fsync must precede the spawn |
| Windows mkdir child IPNS published → parent metadata not yet published | The same orphan window as the fuser path, in a separate code path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --------- | -------- | --------- | ----------- | --------------- |
| T-43-09 | Data loss | Windows `handle_cleanup` ordering | mitigate | D-04: `fs.journal.put` (fsync) precedes the upload `thread::spawn`; crash-before-spawn is recoverable by replay |
| T-43-10 | Information Disclosure | Windows plaintext temp file | mitigate | D-05: `handle.cleanup()` runs immediately after the journal fsync, before spawn |
| T-43-11 | Data loss | Windows `handle_create` mkdir orphan | mitigate | D-11: MkdirPublish journaled before reply + `FsEvent::MkdirConflict` retry; entry cleared only on confirmed parent publish (replaces v2 TODO) |
| T-43-12 | Tampering | Windows-only patch gap | mitigate | D-12: Windows mirrors every fuser change so the two platforms cannot diverge into a one-sided orphan |

</threat_model>
