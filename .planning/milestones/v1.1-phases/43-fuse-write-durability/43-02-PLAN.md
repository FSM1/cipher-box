<objective>
Wire the durable journal (Plan 01) into the shared fuser callback path used by BOTH macOS
(FUSE-T) and Linux. Reorder `handle_release` to journal-fsync-before-ack, move the
plaintext temp-file cleanup before the upload thread spawns, journal the `MkdirPublish`
entry in `handle_mkdir` before `reply.entry()`, and replace the false "debounced publish
will retry" conflict warning with an actual `FsEvent::MkdirConflict` retry signal.

Purpose: This fixes the two data-loss bugs on macOS/Linux. The release path stops acking
the OS before durability is guaranteed (todo 1); the mkdir path stops orphaning the child
folder on parent-publish conflict and closes the crash-before-thread-runs window (todo 2).

Output: An `FsEvent` enum wrapping `UploadComplete` and a new `MkdirConflict { parent_ino }`
variant; a `journal: WriteQueue` field on `CipherBoxFS`; reordered release/mkdir callbacks;
and an extended `drain_upload_completions` that re-arms the debounced publisher on conflict.
macOS and Linux share this single code path (D-12) — Windows is a separate plan (43-03).
</objective>

<threat_model>

## Trust Boundaries

| Boundary | Description |
| -------- | ----------- |
| FUSE callback (single thread) → background upload thread | Durability must be established (journal fsync) before control leaves the callback |
| plaintext temp file → disk lifetime | Temp file must be zeroized+deleted the instant the ciphertext is durably journaled |
| mkdir child IPNS published → parent metadata not yet published | The crash/conflict window that orphans the child folder |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --------- | -------- | --------- | ----------- | --------------- |
| T-43-05 | Repudiation / Data loss | `handle_release` ack ordering | mitigate | D-04: `fs.journal.put` (fsync) precedes `reply.ok()`; a crash after ack is recoverable by replay |
| T-43-06 | Information Disclosure | plaintext temp file | mitigate | D-05: `handle.cleanup()` (zeroize+delete) runs immediately after the journal fsync, before the upload thread spawns |
| T-43-07 | Data loss | `handle_mkdir` orphan | mitigate | D-11: MkdirPublish journaled before `reply.entry()` (crash safety) + `FsEvent::MkdirConflict` retry signal (live-session); entry cleared only on confirmed parent publish |
| T-43-08 | Tampering | stale background upload overwrites newer content | mitigate | preserve `write_generation` capture and the existing `UploadComplete.write_generation` drain guard |

</threat_model>
