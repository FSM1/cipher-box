<objective>
Close the fuser write-side gaps: the release error path that silently acks (CR-04), the premature journal removal before the parent pointer is committed (CR-08), the TEE-wrapped mkdir key (CR-03), and the missing parent IPNS key needed by replay (CR-01 write-side). Also wire the first half of the retry/park pipeline (CR-07) by calling `record_failure` on background upload failure in the fuser path.

This plan owns `crates/fuse/src/read_ops.rs` (handle_release) and `crates/fuse/src/write_ops.rs` (handle_mkdir). It consumes the journal schema field `parent_ipns_key_hex` added in 43-05. The Windows mirror is 43-07 (disjoint files, same wave).

Purpose: stop the two remaining fuser data-loss windows and supply replay with the key material it needs to commit.
Output: corrected release error/removal ordering, user-wrapped + parent-key journaling on both fuser callbacks, and record_failure wiring.
</objective>

## Trust Boundaries

| Boundary | Description |
| -------- | ----------- |
| FUSE release/mkdir callback → journal file | wrapped keys + ciphertext fsynced before OS ack |
| OS (kernel) → handle_release reply | a false success ack loses data silently |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --------- | -------- | --------- | ----------- | --------------- |
| T-43-22 | Repudiation / data loss | handle_release prepare-failure arm | mitigate | Reply `EIO` and return on Err; only the post-fsync Ok arm acks success (CR-04) |
| T-43-23 | Data loss | premature `journal.remove` | mitigate | Remove only after `publish_file_metadata` Ok AND parent pointer publish confirmed; never on `upload_content` alone (CR-08) |
| T-43-24 | Information Disclosure | child_ipns_key_hex content | mitigate | Journal the user-ECIES-wrapped key (decryptable only by user); never raw, never TEE-wrapped (CR-03, D-05) |
| T-43-25 | Information Disclosure | parent_ipns_key_hex content | mitigate | User-ECIES-wrapped parent IPNS key only; journal file 0600 (CR-01 write-side, T-43-17) |
| T-43-26 | Repudiation | silent background upload failure | mitigate | `record_failure` increments retries and parks the entry; surfaced via WriteParked (CR-07, D-09) |

</threat_model>
