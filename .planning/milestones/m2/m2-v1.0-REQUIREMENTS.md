## v1 Requirements (Milestone 1 — Staging MVP)

All v1 requirements were shipped in Milestone 1 (2026-02-11).

### Authentication

- [x] **AUTH-01**: User can sign up with email and password via Web3Auth
- [x] **AUTH-02**: User can sign in with OAuth (Google, Apple, GitHub) via Web3Auth
- [x] **AUTH-03**: User can sign in with magic link (passwordless email) via Web3Auth
- [x] **AUTH-04**: User can sign in with external wallet (MetaMask, WalletConnect) via Web3Auth
- [x] **AUTH-05**: User session persists via access token (15min) and refresh token (7 days)
- [x] **AUTH-06**: User can link multiple auth methods to the same vault
- [x] **AUTH-07**: User can log out and all keys are cleared from memory

### Encryption

- [x] **CRYPT-01**: Files are encrypted client-side with AES-256-GCM before upload
- [x] **CRYPT-02**: File keys are wrapped with user's public key via ECIES (secp256k1)
- [x] **CRYPT-03**: Folder metadata is encrypted with folder key (AES-256-GCM)
- [x] **CRYPT-04**: IPNS records are signed client-side with Ed25519 keys
- [x] **CRYPT-05**: Private key exists only in client RAM, never persisted or transmitted
- [x] **CRYPT-06**: Each file uses unique random key and IV (no deduplication)

### File Operations

- [x] **FILE-01** through **FILE-07**: Upload, download, delete, rename, move, bulk upload, bulk delete

### Folder Operations

- [x] **FOLD-01** through **FOLD-06**: Create, delete, nest (20 levels), rename, move, per-folder IPNS

### Backend API

- [x] **API-01** through **API-08**: JWT verification, token rotation, IPFS relay, unpin, IPNS relay, vault keys, quota, TEE keys

### Multi-Device Sync

- [x] **SYNC-01** through **SYNC-03**: IPNS polling, background sync daemon, loading state

### TEE Republishing

- [x] **TEE-01** through **TEE-05**: 3-hour republish, ECIES-encrypted IPNS keys, hardware-only decrypt, job scheduling, key epoch rotation

### Web UI

- [x] **WEB-01** through **WEB-06**: Login, file browser, drag-drop, context menu, responsive, breadcrumbs

### Desktop App (macOS)

- [x] **DESK-01** through **DESK-07**: Login, FUSE mount, native apps, save, system tray, keychain, background sync

### Data Portability

- [x] **PORT-01** through **PORT-03**: Vault export JSON, encrypted keys, documented format

## Milestone 2 Requirements (Production v1.0)

### File Sharing

- [x] **SHARE-01**: User can share a folder (read-only) with another CipherBox user via ECIES key re-wrapping — Phase 14
- [x] **SHARE-02**: User can share with a recipient by pasting their secp256k1 public key — Phase 14
- [x] **SHARE-03**: Share takes effect instantly on public key paste (no accept/decline) — Phase 14
- [x] **SHARE-04**: User can revoke a share (triggers lazy folder key rotation) — Phase 14
- [x] **SHARE-05**: User can view "Shared with me" folders at ~/shared — Phase 14
- [x] **SHARE-06**: User can generate a shareable link (decryption key in URL fragment only) — Phase 15
- [x] **SHARE-07**: Recipient can open link, authenticate, auto-claim share — Phase 15

### Search

- [x] **SRCH-01**: User can search file names across all folders (client-side) — Phase 15.1
- [x] **SRCH-02**: Search index is encrypted and persisted in IndexedDB — Phase 15.1
- [x] **SRCH-03**: Search index updates incrementally on IPNS changes — Phase 15.1

### Multi-Factor Authentication

- [x] **MFA-01**: User can enable MFA via Core Kit settings — Phase 12.4
- [x] **MFA-02**: User can configure device share as an MFA factor — Phase 12.4
- [x] **MFA-03**: User can generate and store a backup recovery phrase — Phase 12.4
- [x] **MFA-04**: MFA enrollment does not change the derived keypair — Phase 12.4

### File Versioning

- [x] **VER-01**: System automatically retains previous file versions — Phase 13
- [x] **VER-02**: User can view version history — Phase 13
- [x] **VER-03**: User can restore a previous version — Phase 13
- [x] **VER-04**: Version retention policy enforced (max versions) — Phase 13
- [x] **VER-05**: Version storage counted against user quota — Phase 13

### Recycle Bin

- [x] **BIN-01**: Soft-delete to recycle bin — Phase 17
- [x] **BIN-02**: Browse and restore bin items — Phase 17
- [x] **BIN-03**: Permanent delete unpins CIDs + reclaims quota — Phase 17.1
- [x] **BIN-04**: Auto-purge after retention period — Phase 17
- [x] **BIN-05**: Bin items count against quota — Phase 17.1

### Advanced Sync

- [x] **SYNC-04**: Conflict detection via IPNS sequence number mismatch — Phase 16
- [ ] **SYNC-05**: Offline write queue — DEFERRED to M3 (conflict detection delivers core value)
- [ ] **SYNC-06**: Idempotency keys for queued ops — DEFERRED to M3 (depends on SYNC-05)

### TEE Enhancements

- [ ] **TEE-06**: AWS Nitro fallback TEE provider — DEFERRED to M3 Phase 22

### Cross-Platform Desktop

- [x] **PLAT-01**: Linux desktop app (Tauri + AppImage/deb, FUSE mount) — Phase 11.3
- [x] **PLAT-02**: Windows desktop app (Tauri + NSIS, WinFsp virtual drive) — Phase 11

### Cross-Platform E2E Testing

- [x] **E2E-01** through **E2E-05**: Cross-platform CI stack, round-trip tests, crypto compatibility, IPNS sync — Phase 11.4
