# Phase 11.4: Cross-Platform E2E Testing - Context

**Gathered:** 2026-02-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Validate that each desktop client (Windows, macOS, Linux) can round-trip correctly against the API and web client — proving cross-platform data integrity, encryption compatibility, and sync correctness. No new features; this is a testing and CI infrastructure phase only.

</domain>

<decisions>
## Implementation Decisions

### CI backend stack

- Native Postgres + IPFS installs per platform runner (brew on macOS, chocolatey/scoop on Windows, apt on Linux)
- Fresh NestJS API backend per CI run with empty database — full isolation, no staging pollution
- Cache the cargo-built desktop binary from existing build jobs and download it in the E2E job (avoid rebuilding Rust from scratch)

### CI trigger strategy

- Smart trigger: run on PRs only when desktop or crypto paths change (path filter)
- Full cross-platform matrix on pushes to main and release branches
- Manual workflow_dispatch available for ad-hoc runs

### Test execution model

- FUSE mount file operations: real file I/O (create, read, write, rename, delete) via standard OS calls through the mounted filesystem
- Install platform FUSE drivers on all three CI runners (FUSE-T on macOS, WinFsp on Windows, libfuse3 on Linux)
- Launch the actual Tauri app binary in test mode (--test flag or env var), not standalone Rust test binary
- Authenticate via dev-key auth (POST /auth/test-login) — no Web3Auth/Core Kit in CI

### Cross-platform interop

- Full data round-trip via API: web client uploads, desktop downloads and decrypts (and vice versa)
- Static test vectors (known plaintext/key/ciphertext) as baseline PLUS live API round-trips for integration confidence
- Cover both AES-GCM (standard files) and AES-CTR (media streaming) encryption modes
- Skip ECIES key wrapping interop — already proven in production via desktop device approval

### Test organization

- Shared test fixtures checked into git (encrypted test files + keys + expected metadata) as single source of truth for format compatibility
- Desktop-side tests only — don't extend web Playwright for interop (shared test vectors cover web-side validation)

### Claude's Discretion

- Where tests live in the monorepo (top-level tests/e2e-desktop/ vs apps/desktop/tests/)
- Test failure reporting format (standard cargo output vs JUnit XML artifacts)
- Virtual framebuffer (Xvfb) setup for headless Tauri on Linux CI
- Specific path filters for the smart trigger
- Test data cleanup strategy between runs

</decisions>

<specifics>
## Specific Ideas

- Reuse cached cargo binary artifact from existing CI build jobs rather than rebuilding — saves the full Rust compile step in the E2E job
- Tauri app in test mode gives closest-to-real user experience while still being automatable

</specifics>
