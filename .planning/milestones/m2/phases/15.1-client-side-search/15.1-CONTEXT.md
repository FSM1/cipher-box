# Phase 15.1: Client-Side Search - Context

**Gathered:** 2026-02-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Users can search file and folder names across their entire vault with an encrypted index persisted in IndexedDB. The search is triggered via a command palette overlay (Cmd/Ctrl+K). The index updates incrementally when IPNS polling detects metadata changes. Shared items are not indexed. Full-text content search is out of scope.

</domain>

<decisions>
## Implementation Decisions

### Search Interface

- Command palette / spotlight style overlay triggered by Cmd/Ctrl+K keyboard shortcut
- Small clickable search icon in the header as a visual hint (alongside the shortcut)
- Centered modal with search input at top, results streaming below as user types
- Escape key and click-outside both dismiss the overlay
- Backdrop: #000000CC (dimmed app background)

### Result Presentation

- Each result shows: file/folder name (bold), parent path breadcrumb, last modified date (right-aligned, abbreviated)
- File type icons (lucide) distinguish files from folders (file-text, folder, file-lock, file-spreadsheet, etc.)
- Match characters highlighted in the file name
- Keyboard navigable: arrow keys move selection, Enter opens result
- Selected result: green left border accent (2px #00D084) + subtle background highlight (#001a11)
- Click/select navigates to the parent folder with the matched item highlighted
- Footer shows keyboard hints: "↑↓ navigate ↵ open esc close" and "⌘K search"

### Index Scope & Behavior

- Index covers both file names and folder names (not content)
- Fuzzy matching (like VS Code file search — typing 'rpt' matches 'report.pdf')
- Index updates automatically on every IPNS poll (30s interval) when metadata changes detected
- Index encrypted with user's key before persisting to IndexedDB (zero-knowledge on disk)
- Own vault only — shared items ("Shared with me") are not indexed

### Empty & Edge States

- No results: simple message "No results for 'xyz'" — minimal, no suggestions
- First-time indexing: build on first search open with "Building index..." loading state
- Empty input: placeholder text "Search files..." only, no other content
- Empty vault: same "No results" message (no special empty-vault state needed)

### Claude's Discretion

- Exact number of visible results before scroll (somewhere around 8-10)
- Loading skeleton/spinner design during index build
- Debounce timing for search-as-you-type
- IndexedDB schema for encrypted index storage
- minisearch configuration (fields, boost weights, fuzzy threshold)

</decisions>

<specifics>
## Specific Ideas

- Command palette feel like VS Code Cmd+P or Raycast — fast, keyboard-first
- Terminal aesthetic must be preserved: JetBrains Mono, green on black, sharp corners (0 radius)
- Search overlay width: 600px (spacious option chosen), centered horizontally, positioned ~120px from top
- File type icons from lucide icon set (file-text, folder, file-lock, file-spreadsheet, etc.) in muted green (#006644), turning bright (#00D084) on selected row
- Result count shown as terminal comment: "// 5 results"

</specifics>

<deferred>
## Deferred Ideas

- Recent search history (show 2-3 past queries on overlay open) — nice-to-have for future release
- Searching shared items — would require indexing across share boundaries, separate phase
- Full-text content search — fundamentally different (requires decrypting file contents), out of scope

</deferred>
