# Phase 17.1 Plan 01: Bin CID Capture and Unpin Fix Summary

**Fix GAP-1: BinEntry extended with contentCid/contentSize, captured at soft-delete; permanent delete unpins using stored CID for files and decrypted folder metadata for folders**

## Performance

- **Duration:** 11 min

- **Completed:** 2026-03-04T23:59:35Z
- **Tasks:** 3
- **Files modified:** 6

## Accomplishments

- Extended BinEntry with optional contentCid/contentSize in TypeScript, Rust, and schema validator
- Fixed unpinFileCids to use stored contentCid, avoiding the GAP-1 bug of parsing AES-GCM-encrypted file metadata as plain JSON
- Rewrote cleanupFolderCids to unwrap folderKey via ECIES, decrypt folder metadata, then decrypt each nested file's metadata to extract CID for unpinning
- Desktop FUSE now captures file CID from inode data at unlink time
- All cleanupEntryCids call paths now receive userPrivateKey for folder key unwrapping

## Task Commits

Each task was committed atomically:

1. **Task 1: Add contentCid/contentSize to BinEntry types and schema** - `1748a014e` (feat)
2. **Task 2: Web-side fix for CID capture and unpin** - `dc1dbe26a` (fix)
3. **Task 3: Desktop-side CID capture at soft-delete** - `215ec6b89` (fix)

## Files Created/Modified

- `packages/crypto/src/bin/types.ts` - Added optional contentCid/contentSize to BinEntry type
- `packages/crypto/src/bin/schema.ts` - Added validation for new optional fields
- `apps/desktop/src-tauri/src/crypto/bin.rs` - Added content_cid/content_size to Rust BinEntry struct
- `apps/web/src/services/bin.service.ts` - Rewrote unpinFileCids, cleanupFolderCids, added CID capture in addToBin/addManyToBin
- `apps/web/src/hooks/useFolderMutations.ts` - Pass folderKey to addManyToBin for CID resolution
- `apps/desktop/src-tauri/src/fuse/write_ops.rs` - Capture CID from inode in handle_unlink BinEntry construction

## Decisions Made

- **Store CID at soft-delete:** Rather than attempting to re-decrypt AES-GCM-encrypted file metadata at permanent-delete time (which was the GAP-1 bug), we capture the plaintext CID and size when they're already available in memory during soft-delete.
- **Legacy fallback:** Existing bin entries without contentCid fall back to the old IPNS resolution path. This will fail for encrypted metadata but won't crash -- it logs an error and continues.
- **cleanupFolderCids takes FolderEntry:** Changed from accepting an IPNS name string to accepting the full FolderEntry, which provides direct access to folderKeyEncrypted for unwrapping.
