<objective>
Fix GAP-1 (CRITICAL): Bin permanent delete cannot unpin file CIDs because unpinFileCids()
attempts to decrypt AES-256-GCM-encrypted file metadata as plain JSON. The fix has two parts:

1. **File bin entries:** Store plaintext CID and size in BinEntry at soft-delete time (when the
   data is already available in memory), then use these stored fields at permanent-delete time.

2. **Folder bin entries:** At permanent-delete time, unwrap the folderKey from the BinEntry's
   folderEntry.folderKeyEncrypted using userPrivateKey, then for each nested file, resolve its
   IPNS, fetch the encrypted file metadata, decrypt it with the folder key, and extract the CID
   for unpinning. The userPrivateKey is already available in all permanent-delete callers.

Purpose: Without this fix, permanently deleting bin items never reclaims IPFS storage or updates quota.
Output: BinEntry schema extended with optional contentCid/contentSize, web and desktop soft-delete paths
capture these fields, unpinFileCids uses stored fields, cleanupFolderCids properly decrypts nested files.
</objective>

    2. Rewrite `cleanupFolderCids` to accept `FolderEntry` + `userPrivateKey`, unwrap the
       folder key, then decrypt each nested file's metadata to get the CID:
       ```typescript
       async function cleanupFolderCids(
         folderEntry: FolderEntry,
         userPrivateKey: Uint8Array
       ): Promise<void> {
         try {
           // Step 1: Unwrap the folder's AES key using user's private key
           const wrappedFolderKey = hexToBytes(folderEntry.folderKeyEncrypted);
           const folderKey = await unwrapKey(wrappedFolderKey, userPrivateKey);

           // Step 2: Resolve folder's IPNS to get its metadata CID
           const resolved = await resolveIpnsRecord(folderEntry.ipnsName);
           if (!resolved?.cid) return;

           // Step 3: Fetch and decrypt the folder metadata
           const metaBytes = await fetchFromIpfs(resolved.cid);
           const metaJson = new TextDecoder().decode(metaBytes);
           const encrypted = JSON.parse(metaJson) as { iv: string; data: string };

           // Import decryptFolderMetadata from @cipherbox/crypto
           const folderMeta = await decryptFolderMetadata(encrypted, folderKey);

           // Step 4: For each child, unpin CIDs
           for (const child of folderMeta.children) {
             try {
               if (child.type === 'file') {
                 const fp = child as FilePointer;
                 // Decrypt file metadata to get content CID
                 const fileResolved = await resolveIpnsRecord(fp.fileMetaIpnsName);
                 if (fileResolved?.cid) {
                   const fileMetaBytes = await fetchFromIpfs(fileResolved.cid);
                   const fileMetaJson = new TextDecoder().decode(fileMetaBytes);
                   const encryptedFileMeta = JSON.parse(fileMetaJson) as { iv: string; data: string };
                   const fileMeta = await decryptFileMetadata(encryptedFileMeta, folderKey);
                   if (fileMeta.cid) {
                     await unpinFromIpfs(fileMeta.cid);
                     if (fileMeta.size && typeof fileMeta.size === 'number') {
                       useQuotaStore.getState().removeUsage(fileMeta.size);
                     }
                   }
                   // Also unpin the file metadata CID
                   await unpinFromIpfs(fileResolved.cid).catch(() => {});
                 }
               } else if (child.type === 'folder') {
                 // Recursive: subfolder's folderKeyEncrypted is wrapped with PARENT folder's key,
                 // not the user's key. We need to unwrap it differently.
                 // Actually, FolderEntry.folderKeyEncrypted is ECIES-wrapped with the USER's
                 // publicKey (see folder metadata spec). So we can unwrap with userPrivateKey.
                 const subFe = child as FolderEntry;
                 await cleanupFolderCids(subFe, userPrivateKey);
               }
             } catch (childErr) {
               console.error(`[Bin] Failed to cleanup CIDs for child ${child.name}:`, childErr);
             }
           }

           // Unpin the folder metadata CID itself
           await unpinFromIpfs(resolved.cid).catch(() => {});
         } catch (err) {
           console.error(`[Bin] Folder CID cleanup failed for ${folderEntry.ipnsName}:`, err);
         }
       }
       ```
