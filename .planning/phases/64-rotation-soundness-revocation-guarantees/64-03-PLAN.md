<objective>
Fill the `mintFileKeyOnRotate` seam (ROT-03 / CRIT-1) in `packages/sdk-core/src/rotation/engine.ts` — currently `throw new Error('not implemented — phase 64 (ROT-03/CRIT-1 content-key rotation)')` at L200-202. Per design §4.1 and ADR 0002 (D-05): rotating a file node must mint a fresh `fileKey' = 32 random bytes` so that read-revocation protects FUTURE content. Re-sealing the read-body under `readKey'` alone is insufficient — the revoked reader already holds the old `content.fileKey`; if the next write reuses it the revoked reader can still decrypt it (Pitfall 2).

Purpose: close CRIT-1, the highest-severity revocation gap. The re-key is lazy (applied on the next content write — Phase 65 wires the write path); Phase 64's job is to mint `fileKey'` and place it on the node so `rotateOne`'s `sealNode(updatedNode, readKeyPrime, …)` re-seals the body carrying the new fileKey. ADR 0002 honesty: a cold file never rewritten keeps its old still-pinned CID decryptable — read-revocation protects future writes/navigation/filenames, NOT already-distributed content. Crypto business logic with defined I/O → TDD.
Output: a filled `mintFileKeyOnRotate` + engine.test.ts content-key assertions.
</objective>
