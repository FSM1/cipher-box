<objective>
Fix the Phase-63 CRITICAL re-seal bug and adopt fail-closed publishing — the two changes that make the multi-level BFS walk actually sound. In `packages/sdk-core/src/rotation/engine.ts`:

1. **D-01 fail-closed (publish path):** delete the `ipnsPrivateKey: nodeIpnsPrivateKey ?? PLACEHOLDER_WRITE_KEY` fallback in `rotateOne`'s `publishWithCas` call (L357). Throw if no real key is available. Add a test-supplied `nodeKeySource` to `RotationParams` and thread per-node keys through the BFS so children publish with real keys (the test key source — production write-body→key wiring is Phase 65). Keep the `PLACEHOLDER_WRITE_KEY` only as the `sealNode` writeKey argument (the write-BODY is legitimately absent until Phase 65 — that is a separate concern from the publish key).
2. **D-02 out-of-band re-seal + D-09 batched parent-publish:** `rotateOne` currently seals `newReadKeySealed` under `parentReadKey` (the child's OWN pre-rotation key — a legacy misnomer) and the caller never writes it back to any parent. The re-seal MUST happen in `rotateReadFromNode`: after each child's `rotateOne` returns its freshly minted `childReadKey` (the child's new readKey'), re-seal it under the PARENT's NEW readKey' via `sealChildReadKey`, write it onto the parent's in-memory `SealedChildRef[child].readKeySealed` + `.generation` mirror, and re-publish the parent ONCE after all its children rotate (batched per §4.7, via a `Map<parentIpnsName, parentState>`). Without this, every non-root node AEAD-fails on `unsealChildReadKey` (Pitfall 1).

Purpose: this is the single place the walk is genuinely reworked (CONTEXT D-02 / specifics: "the one place the walk is genuinely reworked, done in the caller, not by reshaping rotateOne's contract"). It underpins ROT-06 convergence — a multi-level subtree must converge with every node reachable and no double-bump. Implements D-01, D-02, D-09.
Output: fail-closed publishing, a threaded key source, the out-of-band re-seal + batched parent-publish, and strengthened engine.test.ts assertions.
</objective>
