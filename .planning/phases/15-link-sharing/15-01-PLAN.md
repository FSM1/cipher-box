    NestJS requires one @Controller() decorator per class, so two path prefixes require two controller classes. Create both in the shares/ directory.

    1. Create `invites.controller.ts` -- `@Controller('invites')` with NO class-level auth guard:

       This controller handles the public-facing invite routes at the `/invites` prefix.

       Endpoints:
       a. `GET /invites/:token` -- **NO AUTH, WITH ThrottlerGuard** -- returns `{ status: 'active' | 'expired' | 'claimed' | 'revoked' }` only. Opaque -- no file name, no sharer identity before auth. Uses `@ApiTags('invites')`. ThrottlerGuard prevents token enumeration.
       b. `GET /invites/:token/data` -- **WITH JwtAuthGuard + ThrottlerGuard** -- returns full invite data needed for the claim flow: `{ status, encryptedKey (hex), encryptedChildKeys, itemType, ipnsName, itemName }`. This is the endpoint the client calls AFTER authentication to get the encrypted keys for unwrapping. The encryptedKey bytea column must be converted to hex string in the response. Returns 404 if invite not found or expired. Returns the InviteDataResponseDto.
       c. `POST /invites/:token/claim` -- **WITH JwtAuthGuard + ThrottlerGuard** -- accepts ClaimInviteDto (re-wrapped keys from client), creates Share + ShareKey records via existing SharesService.createShare() pattern, returns `{ shareId }`.

       Apply `@UseGuards(JwtAuthGuard, ThrottlerGuard)` per-method on endpoints b and c. Apply only `@UseGuards(ThrottlerGuard)` on endpoint a.

    2. Create `share-invites.controller.ts` -- `@Controller('shares/invites')` WITH class-level `@UseGuards(JwtAuthGuard, ThrottlerGuard)` and `@ApiBearerAuth()`:

       This controller handles the sharer's invite management routes at the `/shares/invites` prefix.

       Endpoints:
       d. `POST /shares/invites` -- accepts CreateInviteDto, generates token, creates ShareInvite, returns invite details + token (InviteResponseDto).
       e. `GET /shares/invites` -- query param `ipnsName` (required), returns sharer's active invites for that item (InviteResponseDto[]).
       f. `DELETE /shares/invites/:inviteId` -- revokes an invite (sets status='revoked'). Only the sharer can revoke.

       Uses `@ApiTags('share-invites')`.

       Import `RequestWithUser` interface matching the pattern in shares.controller.ts.

    3. Add invite methods to `SharesService`:
       - `createInvite(sharerId, dto)`: Generate token via `crypto.randomBytes(16).toString('base64url')`, set expiresAt to now+7 days, save and return.
       - `getInviteStatus(token)`: Find by token. If active and expired, hard-delete and return null. If found, return { status }. If not found, return null (controller returns 'expired').
       - `getInviteForClaim(token)`: Find by token with full data (encryptedKey, encryptedChildKeys, itemType, ipnsName, itemName). Auto-expire check. Return invite or null. This is the method backing `GET /invites/:token/data`.
       - `claimInvite(token, claimerId, dto)`: ATOMIC -- use `UPDATE share_invites SET status='claimed', claimed_by=:userId, claim_count=claim_count+1 WHERE token=:token AND status='active' AND claim_count < max_claims AND expires_at > NOW()`. Check `affected === 1`. If not, throw ConflictException. Then create Share + ShareKey records using the re-wrapped keys from the DTO. Self-claim prevention: check invite.sharerId !== claimerId. Return { shareId }.
       - `getInvitesForItem(sharerId, ipnsName)`: Find active invites by sharer + ipnsName, auto-clean expired.
       - `revokeInvite(inviteId, sharerId)`: Find invite, check sharerId matches, set status='revoked'.
