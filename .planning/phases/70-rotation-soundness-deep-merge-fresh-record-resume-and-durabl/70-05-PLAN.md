<objective>
Make `verifySubtreeClean` recurse the full subtree and treat a missing root record as unclean (SC#2). Today (engine.ts L491-524) it checks only the root's immediate children and returns `{ isDirty: false, frontier: [] }` when the root IPNS record is missing — a resume then re-enters rotateOne(root) blind. This is the largest single lift in the phase (RESEARCH Pitfall 3): the frontier item shape must change to carry engine-derived keys so a dirty node at any depth can seed the BFS directly.

Purpose: Provide the correct, depth-agnostic dirty-frontier that the fresh-record resume (plan 70-06) consumes.
Output: recursive verifySubtreeClean + shared traversal helper + multi-level fixture tests; stale docstring corrected.
</objective>

<artifacts>

- restructured `verifySubtreeClean(rootIpnsName, rootReadKey, ctx)` returning a richer frontier item shape: { ipnsName, nodeId, parentIpnsName, nodeReadKey, childPubKind, enqueuedGeneration }
- a shared internal traversal helper (e.g. `resolveChildKey`/`walkSubtree`) invoked by both verifySubtreeClean and the main BFS
- new multi-level (>= depth 2) engine.test.ts fixture + dirty-at-depth and missing-root-is-dirty cases
</artifacts>
