<objective>
Hard-cut the vault recovery blob to v3 (two ECIES-wrapped keys in one binary envelope) and remove the legacy single-key `encryptedRootFolderKey` surface. This is the NODE-06 deliverable and is independent of the `node/` codec (it only uses ECIES wrap/unwrap), so it runs in Wave 1 in parallel with Plan 01.

Purpose: The root node now has two independently sealed bodies (read + write), so vault recovery must carry both `ECIES(rootReadKey)` and `ECIES(rootWriteKey)` (D-05). Greenfield (staging wiped, no prod data) permits deleting the v2/v1 paths outright — no dual-codec.

Output: v3-only `vault/blob.ts`; two-key `vault/types.ts` + `vault/init.ts`; `tests/vectors/vault-v3-blob.json` (frozen two-key vector committed in the shared cross-language fixture set); refreshed `vault-blob-vectors.test.ts` (loads that JSON); updated `vault-blob.test.ts` + `vault.test.ts`; vault export block in the package barrel.

This plan implements ZERO phase-63–69 behavior — it builds no Node, runs no rotation. It only reshapes the key-recovery blob.
