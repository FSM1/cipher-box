<objective>
Consolidate the duplicated fuser/winfsp journal write paths (#11) into a shared `journal_helpers.rs` module: one `build_upload_journal_entry` for the upload path (handle_release / handle_cleanup) and one `build_mkdir_journal_entry` for the mkdir path (handle_mkdir / handle_create dir branch). The structurally identical encrypt → ECIES-wrap → resolve-parent-IPNS → build-JournalEntry steps move into the shared builders; each platform keeps its own reply/return, inode mutation, and spawn. Lands LAST so it runs against the stabilized journal shape (#18) and replay refactors (#15/#20), with the Plan-01 safety net green.

Purpose: `read_ops.rs:695-1003` (fuser) and `windows/write_ops.rs:791-1083` (winfsp) are near-identical closures; `write_ops.rs:430-689` (fuser mkdir) and `windows/write_ops.rs:75-284` (winfsp mkdir) likewise. Two copies of the same ECIES-wrap + journal-build logic drift silently. One shared builder removes that.
Output: new `crates/fuse/src/journal_helpers.rs` with `build_upload_journal_entry` + `build_mkdir_journal_entry` (and their result structs); `pub mod journal_helpers` in lib.rs; all four call sites delegate the entry-build step to the shared helpers.
</objective>
