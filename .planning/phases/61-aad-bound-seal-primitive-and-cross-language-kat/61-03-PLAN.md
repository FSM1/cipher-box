<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sealed blob → unsealAesGcmAad | An attacker may replay a blob under a different node identity (AAD transplant) or tamper the tag/length |
| AAD construction → AEAD | The AAD must flow into the GCM computation, not merely be built alongside it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-61-07 | Tampering | AAD transplant (replay under different node identity) | high | mitigate | GCM auth-tag binds AAD; D-02 transplant suite proves unseal rejects wrong nodeId/role/generation/kind/domain |
| T-61-08 | Tampering | auth-tag truncation / short blob | high | mitigate | MIN_SEALED_SIZE (IV+tag=28) guard mirrors non-AAD unseal; truncated-blob test |
| T-61-09 | Tampering | IV reuse under a fixed key | high | mitigate | sealAesGcmAad always mints generateIv(); fixed-IV path is the test-only encryptAesGcmAad; fresh-IV assertion in tests |
| T-61-10 | Tampering | AAD built but not threaded into AEAD | high | mitigate | Full-seal KAT (D-01b) pins exact ciphertext, which only matches if AAD enters the GCM computation |
</threat_model>
