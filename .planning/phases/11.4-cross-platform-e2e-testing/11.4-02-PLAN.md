  Create the `tests/e2e-desktop/scripts/` directory and write these 4 scripts.

**wait-for-mount.sh** (bash, macOS/Linux):

- Accept mount point as first arg, default to `$HOME/CipherBox`
- Poll with `test -d "$MOUNT_POINT" && mount | grep -q CipherBox` every 2 seconds
- Timeout after 90 seconds (configurable via `$MOUNT_TIMEOUT` env var)
- On success: `echo "Mount detected at $MOUNT_POINT"`, exit 0
- On timeout: `echo "FAIL: Mount not detected after ${MOUNT_TIMEOUT}s"`, exit 1
- Use `set -euo pipefail` and include a shebang `#!/usr/bin/env bash`
- On macOS, mount output shows "smbfs" (FUSE-T SMB backend), so grep for the mount path rather than filesystem type
- On Linux, mount output shows "fuse" type, also grep for mount path for consistency

**wait-for-mount.ps1** (PowerShell, Windows):

- Accept mount point as parameter, default to `"$env:USERPROFILE\CipherBox"`
- Poll with `Test-Path $MountPoint` every 2 seconds
- Timeout after 90 seconds (configurable via `$env:MOUNT_TIMEOUT`)
- Same success/failure messaging pattern
- Use `$ErrorActionPreference = "Stop"`

**run-all.sh** (bash, macOS/Linux):

- Shebang `#!/usr/bin/env bash`, `set -euo pipefail`
- Accept `MOUNT_POINT` env var, default to `$HOME/CipherBox`
- Accept `API_URL` env var, default to `http://localhost:3000`
- Accept `TEST_SECRET` env var, default to `e2e-test-secret-ci-only`
- Script dir: `SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"`
- Step 1: Run `wait-for-mount.sh`
- Step 2: Run `test-fuse-operations.sh "$MOUNT_POINT"`
- Step 3: Run `test-round-trip.sh "$MOUNT_POINT" "$API_URL" "$TEST_SECRET"`
- Print summary: total tests passed/failed, exit code
- Each script sourced via `bash "$SCRIPT_DIR/..."` -- if any fails, report but continue to collect all results

**run-all.ps1** (PowerShell, Windows):

- Same orchestration pattern but calling .ps1 equivalents
- `$ErrorActionPreference = "Stop"` at top
- Use `& "$PSScriptRoot\wait-for-mount.ps1"` etc.

All bash scripts must be executable: add a note in the action that `chmod +x` should be run. Actually, set the git filemode: create the files and then `git update-index --chmod=+x` on the .sh files.

  **test-fuse-operations.sh** (bash, macOS/Linux):
  Accept mount point as `$1`, default `$HOME/CipherBox`. Use `set -euo pipefail`.

Test cases (each prints PASS/FAIL with descriptive message):

1. **Create and read text file:** `echo "Hello from CI" > "$MP/e2e-test.txt"`, sleep 3, verify `cat "$MP/e2e-test.txt"` equals "Hello from CI"
2. **Create directory:** `mkdir -p "$MP/e2e-folder"`, verify `test -d "$MP/e2e-folder"`
3. **Write file in subdirectory:** `echo "Nested content" > "$MP/e2e-folder/nested.txt"`, sleep 3, verify content
4. **Overwrite file (modify):** `echo "Modified content" > "$MP/e2e-test.txt"`, sleep 3, verify content changed
5. **Binary file round-trip:** `dd if=/dev/urandom of=/tmp/e2e-binary.bin bs=1024 count=256 2>/dev/null`, `cp /tmp/e2e-binary.bin "$MP/e2e-binary.bin"`, sleep 5 (larger file), verify SHA-256 checksums match. Use `shasum -a 256` on macOS or `sha256sum` on Linux -- detect which is available.
6. **Rename file:** `mv "$MP/e2e-test.txt" "$MP/e2e-renamed.txt"`, sleep 2, verify old doesn't exist and new has correct content
7. **Delete file:** `rm "$MP/e2e-renamed.txt"`, sleep 2, verify file is gone
8. **Delete directory:** `rm -rf "$MP/e2e-folder"`, sleep 2, verify directory is gone
9. **Cleanup:** Remove `$MP/e2e-binary.bin` if it exists, remove `/tmp/e2e-binary.bin`

Track pass/fail count. Exit with count of failures.

IMPORTANT: Sleep values must be generous for CI (debounced IPNS publish = 1.5s debounce + upload time). Use 3s for small text files, 5s for binary files. The desktop app's FUSE write -> release() -> encrypt + upload -> publish cycle needs time.

IMPORTANT: Filter `.DS_Store` from directory listings when checking (macOS Finder may create them even in CI).

**test-fuse-operations.ps1** (PowerShell, Windows):
Same test cases adapted for PowerShell:

- `Set-Content` / `Get-Content` instead of echo/cat
- `New-Item -ItemType Directory` instead of mkdir
- `Copy-Item` instead of cp
- `Get-FileHash -Algorithm SHA256` instead of shasum
- `Move-Item` instead of mv
- `Remove-Item` instead of rm
- `Start-Sleep -Seconds N` instead of sleep
- Mount point default: `"$env:USERPROFILE\CipherBox"`

**test-round-trip.sh** (bash, macOS/Linux):
Accept: `$1` = mount point, `$2` = API URL, `$3` = test login secret.

Tests (using curl + jq):

1. **Authenticate via test-login:** `curl -s -X POST "$API_URL/auth/test-login" -H "Content-Type: application/json" -d '{"email":"e2e-desktop-roundtrip@test.local","secret":"$SECRET"}'` -> extract accessToken
2. **Desktop writes file, API verifies vault exists:** After writing `"API-visible content"` to `"$MP/rt-test.txt"`, sleep 5, then call `GET $API_URL/vault` with Bearer token to verify the vault has content (root IPNS name is set). This is a basic reachability check -- the encrypted data is opaque to the API.
3. **Verify IPNS resolve returns data:** Call `GET $API_URL/ipns/{rootIpnsName}/resolve` to verify IPNS published successfully. Should return a CID.
4. **Cleanup:** Remove `"$MP/rt-test.txt"`

Note: We cannot verify decrypted content via the API because the server is zero-knowledge. The round-trip test proves: file written to FUSE -> encrypted -> uploaded to IPFS -> IPNS published -> API can see the vault metadata.

**test-round-trip.ps1** (PowerShell, Windows):
Same tests using `Invoke-RestMethod` instead of curl, `ConvertFrom-Json` instead of jq.

All bash scripts must be executable (chmod +x).
