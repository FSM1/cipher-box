# Phase 68.2: SDK-Owned Read Chain and Resolved Folder Listings - Context

**Gathered:** 2026-07-06
**Status:** Ready for planning

<domain>
## Phase Boundary

Move the entire gated read chain — IPNS resolve + the ROT-07 durable anti-rollback gate + IPFS fetch + node unseal + per-child metadata resolution — and per-child listing resolution out of `apps/web/src/services` and into `packages/sdk` (facade) over `packages/sdk-core`/`packages/core` primitives. The SDK becomes the single source of truth: it exposes **resolved folder listings** (`ResolvedChild` carrying `ipnsName`, `name`, `kind`, `size?`, `modifiedAt`, `sequence`) and owns resolve + cache + invalidation. `apps/web/src/stores/folder.store.ts` collapses to a thin projection of SDK state/events. This closes the Web/SDK folder-state desync bug class (owner not seeing a grantee's upload until they themselves write; size/modifiedAt display gaps).

**Scope expansion locked in discussion (beyond roadmap literal SC#1):** the SDK-mediation boundary applies to **both the read AND the write paths** on the TypeScript side. `apps/web/src` must make **no runtime calls into `@cipherbox/sdk-core` or `@cipherbox/core`, and no raw IPFS/IPNS access** — all resolve/fetch/seal/unseal/publish flows through `@cipherbox/sdk` (`CipherBoxClient`). The whole reason the SDK exists is to mediate this.

**In scope:** SDK-owned gated read chain + resolved listings API; freshness/invalidation ownership; reverting the interim `SealedChildRef.size`/`modifiedAt` mirror (commit `ba3e0229a`); collapsing `folder.store.ts` to a projection; rewiring **all** `apps/web/src` read- and write-path runtime call sites off `@cipherbox/sdk-core`/`@cipherbox/core`/raw IPFS-IPNS and onto the `@cipherbox/sdk` facade; deleting `apps/web/src/services/ipns.service.ts`, `file-metadata.service.ts`, `apps/web/src/lib/kind-cache.ts`, `apps/web/src/hooks/useFileSize.ts`; a `tests/web-e2e` proving the desync fix; full web-e2e green.

**Out of scope:** Phase 69 (FUSE/WinFsp/Rust) — Phase 69 is **entirely** the Rust/Desktop side and must NOT be conflated with the TS code (web + sdk); no codec/crypto redesign; no change to the frozen `Node`/`SealedChildRef` read schema (SC#4 restores it to its five-field NODE-03 set).

</domain>

<decisions>
## Implementation Decisions

### SDK read-listing API surface + web consumption (Read API)
- **D-01:** The SDK exposes an **imperative pull + event push** model: `client.listFolder(ipnsName)` / `client.listSharedFolder(...)` returning `ResolvedChild[]`, plus a `folder:updated` event. `apps/web/src/stores/folder.store.ts` becomes a **thin Zustand projection** that subscribes to SDK events — it is not an independent source of truth (SC#3). Chosen over an SDK-owned reactive store (new pattern, no precedent) and React Query (reintroduces a second cache outside the SDK, tension with SC#2/#3). Matches existing `CipherBoxClient` patterns.
- **D-02:** `ResolvedChild` is the single carrier of `kind`, `size?`, `modifiedAt`, `sequence` per child (plus `ipnsName`, `name`), resolved once per folder load and cached inside the SDK. This subsumes the D-02 kind-cache and `useFileSize` mechanisms from 68.1 — both are deleted.

### Freshness / cache-invalidation (the desync fix — SC#5)
- **D-03:** Belt-and-suspenders freshness: **re-resolve on every folder open/navigation** (no stale cache carried across navigation; cache is per-open-view) **AND** poll-driven invalidation for the currently-open folder layered on the existing 30s IPNS poll doctrine. The nav-resolve leg is the deterministic SC#5 fix (owner sees a grantee's upload without writing first); the poll leg keeps an already-open folder live.

### Anti-rollback gate consolidation + resolve scope (Gate / boundary)
- **D-04:** **Reuse the existing `RotationHighWater` + IndexedDB-backed `HighWaterStore` seam** (`packages/sdk/src/state/rotation-high-water.ts`, injected into `client.ts:1063`) as the "DurableFloorStore" the roadmap names — do **not** introduce a new floor-store abstraction (avoids two stores drifting). The new gated read-listing resolve routes through `RotationHighWater.enforceResolved`.
- **D-05:** The **gated listing path is the single read entrypoint** and always enforces the floor gate. Raw `sdk-core` `resolveIpnsRecord` becomes **SDK-internal only** (rotation/write internals); it is never called from the read path and never from `apps/web/src`.
- **D-06:** `HighWaterStore` must be **injectable/mockable for Node.js SDK unit tests** (the browser supplies the real IndexedDB adapter; tests inject a fake — mirrors the existing `fakeRotationHighWater` pattern in `packages/sdk/src/__tests__/client-rotation.test.ts`). Keeps the SDK persistence-decoupled and unit-testable off-browser.
- **D-07 (boundary — read + write):** `apps/web/src` performs **no runtime calls into `@cipherbox/sdk-core` or `@cipherbox/core`, and no raw IPFS/IPNS access, on either the read or the write path** — everything is mediated by `@cipherbox/sdk` (`CipherBoxClient`). Acceptance is a `grep` gate. **Type-only imports** (`import type { ... }`) from `@cipherbox/core`/`@cipherbox/sdk-core` remain allowed (the SDK MAY re-export the needed types for convenience); the boundary is about runtime I/O and crypto, not type definitions. Forbidding type imports would be a ~54-file no-op churn and is explicitly NOT intended.
  - **D-07 scope resolution (2026-07-06, plan-phase — resolves RESEARCH.md Open Question 3):** **Full boundary.** The grep gate covers **all of `apps/web/src` with zero runtime violations and no allowlist carve-out** — including the two off-path pockets the SC#1–5 wording does not name: (a) BYO-pinning settings (`apps/web/src/components/settings/ConnectionTest.tsx`, `StorageTab.tsx` — the config-blob `testConnection` / `addToIpfs` / `fetchFromIpfs` / `resolveIpnsRecord` / `createAndPublishIpnsRecord` calls), and (b) auth-bootstrap/device-registry crypto (`apps/web/src/hooks/useAuth.ts`, `apps/web/src/services/device-registry.service.ts` — the login-time `@cipherbox/core` key-wrapping runtime imports). All are rewired onto the `@cipherbox/sdk` facade this phase (~4 files beyond the folder-listing data path). SDK-READ-04's acceptance is therefore an unscoped, allowlist-free grep across `apps/web/src`. Chosen over a scoped gate because an allowlist is exactly the boundary erosion the governing principle rejects.

### Cutover sequencing + mirror revert (Cutover)
- **D-08:** **Big-bang, gated on full web-e2e green.** Order: (1) build the SDK listing API + gated resolve + facade write mediation; (2) add the desync web-e2e (owner/second-client sees a grantee's upload into a shared folder without writing first; size/modifiedAt render from the resolved listing); (3) rewire all `apps/web/src` read+write runtime call sites onto the facade and delete `ipns.service.ts`/`file-metadata.service.ts`/`kind-cache.ts`/`useFileSize.ts` + collapse `folder.store.ts`; (4) **revert the `ba3e0229a` `SealedChildRef` mirror LAST**, once `ResolvedChild` demonstrably renders size/modifiedAt — no display-regression window. Not behind a fallback flag (would leave dual state, against SC#3).

### Reusable Assets
- `RotationHighWater` + IndexedDB `HighWaterStore` (`packages/sdk/src/state/rotation-high-water.ts`) — the durable floor gate already exists and is injected into `client.ts`; reuse as the read-path gate (D-04) rather than building a new `DurableFloorStore`.

- `fakeRotationHighWater` (`client-rotation.test.ts`) — the mock/injection pattern for Node SDK unit tests (D-06).

### Established Patterns
- **Boundary blast radius (grounds the D-07 grep gate):** `apps/web/src` currently has ~15 runtime `@cipherbox/sdk-core` import sites and ~19 files touching raw IPFS/IPNS (`lib/api/ipfs`, `fetchFromIpfs`, `addToIpfs`); 54 files import `@cipherbox/core` but **most are type-only** — the gate must distinguish runtime calls from `import type`.
- Web/SDK folder-state desync doctrine: state lived in BOTH the Zustand store and the SDK `folderTree`; `sequenceNumber` is the clock; reconcile before mutations (68-11). This phase removes the duplication root-cause.
- Terminal-owner zeroing rule (68.1 D-09): zero minted/derived keys on success + in catch/finally; never zero caller-supplied buffers.
- Cross-package build order: rebuild `sdk-core`/`sdk` dist before web typecheck/e2e (vite/API resolve built dist).

### Integration Points
- `folder.store.ts` (+ shared-folder projection hooks) subscribe to the new SDK `folder:updated` event (D-01).
- Web read+write runtime call sites (file browser hooks/components, shared nav/write hooks, services) rewire onto `CipherBoxClient` facade methods (D-07).
- Requirements SDK-READ-01..04 to be registered in `.planning/REQUIREMENTS.md` during planning — extend/rename to also cover the write-path facade mediation locked by D-07 (both planes are in scope this phase).
