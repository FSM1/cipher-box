# Phase 68.2 Learnings: SDK-Owned Read Chain and Resolved Folder Listings

## Decisions

### D-05: single gated read entrypoint inside the SDK
Every read-path IPNS resolve (`resolvePublishedNode` / `dfsFindFolder` / `ensureFolderLoaded` / `listFolder` / `listSharedFolder`) enforces the ROT-07 durable anti-rollback floor via `RotationHighWater.enforceResolved`, fail-closed on `signatureVerified=false` before any floor mutation.

**Rationale:** the working read-side gate previously lived only in the web (`ipns.service.ts`, deleted this phase); the SDK's internal navigate path was ungated. Centralizing it makes the SDK the sole in-process owner and removes the web parallel path.
**Source:** 68.2-01-PLAN.md, 68.2-VERIFICATION.md, 68.2-SECURITY.md

### D-07: allowlist-free web/SDK boundary (full scope)
`apps/web/src` makes zero runtime imports of `@cipherbox/sdk-core`/`@cipherbox/core` and no raw IPFS/IPNS access (type-only `import type` allowed), enforced by a grep gate across ALL of `apps/web/src` with no allowlist — including BYO-pinning and auth-bootstrap/device-registry crypto.

**Rationale:** a partial boundary invites drift; a full, allowlist-free gate is verifiable in one command.
**Source:** 68.2-CONTEXT.md (D-07 resolution), 68.2-11 (grep gate commit)

### D-02: ResolvedChild as the single per-child listing answer
`listFolder`/`listSharedFolder` return `ResolvedChild[]` (`ipnsName, name, kind, size?, modifiedAt, sequence`), resolved once per folder load and cached in the SDK; the web renders directly with no web-side per-child resolve or cache. Subsumes the deleted web kind-cache + useFileSize.

**Rationale:** one owner of per-child metadata eliminates the desync between the web's cache and the SDK's state.
**Source:** 68.2-02, folder-listing.ts

### Gate-then-delete ordering
The SDK read-path gate (plan 01) landed BEFORE any web read-service deletion (plan 11), so no shipped anti-rollback guarantee regressed during the migration.

**Rationale:** deleting the old gate first would open a coverage window.
**Source:** 68.2-01-PLAN.md (Pitfall 2)

### NODE-03 mirror reverted LAST
The interim `SealedChildRef.size`/`modifiedAt` display mirror was reverted only after every render site rendered from `ResolvedChild`, so `SealedChildRef` returned to its frozen five-field set with no display-regression window.

**Rationale:** revert-last avoids a window where the web still reads mirror fields that no longer exist.
**Source:** 68.2-12-SUMMARY.md

## Lessons

### Post-mutation refresh must target the OPEN folder, not root
`UploadZone` targets `currentFolderId` (may be a subfolder) but `handleSync` (the `onUploadComplete` handler) only resynced root. An upload into a subfolder never appeared until the 30s poll's `invalidateOpenFolder` leg fired. Fix: call `invalidateOpenFolder()` immediately on upload complete.

**Context:** the initial hypothesis (SDK cache staleness on root) was wrong — the refresh was resolving the wrong folder. `forceResolve` is necessary for freshness but useless if aimed at the wrong ipnsName.
**Source:** 68.2-16-SUMMARY.md

### `isFileRef(bareSealedChildRef)` is always false after the kind-cache removal
Removing the per-ipnsName kind-cache (plan 11) left `isFileRef` reporting every kind-less `SealedChildRef` as a folder. This broke not only download affordances but the download LOGIC itself (`handleDownload`/`handleBatchDownload` filtered every file out). Classify identity-only refs via the resolved listing (`isFileRefResolved`), not the bare ref.

**Context:** the crypto-carrier refs (`rawChildren`) intentionally lack `.kind`; kind lives only on `ResolvedChild`.
**Source:** 68.2-15-SUMMARY.md

### A partial listing cached at a sequenceNumber pins itself
`resolveListingChildren` cached the result of `resolveChildren` even when a child was dropped on a transient failure. Because the cache is keyed by `{ipnsName, sequenceNumber}` and even `forceResolve` reuses a same-sequence entry, the missing child stayed invisible until a remote write advanced the sequence or the client reloaded. Fix: skip caching when `resolved.length < children.length`.

**Context:** `forceResolve` refreshes the folder's OWN sequence, not its children's cache entry.
**Source:** Greptile PR review (P1), 68.2 PR #589

### The SDK E2E tee-republish suite needs a running tee-worker
`tee-republish.test.ts` fails with `tee_key_state is empty` unless a tee-worker is running and enrolled. The fresh web-e2e stack deliberately excludes the tee-worker, so those 2 tests are infra-gated (identical on main), not a regression — CI runs them with the worker.

**Context:** phase 68.2 touched zero TEE/republish code (empty diff), so the failures are unambiguously environmental.
**Source:** ship SDK E2E gate

### CodeRabbit skips large PRs; Greptile becomes primary
Both the CodeRabbit CLI (timed out) and the PR-level review ("Review skipped") bailed on the 76-commit / 126-file diff. Scoped CLI reviews (`--dir apps/web/src`, `--dir packages/sdk/src`) surfaced the findings; Greptile (no size cap) became the effective PR reviewer.

**Context:** matches the known 150-file cap. Scope big-phase reviews by directory.
**Source:** ship CodeRabbit/Greptile steps

### Terminal-owner zeroization must adopt before the throwing op
In the `descendSharedChild` hop loop, the minted `childReadKey` was adopted into the cleanup-tracked `mintedReadKey` only AFTER `unsealNode` — so a throw there leaked the key. Adopt into the tracked variable BEFORE the operation that may throw.

**Context:** the buffer is locally minted (terminal owner), so zeroing on failure is safe — unlike a caller-owned buffer.
**Source:** CodeRabbit finding, ship fix (218e69345)

## Patterns

### Fresh-container full-suite triage
When a full web-e2e suite shows failures on a long-lived local stack, re-run on a fresh-container stack to separate real regressions from stale-stack/cache flake. This cleanly classified two real 68.2 regressions vs pre-existing 68.1 debt.

**When to use:** any time a large e2e suite fails locally and stack age is a plausible confound.
**Source:** 68.2-UAT.md, gap-closure round 2

### Don't cache partial results
When a per-item resolver degrades gracefully (skips failing items), do NOT cache a partial aggregate keyed by a version clock — a later same-version read will reuse the incomplete set. Skip caching when `resolved.length < input.length`.

**When to use:** any cache over a best-effort fan-out resolve.
**Source:** Greptile P1 fix

### Parallel read-only audits during ship
Verify, Secure, and Validate are independent read-only audits — run them concurrently as background subagents and triage findings together, rather than serially.

**When to use:** the pre-ship gate sequence when the audits don't mutate code.
**Source:** ship-phase execution

### Triage-then-defer with typed todos
Every review finding is triaged: in-scope + low-risk → fix now; pre-existing / out-of-domain / risky → a typed todo under `.planning/todos/pending/` with file refs and rationale, noted in the PR. Keeps a verified-green phase from absorbing risky late changes.

**When to use:** ship-time review triage on any phase already past verification.
**Source:** ship CodeRabbit/Greptile triage

### Grep-gate boundary (promote to lint)
A grep gate enforces the web/SDK runtime boundary cheaply, but is only checked when run. Promote it to an ESLint `no-restricted-imports` (allowing `import type`) or a CI step so reintroductions fail automatically.

**When to use:** any enforced module boundary that currently relies on a manual grep.
**Source:** 68.2-SECURITY.md advisory

## Surprises

### The Regression B root cause was the wrong folder, not stale cache
The natural first hypothesis (`forceResolve` cache staleness) was refuted: adding `forceResolve` to `handleSync` didn't fix the subfolder-upload invisibility because `handleSync` refreshes root, not the open subfolder.

**Impact:** a second fresh-stack run was needed to see that writable-shares 1.2 still failed after the "fix", redirecting to `invalidateOpenFolder`.
**Source:** 68.2-16-SUMMARY.md

### Regression A broke the download logic, not just the button
The kind-cache removal's blast radius reached the actual `handleDownload`/`handleBatchDownload` filters (`selectedItems.filter(isFileRef)` returned empty), so even a forced download was a no-op — wider than the visible affordance bug.

**Impact:** the fix had to thread the resolved listing into the hook's download logic, not just the two presentational components.
**Source:** 68.2-15-SUMMARY.md

### The shared browser needed no change for Regression B
Bob's grantee uploads refresh through the live `folderChildren` projection (`useSharedWriteOps` / `shared-folder-projection`), so only the OWNED browser's `onUploadComplete` needed the fix — confirmed by writable-shares 29/29.

**Impact:** avoided an unnecessary (and riskier) change to the shared write path.
**Source:** 68.2-16-SUMMARY.md, writable-shares.spec.ts

### Two ungated read facades survived a SECURED audit
`resolveNodeIdentity` and `resolveFileMetadata` call `resolvePublishedNode` directly (ungated for anti-rollback), yet the phase verified PASS and SECURED — because the phase's defined gated scope was the listing/navigation chain, and AEAD still protects content integrity on those facades.

**Impact:** captured as a security-tagged hardening todo (gate the non-listing facades) rather than a blocker; the residual gap is staleness, not an integrity/confidentiality hole.
**Source:** Greptile/CodeRabbit PR review, gate-non-listing-read-facades todo
