### Gap-Closure Verification (SC#5 / SDK-READ-03) — Read Directly From Code, Not Trusted From SUMMARY

The prior BLOCKER was: `CipherBoxClient.ensureFolderLoaded` unconditionally short-circuited on any already-loaded `folderTree` entry, so an owner who loaded a shared folder once would never see a grantee's later upload without writing first.

**Independent code confirmation (`packages/sdk/src/client.ts`):**

- `ensureFolderLoaded(targetIpnsName, opts?: { forceResolve?: boolean })` (L1575-1598): when `existing` is found AND `opts?.forceResolve` is true, it now routes to `reresolveFolderInPlace(existing)` (L1581-1582) **instead of** the old verbatim short-circuit. The no-opts path is untouched byte-for-byte (confirmed: write-mutation chokepoints like `requireFolder` still get the cheap cached fast path).
- `reresolveFolderInPlace` (L1606-1616) is a dedup wrapper keyed by `ipnsName` via a `reresolveInFlight: Map<string, Promise<...>>` (L207) — concurrent calls for the same folder share one in-flight promise, registered synchronously before the first `await` (correct dedup mechanics, confirmed by reading the code, not just the docstring claim).
- `doReresolveFolderInPlace` (L1643-1692) genuinely calls `this.resolvePublishedNode(existing.ipnsName)` (a real network resolve, not a cache read), then **fails closed** if `!resolved.signatureVerified` (L1648-1652, throws before any floor mutation), guards `Number.MAX_SAFE_INTEGER` overflow (L1653-1657), and gates through `this.config.rotationHighWater.enforceResolved(...)` (L1658-1663) sourcing `generation` from `existing.nodeGeneration` (the locally-trusted value, never the freshly relay-served envelope's own `generation` — matches the Pitfall 3/D-04 rule enforced everywhere else in the read path). A resolved sequence `<= existing.sequenceNumber` returns `existing` unchanged (L1670-1672, the #489 sequence-as-clock guard) without re-unsealing. On a genuine advance, `FolderState` is updated **in place** (`this.folderTree.set(existing.ipnsName, existing)`, L1687) — single-owner (D-09/SC#3) preserved, no second cache introduced.
- `listFolder(ipnsName, opts?)` (L877-888) threads `opts` into `ensureFolderLoaded` before calling `resolveListingChildren`, so the cache-invalidation clock (`folder.sequenceNumber`) is now genuinely advanced by the network resolve **before** the self-referential comparison runs — the exact self-referential no-op the prior verification identified is eliminated.
