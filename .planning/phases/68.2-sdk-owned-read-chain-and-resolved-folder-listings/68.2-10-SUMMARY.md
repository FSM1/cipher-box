# Phase 68.2 Plan 10: Off-Path Pocket + Pure-Util Cutover Summary

**Rewired the last three off-path web pockets (BYO-pinning settings, auth-bootstrap/vault crypto, device-registry crypto) and the pure-util call sites onto the `@cipherbox/sdk` facade, closing the D-07 full-boundary scope with a new throwaway-client pattern for the pre-login vault-bootstrap chicken-and-egg problem.**

## Performance

- **Duration:** ~45 min
- **Tasks:** 2
- **Files modified:** 12 (10 apps/web files per plan's `files_modified`, plus 2 deviation files: `apps/web/src/lib/sdk-provider.ts` and `packages/sdk/src/index.ts`)

## Accomplishments

- `useAuth.ts`'s vault-bootstrap (new-user mint + existing-user load) and BYO-config load now go through a throwaway `CipherBoxClient` (new `sdk-provider.createBootstrapClient()`) for `bootstrapVaultKeys`/`serializeVault`/`deserializeVault`/`publishEmptyRootNode`/`resolveConfigBlob`/`uploadBytes`/`downloadBytes` -- resolving the chicken-and-egg problem where this code runs BEFORE `rootIpnsName`/`rootFolderKey` (and therefore the real SDK client) exist
- `device-registry.service.ts`'s `initializeOrSyncRegistry`/`loadRegistry` route registry crypto and config-blob resolve/publish/transport through `getSdkClient()` (called only after login, when the real client is guaranteed to exist)
- `vault-settings.service.ts`'s `loadVaultSettings`/`saveVaultSettings` now take an injected `CipherBoxClient` parameter, letting the same functions work with either the bootstrap client (pre-login, from `useAuth.ts`) or the real client (post-login, from `VaultTab.tsx`'s save action)
- `vault-settings.store.ts` and `VaultTab.tsx` import `DEFAULT_VAULT_SETTINGS`/`validateVaultSettings`/`VaultSettings` from a new `@cipherbox/sdk` re-export instead of `@cipherbox/core` directly
- `ConnectionTest.tsx`'s browser-side fallback and `StorageTab.tsx`'s BYO config-blob load/save route through `getSdkClient().testConnection`/`resolveConfigBlob`/`publishConfigBlob`/`uploadBytes`/`downloadBytes` instead of `@cipherbox/sdk-core`/`ipns.service`/`lib/api/ipfs`
- `MoveDialog.tsx`/`useFolderMutations.ts`/`streaming-crypto.service.ts` pure-util imports (`getDepth`/`isDescendantOf`/`calculateSubtreeDepth`/`selectEncryptionMode`) now come from `@cipherbox/sdk` instead of `@cipherbox/sdk-core` (mechanical import-path change)
