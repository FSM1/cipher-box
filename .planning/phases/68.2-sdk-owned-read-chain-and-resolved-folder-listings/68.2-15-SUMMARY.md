## What shipped

Gap-closure round 2, **Regression A** — download affordances AND download
logic were broken because the 68.2-11 kind-cache removal left
`isFileRef(bareSealedChildRef)` permanently returning `false` (folder-safe
default). Every site that classifies an identity-only `SealedChildRef`
therefore treated files as folders.

Root cause was wider than the affordances: `FileBrowser` feeds
`useFileBrowserActions` the raw, kind-less `rawChildren` mirror, so
`handleDownload` (single) and `handleBatchDownload` (batch) filtered every
selected file out — even a forced download was a no-op — on top of the hidden
selection-bar button and context-menu items.

### Fix

- `apps/web/src/utils/fileTypes.ts` — added `isFileRefResolved(ref, resolvedByIpnsName)`: a `ResolvedChild` is read inline; a bare `SealedChildRef` is classified against the SDK-resolved listing keyed by ipnsName (miss stays folder-safe `false`). `isFileRef` kept for sites that already hold a `ResolvedChild`.
- `useFileBrowserActions.ts` — new `resolvedChildren` input + `resolvedByIpnsName` map; both download handlers classify via `isFileRefResolved` (map added to their deps).
- `FileBrowser.tsx` — passes `resolvedChildren={currentFolder?.children ?? []}` into the hook, `SelectionActionBar`, and `ContextMenu`.
- `SelectionActionBar.tsx` — required `resolvedChildren` prop; `fileCount`/download-button gating classify via the map.
- `ContextMenu.tsx` — optional `resolvedChildren` prop; `isFile` (which gates Download/Edit/Preview) classifies via the map (folder-safe when omitted, so Bin/read-only callers are unaffected).
- `SharedFileBrowser.tsx` — swapped `isFileRef`→`isFileRefResolved`, reusing its existing `resolvedByIpnsName` map for the double-click navigate guard + writable context-menu download gate; threads `resolvedChildren` into both `<ContextMenu>` and the `<SelectionActionBar>`.

No SDK change — `ResolvedChild`/`listFolder` already carry `kind` (SDK-READ-02);
purely web-consumer re-wiring. `SharedFolderRow` left untouched (its
`isFileRef(resolved ?? item)` already prefers the resolved kind).
