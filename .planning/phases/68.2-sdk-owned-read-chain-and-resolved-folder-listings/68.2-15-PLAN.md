<objective>
Gap-closure (round 2, Regression A). The 68.2-11 removal of the per-ipnsName
kind-cache left `isFileRef(bareSealedChildRef)` permanently returning `false`
(folder-safe default). Every download-affordance AND download-logic site that
classifies an identity-only `SealedChildRef` (selection/context-menu/download
payloads keyed off `rawChildren`) therefore treats files as folders: the
selection-bar download button is hidden, the context-menu Download/Edit/Preview
items never render, and -- critically -- `handleDownload`/`handleBatchDownload`
filter every selected file out, so even a forced download is a no-op.

Fix: classify identity-only refs against the SDK-resolved `ResolvedChild`
listing (SDK-READ-02, keyed by ipnsName) instead of the absent `.kind`. No SDK
change -- `ResolvedChild`/`listFolder` already carry `kind`; this is purely
re-wiring the web consumers that were fed the raw (kind-less) mirror.

Fixes: `batch-download.spec.ts` (download button visible + batch context-menu
download); download logic actually emits files.
</objective>
