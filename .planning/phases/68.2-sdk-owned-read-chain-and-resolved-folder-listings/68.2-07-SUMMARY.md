# Phase 68.2 Plan 07: Owned File I/O SDK-Facade Cutover Summary

**Upload/download/delete/replace/version-history/detail flows for owned files now route through the SDK's IPFS-transport and metadata-read facade (`client.uploadBytes`/`downloadBytes`/`unpin`/`getFolderMetadata`) instead of `lib/api/ipfs` or web-side `ipns.service`/`kind-cache`, plus a new `client.resolveChildIdentity` facade method (Rule 2) that lets `key-wrapping.ts` stop calling `@cipherbox/core`'s `unsealChildReadKey` directly.**

## Performance

- **Duration:** ~35 min
- **Tasks:** 2 (each committed atomically per the plan)
- **Files modified:** 10 (1 new SDK test file; 9 modified across `apps/web` services/hooks/components and `packages/sdk/src/client.ts`)

## Accomplishments

- `upload.service.ts`/`download.service.ts`/`delete.service.ts` now call `client.uploadBytes`/`downloadBytes`/`unpin` (Plan 03 facade) instead of `lib/api/ipfs`'s `addToIpfs`/`fetchFromIpfs`/`unpinFromIpfs`; upload/download progress callbacks are threaded through verbatim
- `useDropUpload.ts`'s duplicate-file upload path and orphan-CID cleanup now use the already-resolved SDK client (`client.uploadBytes`/`client.unpin`) instead of dynamically importing `lib/api/ipfs`
- `ReplaceFileDialog.tsx` and `VersionHistory.tsx` route their unpin/download-content calls through `client.unpin`/`client.downloadBytes`
- `DetailsDialog.tsx` drops its `resolveIpnsRecord` (`ipns.service`) call and its kind-cache lookup entirely; folder/file kind discrimination is now sourced solely from folderStore membership, and the folder metadata probe routes through `client.getFolderMetadata` (the gated facade) rather than a raw IPNS resolve
- `key-wrapping.ts`'s `resolveChildNodeIdentity` is now a one-line delegate to a new `client.resolveChildIdentity` SDK facade method, which recovers a single child's own readKey + plaintext node identity via the same ROT-07-gated `gatedResolveChild` + `unsealChildReadKey` pattern `folder-listing.ts`'s `resolveChildren` already uses internally -- the web no longer performs the raw IPNS resolve, IPFS fetch, or child-readkey unseal itself
- `ShareDialog.tsx`/`invite.service.ts` (the only current callers of `resolveChildNodeIdentity`, both outside this phase's scope) keep working unmodified through the same exported function signature
