# Phase 68.2 Plan 06: Owned Read-Path Rewire and ResolvedChild Render Repoint Summary

**Relocated the 3 pure version-transform helpers out of file-metadata.service.ts, rewired the owned file-browser's background-sync/409-resync read path onto `client.listFolder`+`client.getFolderMetadata` (the SDK's ROT-07-gated read path), and repointed FileListItem/FileDetails/FolderDetails to render kind/size/modifiedAt from a `ResolvedChild`-shaped value via a dual-prop (identity vs. display) design that avoids breaking the write-path's crypto-identity carriers.**

## Performance

- **Duration:** ~65 min
- **Tasks:** 3
- **Files modified:** 12 (1 created, 11 modified — 6 in the plan's declared scope, 6 companion/adjacent files patched to keep the build green, see Deviations)

## Accomplishments

- `apps/web/src/lib/version-transforms.ts` hosts `shouldCreateVersion`/`computeRestoreVersionUpdate`/`computeDeleteVersionUpdate`, relocated verbatim; `useFileVersions.ts`/`useFileOperations.ts`/`TextEditorDialog.tsx` import from the new module
- `useFileBrowserActions.ts`'s `handleSync` and `folder-helpers.ts`'s `resyncFolder` no longer import `@cipherbox/sdk-core` (`fetchAndDecryptMetadata`) or the web's own `resolveIpnsRecord` — both route through `client.listFolder` (gated resolve + `ResolvedChild[]` listing cache warm) and `client.getFolderMetadata` (cache-hit, raw `SealedChildRef[]` for the store's write-path-facing `children` field)
- `folder-helpers.ts`'s `getDepth` import repointed from `@cipherbox/sdk-core` to the `@cipherbox/sdk` facade re-export (Plan 03)
- `FileListItem.tsx` gained a `resolved: ResolvedChild` prop (kind/size/modifiedAt display), keeping `item: SealedChildRef` as the identity/crypto carrier its callbacks need
- `FileDetails.tsx`/`FolderDetails.tsx` repoint their `item` prop to `ResolvedChild`; `FolderDetails.tsx` gained a dedicated `readKeySealed: string` prop for the one write/crypto-identity field it displays
- `fileTypes.ts`'s `isFileRef` accepts `SealedChildRef | ResolvedChild`, reading `.kind` directly when resolved
- Companion patches to keep the build green (not in this plan's declared file list): `DetailsDialog.tsx` builds a `ResolvedChild` view from its existing `cachedKind` computation and threads `readKeySealed` separately; `FileList.tsx` builds each row's `ResolvedChild` view via a small adapter before rendering `FileListItem`

**2. [Rule 1 - Bug avoidance / Rule 4 boundary] `isFileRef` kept backward-compatible instead of narrowed to `ResolvedChild`-only**
- **Found during:** Task 3
- **Issue:** Task 3's acceptance criteria requires zero `kind-cache`/`useFileSize` grep hits in `fileTypes.ts`. A strict removal (narrowing `isFileRef`'s signature to `ResolvedChild` only) would have been a compile-breaking regression across 6 live production call sites: `useFileBrowserActions.ts`'s own `handleDownload`/`handleBatchDownload` (this plan's own Task 2 file, still `SealedChildRef`-typed by design — see key-decisions), `SelectionActionBar.tsx`, `ContextMenu.tsx`, `SharedFileBrowser.tsx` (none owned by any plan in this phase), and `SharedFolderRow.tsx` (Plan 08's declared scope, not yet executed). Shipping a broken `isFileRef` signature would have silently made every file in the owned AND shared browsers render as a folder (a severe, user-visible regression) until Plans 08/09/11 individually happened to patch every caller.
- **Fix:** Widened `isFileRef` to accept `SealedChildRef | ResolvedChild`, using a `'kind' in item` type guard: the `ResolvedChild` branch reads `.kind` directly (the genuine SDK-READ-02 behavior Task 3 wants); the `SealedChildRef` branch falls back to the kind cache (preserving all 6 currently-working call sites unchanged). This is a deliberate, bounded exception to the plan's literal "zero kind-cache reference in `fileTypes.ts`" wording — the 2 remaining hits (one `import`, one doc comment) are the ONLY way to keep 6+ files across 2 other plans' scope (and files unowned by any plan) working. `FileListItem.tsx`/`FileDetails.tsx`/`FolderDetails.tsx` themselves have ZERO `kind-cache`/`useFileSize` references (confirmed via grep) — only `fileTypes.ts`'s own file has the accepted exception.
- **Files modified:** `apps/web/src/utils/fileTypes.ts`
- **Verification:** `grep -n "kind-cache\|useFileSize"` returns nothing for `FileListItem.tsx`/`FileDetails.tsx`/`FolderDetails.tsx`; typecheck byte-identical to baseline; `pnpm --filter @cipherbox/sdk test` 318/318 passing
- **Committed in:** `9105cbf8f` (Task 3 commit)
