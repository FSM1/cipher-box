## What shipped

Gap-closure round 2, **Regression B** — an upload into a subfolder never
appeared in that subfolder's view.

### Root cause

`UploadZone` targets `folderId={currentFolderId}` (which may be a subfolder),
but `onUploadComplete` only called `actions.handleSync`, which resyncs **root
only** (`rootIpnsName`, folder `'root'`). The currently-open subfolder was
never refreshed, so the just-uploaded child stayed invisible until the 30s
poll's `invalidateOpenFolder` leg happened to fire — longer than the test's
30s wait. The initial hypothesis (SDK cache staleness on root) was wrong: the
refresh was resolving the *wrong folder*.

### Fix

- `FileBrowser.tsx` — `onUploadComplete` now calls the already-exported `invalidateOpenFolder()` (immediate gated re-resolve of the currently-open folder, `{ forceResolve: true }` on both legs) first, then runs `handleSync()` best-effort for the root tree + search index. Covers both UploadZone paths (drop + file-input), which share this handler.
- `useFileBrowserActions.ts` — `handleSync` now forces both `listFolder`/`ensureFolderLoaded` on root (deterministic-freshness consistency with the nav/poll precedent).
- `folder-helpers.ts` — `resyncFolder` (post-409 CAS re-sync) forces both legs.

No SDK change — `forceResolve` (68.2-13) and `invalidateOpenFolder` (68.2-14)
already existed. The **shared** browser needed no change: Bob's uploads refresh
through the live `folderChildren` projection (`useSharedWriteOps` /
`shared-folder-projection`), confirmed by the full writable-shares pass.
