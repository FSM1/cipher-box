## Pattern Assignments

### `packages/sdk/src/folder-listing.ts` (NEW service module) / `client.ts` gated resolve + `listFolder`/`listSharedFolder`

**Analog:** `packages/sdk/src/client.ts` (`reconcileFolderSequence` gate, L1050-1095; `dfsFindFolder`/`resolvePublishedNode`, L800-970)

**Gate pattern to replicate** (source: `packages/sdk/src/client.ts` L1050-1091, existing write-path-only gate):
```typescript
if (this.config.rotationHighWater) {
  // Fail closed BEFORE any floor mutation: an unverified record must never
  // bump a durable floor.
  if (!resolved.signatureVerified) {
    throw new Error(
      `IPNS resolve for ${ipnsName} returned an unverified record -- refusing to gate durable floors on it`
    );
  }
  if (
    resolved.sequenceNumber > BigInt(Number.MAX_SAFE_INTEGER) ||
    expectedSequence > BigInt(Number.MAX_SAFE_INTEGER)
  ) {
    throw new Error(
      `IPNS sequence number for ${ipnsName} exceeds Number.MAX_SAFE_INTEGER -- refusing lossy floor conversion`
    );
  }
  const nodeGeneration = this.folderTree.get(ipnsName)?.nodeGeneration ?? 0;
  await this.config.rotationHighWater.enforceResolved({
    nodeId: ipnsName,
    seq: Number(resolved.sequenceNumber),
    generation: nodeGeneration,
    versionFloor: Number(expectedSequence),
  });
}
```

**Critical divergence (RESEARCH.md Pitfall 3):** the write-path gate above sources `generation` from `this.folderTree.get(ipnsName)?.nodeGeneration` because it reconciles the SAME node. A new READ-path gate resolving a not-yet-cached child inside `dfsFindFolder`'s per-hop loop (client.ts L854-905) MUST instead use `childRef.generation` (the PARENT's `SealedChildRef` mirror) — copy the existing unseal-step's generation-source rule at that call site, do not copy this write-path snippet verbatim.

**Sequencing constraint (RESEARCH.md Pitfall 2 — CRITICAL):** this gate MUST land in `client.ts`'s internal read path (`resolvePublishedNode`/`dfsFindFolder`) and be unit-tested BEFORE `apps/web/src/services/ipns.service.ts` is deleted. `ipns.service.ts` is currently the ONLY working ROT-07 read-side gate in production; deleting it first drops read-side anti-rollback protection entirely.

**Pitfall 1 — `listSharedFolder` cannot wrap `navigateReadChain` as-is:** `navigateReadChain` (`packages/sdk-core/src/share/navigate.ts`) forces `kind: 'file'` at the walk's end and cannot render an intermediate folder. Default approach (research recommendation): hoist the existing web-layer intermediate-folder walk from `apps/web/src/hooks/useSharedNavigationActions.ts` (the `fetchPublishedNode` + `unsealChildReadKey` + `unsealNode` loop, lines 127-136 and 347-467) into `packages/sdk` verbatim, then add the gate to it — do not modify `navigateReadChain` itself (it has existing callers `downloadSharedFile`/`loadSharedFileContent`).

## Shared Patterns

### ROT-07 durable anti-rollback gate (security-critical, applies to ALL new read-path code)
**Source:** `packages/sdk/src/client.ts` L1050-1091 (write-path gate, extend to read path); `packages/sdk/src/state/rotation-high-water.ts` (the seam itself)
**Apply to:** `folder-listing.ts`'s gated resolve, `dfsFindFolder`'s per-hop child gating, `listSharedFolder`'s hoisted walk.
**Rule:** fail closed on `!resolved.signatureVerified` BEFORE any floor mutation; guard `Number.MAX_SAFE_INTEGER` overflow; source `generation` from the PARENT's `SealedChildRef.generation` mirror for not-yet-cached children, never the child's own envelope generation (Pitfall 3).

### SDK event projection (applies to `folder.store.ts` and any future Zustand projection)
**Source:** `apps/web/src/stores/folder.store.ts` L202-308
**Apply to:** any store subscribing to `client.on()`.
**Rule:** preserve sequence-number staleness guards verbatim; the store must never independently resolve — a `folder:updated` event with `ResolvedChild[]` fully determines rendered state (D-01/D-03).

### D-07 grep-gate two-step verification (applies to every rewired file)
**Source:** RESEARCH.md Pitfall 5
**Apply to:** all 9 sdk-core + 20 raw-IPFS/IPNS + 7 core call sites.
**Rule:** never trust a single-line regex against `import type`; use the two-grep pipeline (strip `import type {` lines, then strip fully-inline-typed import blocks) to avoid false positives like `StorageTab.tsx:2`.
