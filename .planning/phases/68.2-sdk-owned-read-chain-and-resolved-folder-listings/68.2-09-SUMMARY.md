# Phase 68.2 Plan 09: SDK-Owned Folder Projection + D-03 Belt-and-Suspenders Freshness Summary

**Collapsed `folder.store.ts` to a pure `ResolvedChild[]` display projection over SDK events (no independent resolve, no kind-cache), wired deterministic nav re-resolve + poll-driven invalidation for D-03 freshness, and brought `apps/web` typecheck from 18 pre-existing errors to zero.**

## Performance

- **Duration:** ~40 min
- **Tasks:** 2 plan tasks + 1 addendum (poll-invalidation behavioral test)
- **Files modified:** 12 modified, 1 created

## Accomplishments

- `folder.store.ts`'s `children` field is now the SDK's resolved `ResolvedChild[]` (kind/size/modifiedAt pre-resolved, 68.2-02) -- the `allKindsCached`/async `resolveKinds()` IIFE is deleted entirely; the `folder:updated`/`folder:loaded` handler is a single straight-line synchronous projection
- The three load-bearing 68.1 staleness guards (empty-over-populated T-68.1-26-01, stale-sequence T-68.1-33-01) are preserved and independently regression-tested
- New `FolderNode.rawChildren?: SealedChildRef[]` field carries the same-session raw write-path/crypto identity mirror the event no longer supplies, populated wherever a call site already fetches it via `ensureFolderLoaded`
- D-03 belt-and-suspenders freshness wired end-to-end: `useFolderNavigation.ts` re-resolves via `client.listFolder` on root nav, already-loaded nav (fire-and-forget background refresh), and cold-load nav; `useSyncPolling.ts` layers poll-driven invalidation of the currently-open folder on the existing 30s poll
- `folder.store`'s previously dead `currentFolderId`/`setCurrentFolder` state is now actually driven by every navigation, making "the currently open folder" a real, queryable concept for the poll leg
- `shared-folder-projection.ts` fixed to re-read raw identity from `client.getSharedFolderState` (the SDK's authoritative `sharedFolderTree`) instead of the now-resolved `sharedFolder:updated` event payload -- this was explicitly flagged as this plan's scope by three prior plan SUMMARYs (06/07/08)
- `apps/web` typecheck brought from 18 pre-existing errors (documented by Plans 06-08 as this plan's ownership) to **zero**
- Added real behavioral coverage (`useSyncPolling.test.ts`, 6 tests) for the poll-invalidation leg, retiring the pending todo that flagged it as grep-only

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] Added `FolderNode.rawChildren?: SealedChildRef[]` and `updateFolderRawChildren`**
- **Found during:** Task 1 (retyping `children` to `ResolvedChild[]`)
- **Issue:** The SDK's `folder:updated`/`folder:loaded` event (Plan 02) no longer carries raw `SealedChildRef[]` at all once `children` becomes the resolved display shape. Several write-path call sites (file version restore/delete, file content update) need `readKeySealed`/`generation`/`versionFloor` to unseal a file's read-chain -- without a raw-identity mirror, those flows would have no way to recover it.
- **Fix:** Added an optional `rawChildren` field to `FolderNode`, populated wherever a call site already fetches `ensureFolderLoaded`'s raw `FolderState.children` (nav, resync, poll, root sync).
- **Files modified:** `apps/web/src/stores/folder.store.ts` and all raw-identity consumers listed above
- **Verification:** `pnpm --filter @cipherbox/web` typecheck 0 errors; `useFileOperations.ts`/`useFileVersions.ts` file-ref lookups now resolve correctly against `rawChildren`
- **Committed in:** `de80bca3a`
