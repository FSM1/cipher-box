<objective>
Gap-closure (round 2, Regression B). After 68.2 moved the read chain into the
SDK, the owned-vault post-upload refresh (`handleSync`, fired by
`UploadZone.onUploadComplete`) called `client.listFolder(rootIpnsName)` /
`ensureFolderLoaded(rootIpnsName)` WITHOUT `{ forceResolve: true }`. The
freshly-published record is still inside the SDK cache's ipnsName+sequence
window, so the refresh returns the pre-upload listing and the just-uploaded file
never appears until an unrelated poll/nav forces a live resolve.

Fix: force a live gated resolve on both legs of every post-mutation refresh --
mirroring the 68.2-14 D-03 deterministic-freshness precedent already applied to
navigation (`refreshFolderListing`) and polling (`useSyncPolling`). Also apply
it to `resyncFolder` (the post-409-CAS re-sync), which is the same
post-mutation-freshness class. No SDK change -- `forceResolve` already exists
(68.2-13).

Fixes: `writable-shares.spec.ts` step 1.2 ("Alice creates a folder with a text
file" -- owner-vault upload becomes visible). Guard: `shared-folder-desync.spec.ts`
must stay 4/4.
</objective>
