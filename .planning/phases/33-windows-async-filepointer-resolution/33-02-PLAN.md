<objective>
Wire the async FilePointer resolution into Windows WinFsp callback entry points and add the read-while-resolving poll behavior. After this plan, Explorer operations no longer stall during background metadata refresh.

Purpose: The shared async infrastructure from plan 33-01 spawns resolution tasks and accepts results via channel, but the WinFsp callbacks must drain those results and handle the case where a user reads a file that is still resolving.

Output: All three Windows callback modules updated with drain calls; read_ops.rs has the polling loop for D-06; operations.rs has the STATUS_DEVICE_NOT_READY helper.
</objective>
