<objective>
Collapse the `ipns_republish_schedule` table to pure scheduling metadata (D-02 / TEE-03). Drop the four duplicated signing-input columns (`encrypted_ipns_key`, `key_epoch`, `latest_cid`, `sequence_number`) from both the TypeORM entity and the live schema via a forward migration, so the canonical `ipns_records` row becomes the sole source of the TEE's signing inputs.

Purpose: Remove the only crypto-bearing duplicate (`encrypted_ipns_key`) and the stale snapshot columns the relay must never sign from again. Keeps churn-y retry/status state off the integrity-authoritative `ipns_records` row (D-02 rationale).
Output: A slimmed entity + a forward TypeORM migration following the Phase-66 greenfield drop pattern.
</objective>
