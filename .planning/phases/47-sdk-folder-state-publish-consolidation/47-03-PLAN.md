<objective>
Add three new methods to `CipherBoxClient` — `replaceFile`, `restoreFileVersion`, `deleteFileVersion` — that own the full publish + folderTree bookkeeping + `folder:updated` emission cycle for file replace and version edits, and DELETE the `reconcileFolderState` band-aid.

Purpose: Today the web hooks (`useFileOperations.updateFile` "6b" block, `useFileVersions` restore/delete) publish folder metadata directly via sdk-core and update only the Zustand store — leaving the SDK `folderTree` stale (the PR #489 recycle-bin TC08 resurrection bug). Routing these through client methods makes the SDK client the single source of truth: each method updates folderTree synchronously after the awaited publish and emits `folder:updated`, which the store projects. Once these exist (and Plan 05 wires the web hooks to them), `reconcileFolderState` is dead by construction — DELETE it now (REQ-1 exit criterion).

Per locked decision 2: methods accept PRE-RESOLVED `fileIpnsPrivateKey` + `currentMetadata`; restore/delete service logic stays in the web tier (web hook resolves keys via getFileIpnsPrivateKey before calling).

Output: three new client methods following the canonical 5-step pattern (deleteItem analog); `reconcileFolderState` removed; new `client-file-ops.test.ts` asserts each emits `folder:updated` with correct children + sequenceNumber; sdk dist rebuilt.
</objective>
