<objective>
Two same-file edits to `packages/sdk/src/share/shared-write.ts`:
1. (REQ-3, sdk tier) Drop the redundant `updatedChildren` from the four shared-write function return shapes — only `publishedChildren` remains.
2. (REQ-4) Make `updateSharedFile` consume `prunedCids` from `updateFileMetadata` and fire-and-forget unpin each one, closing the shared-file storage pin leak.

Purpose: `updatedChildren` is the stale pre-merge set — a foot-gun that resurrects deletes if a caller reads it instead of `publishedChildren` (REQ-3). Separately, `updateSharedFile` today `await`s `updateFileMetadata` and throws the whole return away (bare call), dropping `prunedCids` — every shared-file update that prunes a version leaks pinned storage forever (REQ-4). Both edits live in the same file, so they ship together.

Output: `updatedChildren` removed from all four returns; `updateSharedFile` destructures `{ prunedCids }` and unpins each via `sdkCore.unpinFromIpfs(params.ctx, cid).catch(...)`; new/extended tests assert the unpin loop and its failure tolerance; sdk + web typecheck clean.
</objective>
