<objective>
Update Docker Compose configurations to use Kubo's pebbleds datastore for faster write throughput, then capture post-optimization baselines and document before/after comparison.

Purpose: The pebbleds datastore uses an LSM-tree (PebbleDB) instead of flatfs (one file per block), providing significantly faster write performance under concurrent pin operations. Combined with Plan 01's SDK concurrent pin orchestration, this targets the per-pin latency component of the upload bottleneck.

Output: Updated Docker configs, post-optimization baseline document with before/after comparison table.
</objective>

From research -- pebbleds profile:

- Kubo supports comma-separated profiles at init: `IPFS_PROFILE=server,pebbleds`
- pebbleds uses PebbleDB (LSM-tree) instead of flatfs for block storage
- Requires fresh IPFS repo (cannot convert in-place from flatfs)
- User must recreate Docker volumes after config change
