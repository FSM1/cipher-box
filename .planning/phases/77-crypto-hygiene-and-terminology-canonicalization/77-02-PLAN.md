<objective>
Eliminate the latent key-plaintext leak in the AES helpers: 7 functions across 4 files each allocate a local owned copy of the caller's key (`const keyBuffer = new Uint8Array(key).buffer`) that is fed to `crypto.subtle.importKey` and then never zeroed. Extract a single internal `importAesKey()` helper that owns that copy and zeroes it in a `finally` block, and route all 7 functions through it.

Implements Source todo `2026-06-28-zeroize-local-key-plaintext-copies-in-aes-helpers`. Delivers part of Success Criterion 1 (no owned key/plaintext buffer copy survives on the audited crypto paths). No behavior change — `importKey` consumes the bytes into an opaque `CryptoKey` before the copy is zeroed, so ciphertext/plaintext output is identical.

Purpose: Close the memory-exposure window on every AES key import, using one auditable helper instead of 7 inline copies.
Output: `importAesKey()` helper + all 7 AES functions consuming it + parity/aliasing tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → AES helper | caller passes a raw symmetric key (Uint8Array) it still owns; the helper must borrow, copy internally, and never mutate the caller's buffer |
| helper → Web Crypto | the local key copy crosses into `crypto.subtle.importKey`, which consumes it into an opaque CryptoKey |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-77-02a | Information Disclosure | un-zeroed local key-plaintext copy lingering in heap after importKey (memory-dump exposure) | medium | mitigate | `importAesKey` zeroes its owned `keyView` copy in a `finally` block after importKey consumes the bytes — best-effort per memory.ts convention; reduces exposure window |
| T-77-02b | Tampering | accidental zeroization of the caller-owned key (D-09 violation, prior 48/89 E2E regression class) | high | mitigate | Helper only ever `.fill(0)`s the local copy; a caller-key-unchanged unit assertion guards against zeroing the borrowed argument |
| T-77-02c | Tampering | refactor silently alters encrypt/decrypt output | high | mitigate | Existing aes.test.ts + aes-ctr.test.ts round-trip suites re-run as the no-behavior-change gate |
</threat_model>
