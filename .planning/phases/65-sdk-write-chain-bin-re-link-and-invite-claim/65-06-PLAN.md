<objective>
Build the write-revocation driver `rotateWriteFromNode` (WRITE-02/03/04) — the heaviest new operation in the system (design §5.3: "strictly heavier than read-rotation, not a strict subset"). It performs ADR-0001 (c) full Ed25519 rotation of the write plane for a subtree, leaving the read plane invariant (read/write keys are independent — D-06).

**OQ-2 resolution (documented decision): the cascade is child-first / bottom-up.** Mint new Ed25519 keypairs + k51 names + `writeKey'` for the leaves first, first-publish each at `sequenceNumber 1n`, then re-point each parent's `SealedChildRef.ipnsName` and `writeChildren[].writeKeySealed` to the new child names, cascading UPWARD to the share root. (Read-rotation is root-first for an immediate navigation cut; write-rotation is child-first because parents must point at already-published new child names — design §4.6 interior child-first + §5.3 "cascades parent re-points upward to the share root.")

Per node: generate a new Ed25519 keypair (`generateEd25519Keypair`) → new k51 name (`deriveIpnsName`); mint a new `writeKey'` (`generateRandomBytes(32)`); re-seal the write-body with the new `ipnsPrivateKey` under the new `writeKey'`; first-publish to the new name at `1n` (`createAndPublishIpnsRecord`); fire `teeUnenrollFn(oldIpnsName)` (tombstone-intent: remove from the TEE republish batch — §5.5); re-point the parent. At the share root: re-wrap the new `writeKey'` into each surviving co-writer's `writeDescriptorRef` (`wrapKey` + `writeDescriptorRefPersistFn`) and drop the revoked recipient's grant (WRITE-03). The publish-gate-reject + resolve-410 enforcement is **mock-asserted** here behind the injected seam and cut over live in Phase 66 (D-02 / WRITE-04).

All transport is injected callbacks (`WriteRevocationCallbacks`), extending the Phase-64 `GrantRemintCallbacks` discipline. Read and write keys are independent: this driver mints NO readKey and bumps NO read generation.

Purpose: cryptographically enforceable write revocation. Output: `rotateWriteFromNode` + `WriteRevocationCallbacks`, the barrel export, and a driver unit test asserting per-node new names, child-first cascade, tombstone-intent, and co-writer re-wrap with the revoked recipient dropped.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| revoked writer → old k51 name | the revoked writer's cached key must not publish to the old name after rotation (tombstone-intent here; live publish-gate reject Phase 66) |
| surviving co-writer → new key | only non-revoked recipients receive the re-wrapped new writeKey via writeDescriptorRef |
| driver → relay | tombstone/persist/co-writer transport is injected callbacks; no live apps/api this phase (D-02) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-65-21 | Tampering | revoked writer publishing to old name | critical | mitigate | Full Ed25519 rotation mints a new k51 per node; teeUnenrollFn removes the old name from the republish batch; publish-gate reject + resolve-410 mock-asserted (live Phase 66 — WRITE-04 / §5.5) |
| T-65-22 | Elevation of Privilege | revoked recipient retaining write | high | mitigate | Revoked grant is dropped (not re-wrapped); only non-revoked recipients get wrapKey(newWriteKey') into writeDescriptorRef (WRITE-03) |
| T-65-23 | Tampering | parent pointing at stale child name | high | mitigate | Child-first cascade (OQ-2): parents re-point only after the child's new name is first-published; sealChildWriteKey binds the new child writeKey under the new parent writeKey |
| T-65-24 | Spoofing | first-publish sequence forgery | high | mitigate | New k51 first-publishes embed sequenceNumber 1n (strict gate); subsequent publishes via CAS (project memory ipns-first-publish-embed-seq-1) |

| T-65-26 | Tampering | read plane disturbed by write-revoke | medium | mitigate | Driver mints no readKey and bumps no read generation; read-plane invariance asserted by test (D-06 / ADR 0001) |
