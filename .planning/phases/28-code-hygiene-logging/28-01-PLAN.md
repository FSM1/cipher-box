## Objective

Create a lightweight structured logging wrapper at `apps/web/src/lib/logger.ts` that replaces raw `console.*` calls with level-filtered, transport-hookable, redaction-aware logging. This module is the foundation for all subsequent console replacement work in this phase and the transport hook that Phase 30 will wire observability into.

## Background

The web app currently has 139 `console.*` calls scattered across 29 files with no level filtering, no structured metadata, and no ability to suppress debug noise in production. The logger must feel like a drop-in replacement for `console.*` while adding level filtering via `VITE_LOG_LEVEL`, a `redact()` interceptor for sensitive fields, and a `transports` hook array for Phase 30.

## must_haves

- Logger module exists at `apps/web/src/lib/logger.ts`
- Four log levels: `debug`, `info`, `warn`, `error`
- Level filtering based on `VITE_LOG_LEVEL` env var with fallback to `debug` in dev, `info` in production
- `redact()` function strips `privateKey`, `rootFolderKey`, `folderKey`, `fileKey`, `accessToken` from context objects
- `transports` array hook for Phase 30 integration
- Named export `logger` with methods `debug`, `info`, `warn`, `error`
- Zero external dependencies

### Task 1: Create logger.ts module

<read_first>

- apps/web/src/main.tsx (lines 1-31, to see DEV-only error capture pattern and import.meta.env.DEV usage)

  </read_first>

<action>
Create `apps/web/src/lib/logger.ts` with the following implementation:

1. Define `LogLevel` type as `'debug' | 'info' | 'warn' | 'error'`.

2. Define `LEVEL_PRIORITY` map: `{ debug: 0, info: 1, warn: 2, error: 3 }`.

3. Define `SENSITIVE_KEYS` set: `new Set(['privateKey', 'rootFolderKey', 'folderKey', 'fileKey', 'accessToken'])`.

4. Implement `redact(context: Record<string, unknown>): Record<string, unknown>` function:
   - Shallow-clone the context object
   - For each key in `SENSITIVE_KEYS`, if present in the clone, replace value with `'[REDACTED]'`
   - Return the clone

5. Define `Transport` type: `(level: LogLevel, message: string, context?: Record<string, unknown>) => void`.

6. Determine the current log level:

   ```typescript
   const configuredLevel: LogLevel =
     (import.meta.env.VITE_LOG_LEVEL as LogLevel) || (import.meta.env.DEV ? 'debug' : 'info');
   ```

7. Create the `transports` array: `const transports: Transport[] = [];`

8. Implement internal `log(level: LogLevel, message: string, context?: Record<string, unknown>)` function:
   - If `LEVEL_PRIORITY[level] < LEVEL_PRIORITY[configuredLevel]`, return early
   - If context is provided, run `const safe = redact(context)`; otherwise `const safe = undefined`
   - Call `console[level](message, ...(safe ? [safe] : []))`
   - For each transport in `transports`, call `transport(level, message, safe)`

9. Export the `logger` object:

   ```typescript
   export const logger = {
     debug: (message: string, context?: Record<string, unknown>) => log('debug', message, context),
     info: (message: string, context?: Record<string, unknown>) => log('info', message, context),
     warn: (message: string, context?: Record<string, unknown>) => log('warn', message, context),
     error: (message: string, context?: Record<string, unknown>) => log('error', message, context),
     transports,
   };
   ```

10. Export the `LogLevel` and `Transport` types for consumers.

The module should be approximately 50 lines of code, with no external dependencies.
</action>
