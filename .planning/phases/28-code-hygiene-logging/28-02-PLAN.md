## Objective

Replace all `console.*` calls in the 8 highest-volume files (those with 5+ console calls) with structured `logger.*` calls. These 8 files account for 97 of the 139 total console calls (70%). The mapping is: `console.error` -> `logger.error`, `console.warn` -> `logger.warn`, `console.log` -> `logger.debug`, `console.time`/`console.timeEnd` -> `logger.debug` with duration context.

## Background

Per CONTEXT.md D-06/D-07/D-08: Replace all console calls. The DEV-only global error capture in `main.tsx` (lines 8-31) stays as-is since it intercepts `console.error` at the global level and is gated behind `import.meta.env.DEV`. The biggest offender is `hooks.ts` with 34 calls — Web3Auth debug logging that should be `logger.debug` (suppressed in production).

## must_haves

- All `console.error` calls in listed files replaced with `logger.error`
- All `console.warn` calls in listed files replaced with `logger.warn`
- All `console.log` calls in listed files replaced with `logger.debug`
- All `console.time`/`console.timeEnd` pairs replaced with `logger.debug` using duration context
- Each file imports `{ logger }` from the logger module
- Existing `[Module] message` prefix patterns preserved as part of the message string
- No behavioral changes — same information logged, just through the logger abstraction

## Tasks

### Task 1: Replace console calls in web3auth/hooks.ts (34 calls)

<read_first>

- apps/web/src/lib/web3auth/hooks.ts (full file — 34 console calls, biggest offender)
- apps/web/src/lib/logger.ts (logger API)
  </read_first>

<action>
In `apps/web/src/lib/web3auth/hooks.ts`:

1. Add import at top: `import { logger } from '../logger';`

2. Replace all `console.error(...)` calls with `logger.error(...)`. For calls with error objects like `console.error('[Web3Auth] Error:', error)`, convert to `logger.error('[Web3Auth] Error', { error })` to pass the error as structured context.

3. Replace all `console.warn(...)` calls with `logger.warn(...)`. Same pattern for context.

4. Replace all `console.log(...)` calls with `logger.debug(...)`. These are Web3Auth SDK state transitions that should be suppressed in production. For example:
   - `console.log('[Web3Auth] Core Kit status:', status)` -> `logger.debug('[Web3Auth] Core Kit status', { status })`
   - `console.log('[Web3Auth] Login successful')` -> `logger.debug('[Web3Auth] Login successful')`

5. For any `console.log` that logs sensitive-looking data (SDK state, auth parameters), use the context object pattern so redaction can strip sensitive fields.

6. Keep the line `coreKit: any` as-is in this task — the `as any` cleanup is in plan 28-04.

Total: 34 replacements.
</action>

- `grep -c 'logger\.' apps/web/src/lib/web3auth/hooks.ts` returns at least 30
- `grep -q "from '../logger'" apps/web/src/lib/web3auth/hooks.ts` succeeds
- `pnpm --filter web exec tsc --noEmit` succeeds
  </acceptance_criteria>
