## Accept-Disposition Notes

**T-70.1-SC ("zero new dependencies") — minor rationale inaccuracy, no security gap.**
The `accept` rationale states "zero new deps." The diff actually adds two package
entries, both **devDependencies (test-only)**:

- `packages/sdk-core/package.json` devDependencies: `@noble/secp256k1@^2.2.3` — already
  a trusted workspace dependency (used by `packages/crypto` at the same `^2.2.3`); this
  is a direct-dep promotion for unit-test keypair generation, not a new supply-chain entrant.
- `packages/sdk/package.json` devDependencies: `fake-indexeddb@^6.2.5` — genuinely new to
  the workspace, but a well-known, test-only IndexedDB polyfill (never in the shipped
  runtime or the zero-knowledge data path).

Zero new **production/runtime** dependencies and zero new Rust crates were added
(confirmed against every changed `package.json` dep-section and all `Cargo.toml`). The
security-relevant claim (no new runtime supply-chain surface on shipped code) holds; the
"zero new deps" wording is imprecise. **Non-blocking documentation-accuracy note only.**
