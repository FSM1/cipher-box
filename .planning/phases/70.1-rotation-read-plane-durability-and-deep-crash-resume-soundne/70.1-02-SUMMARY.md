## Decisions Made

- `createRotationHighWater(generationStore, seqStore)` -> `createRotationHighWater(store)` (single combined seam). The PUBLIC `RotationHighWater` interface (`getGenerationFloor`/`bumpGeneration`/`seedFromGrant`/`getSeqFloor`/`bumpSeq`/`enforceResolved`) is unchanged, so `client.ts` and the `RotationHighWater`-shaped mocks in `client-rotation.test.ts`/`folder-listing-gate.test.ts`/`folder-reresolve.test.ts` kept compiling with zero changes — verified by running the full `@cipherbox/sdk` suite (346 passed / 49 skipped, 0 failed).
- Test B (wrapped-key round trip) and Test C (migration-preservation) were placed in a NEW colocated `apps/web/src/services/rotation-state.service.test.ts` rather than `packages/sdk/src/__tests__/rotation-high-water.test.ts` as the plan's `must_haves.artifacts` literally listed. The migration/IndexedDB adapter logic is inherently browser-only `apps/web` code; testing it from `packages/sdk` (a published, browser-agnostic package) would mean the SDK's own test suite reaching into the web app, which is backwards for the monorepo's dependency direction. The plan's own RESEARCH section explicitly anticipated this ambiguity and pre-authorized "introduce coverage here or in a new colocated test file if the fake-indexeddb setup lives elsewhere" (Claude's Discretion). Test A (pure store-seam atomicity, no IndexedDB needed) stayed in `packages/sdk`'s test file as specified.
- `fake-indexeddb@6.2.5` verified before installing (zero runtime deps, Apache-2.0, 52 published versions, maintained by `dumbmatter/fakeIndexedDB`, `npm view` confirmed legitimate) — package-manager installs are excluded from blanket Rule-3 auto-fix, but this was an explicit, pre-authorized plan requirement (the plan's own action text names "the existing fake-indexeddb harness"), not a reactive blocker fix, and the install succeeded cleanly with no substitution.
- `idbPutFloors`/`idbPutWrappedKey` kept as two separate single-purpose write helpers rather than one generic patch function, so each function's contract is explicit: floors are always max-preserved per field inside one readwrite transaction, the wrapped-key ciphertext blob is always overwritten/cleared and never numerically compared.

## Post-Review Correction — IndexedDB adapter hoisted into the SDK for CI coverage

The reviewer flagged that the original Test B/C lived in `apps/web/src/services/rotation-state.service.test.ts`, and **apps/web `*.test.ts` files are NOT run by CI** (web is web-e2e-gated; the CI Test job covers api/crypto/core/sdk-core/sdk/api-client only). So the migration and wrapped-key coverage never executed in CI. The correction:

- **Hoisted** the entire concrete IndexedDB adapter — `openRotationDB`, `foldLegacyStoresIntoCombined` (the `onupgradeneeded` legacy two-store→combined fold), the transactional max-preserving get/put helpers, the SC#3 wrapped-key accessors, the D-08 degradation tracking, and the DB/store-name/version constants — out of `apps/web` into a NEW `packages/sdk/src/state/rotation-idb-store.ts`. It exposes a `createIndexedDbHighWaterStore()` factory returning the `HighWaterStore` `{ get, put }` seam plus `persistWrappedKey`/`getWrappedKey`/`deleteWrappedKey` and an instance-scoped `isRotationStateDegraded()`.
- **Lazy global `indexedDB`**: referenced only inside function bodies (on first open), never at module top-level, so importing the module in Node without a polyfill does not throw. It is exposed as its OWN tsup entry + package `exports` subpath (`@cipherbox/sdk/state/rotation-idb-store`), NOT added to the main `index.ts` barrel, so IndexedDB is never pulled into desktop/node consumers and the adapter stays tree-shakeable.
- **CI-covered tests**: NEW `packages/sdk/src/__tests__/rotation-idb-store.test.ts` (13 tests, `fake-indexeddb`) covers the `onupgradeneeded` fold preserving max floors + deleting the two legacy stores, the max-preserving `put` (a concurrent higher write is never clobbered by a lower one), the wrapped-key persist/get/delete round trip, and D-08 degradation on open failure. This runs under `pnpm --filter @cipherbox/sdk test`, which IS in CI.
- **Thinned** `apps/web/src/services/rotation-state.service.ts` to pure wiring over the SDK factory (re-exports `enforceResolved`/`seedFromGrant`/`persistWrappedKey`/`getWrappedKey`/`deleteWrappedKey`/`isRotationStateDegraded`), moved `fake-indexeddb` from the `apps/web` devDependency to `packages/sdk`, and DELETED the web test (its coverage now lives in the SDK).
- **Zeroization discipline unchanged**: the adapter handles the ECIES-wrapped ciphertext blob only — it never sees, persists, or logs plaintext key bytes (documented in the module header).

Verification: `pnpm --filter @cipherbox/sdk test` green (rotation-idb-store 13/13, rotation-high-water 29/29, full suite 359 passed / 49 skipped, 0 failed); `pnpm --filter @cipherbox/sdk build` emits the subpath `dist/state/rotation-idb-store.{js,mjs,d.ts}`; `pnpm --filter @cipherbox/web exec tsc -b` clean against the fresh dist.
