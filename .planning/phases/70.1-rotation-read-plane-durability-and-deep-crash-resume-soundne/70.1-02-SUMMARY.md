## Decisions Made

- `createRotationHighWater(generationStore, seqStore)` -> `createRotationHighWater(store)` (single combined seam). The PUBLIC `RotationHighWater` interface (`getGenerationFloor`/`bumpGeneration`/`seedFromGrant`/`getSeqFloor`/`bumpSeq`/`enforceResolved`) is unchanged, so `client.ts` and the `RotationHighWater`-shaped mocks in `client-rotation.test.ts`/`folder-listing-gate.test.ts`/`folder-reresolve.test.ts` kept compiling with zero changes — verified by running the full `@cipherbox/sdk` suite (346 passed / 49 skipped, 0 failed).
- Test B (wrapped-key round trip) and Test C (migration-preservation) were placed in a NEW colocated `apps/web/src/services/rotation-state.service.test.ts` rather than `packages/sdk/src/__tests__/rotation-high-water.test.ts` as the plan's `must_haves.artifacts` literally listed. The migration/IndexedDB adapter logic is inherently browser-only `apps/web` code; testing it from `packages/sdk` (a published, browser-agnostic package) would mean the SDK's own test suite reaching into the web app, which is backwards for the monorepo's dependency direction. The plan's own RESEARCH section explicitly anticipated this ambiguity and pre-authorized "introduce coverage here or in a new colocated test file if the fake-indexeddb setup lives elsewhere" (Claude's Discretion). Test A (pure store-seam atomicity, no IndexedDB needed) stayed in `packages/sdk`'s test file as specified.
- `fake-indexeddb@6.2.5` verified before installing (zero runtime deps, Apache-2.0, 52 published versions, maintained by `dumbmatter/fakeIndexedDB`, `npm view` confirmed legitimate) — package-manager installs are excluded from blanket Rule-3 auto-fix, but this was an explicit, pre-authorized plan requirement (the plan's own action text names "the existing fake-indexeddb harness"), not a reactive blocker fix, and the install succeeded cleanly with no substitution.
- `idbPutFloors`/`idbPutWrappedKey` kept as two separate single-purpose write helpers rather than one generic patch function, so each function's contract is explicit: floors are always max-preserved per field inside one readwrite transaction, the wrapped-key ciphertext blob is always overwritten/cleared and never numerically compared.
