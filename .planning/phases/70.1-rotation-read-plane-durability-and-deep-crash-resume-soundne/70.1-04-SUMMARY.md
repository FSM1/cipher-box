# Phase 70.1 Plan 04: Rust rotation-engine structural catch-up (D-12) Summary

**Widened Rust `DirtyFrontierEntry` to carry `parent_ipns_name` + derived read key, made `verify_subtree_clean` recurse the full subtree via an explicit work-stack, and made a missing root surface as `is_dirty: true` instead of an empty converged frontier.**

## Performance

- **Duration:** ~30 min
- **Completed:** 2026-07-08
- **Tasks:** 2 (TDD RED, TDD GREEN)
- **Files modified:** 1 (`crates/sdk/src/rotation/engine.rs`)

## Accomplishments

- `DirtyFrontierEntry` widened from the naive 2-field `{ ipns_name, node_id }` shape to `{ ipns_name, node_id, parent_ipns_name, node_read_key: Zeroizing<[u8;32]>, child_pub_kind: NodeKind, enqueued_generation: u32 }` — the Rust twin of TS's `DirtyFrontierItem`.
- `verify_subtree_clean` recurses the FULL subtree via a new `collect_dirty_frontier` explicit work-stack walk: descends below CLEAN folder edges only, stops below a DIRTY edge (no crypto recovery path for a key possibly lost to an interrupted run).
- New `VerifySubtreeOutcome { is_dirty, frontier }` return shape replaces the bare `Vec<DirtyFrontierEntry>` — a missing root is now `{ is_dirty: true, frontier: [] }`, distinct from a fully-converged `{ is_dirty: false, frontier: [] }`. This fixes a real bug: previously `rotate_read_from_node`'s resume branch checked `frontier.is_empty()` and would mark a job `Complete` when the root was simply gone, silently treating "root missing" as "nothing left to reconcile" (T-70.1-10).
- Extracted `derive_child_read_key`, a shared read-only child-key derivation helper (parent read key → child's pre-rotation read key via `unseal_child_read_key`), out of `enqueue_child` and reused it from `collect_dirty_frontier` — one derivation path for both the BFS walk driver and the new verify walk.
- Deliberately did NOT fix the depth>=2 consumption bug in `rotate_read_from_node`'s resume branch (`root_children.iter().find(...)` silently `continue`s past depth 1) — that is Plan 06's scope; this plan only lands the structural type/recursion prerequisite it depends on.

## Decisions Made

- Implemented the recursive walk as an explicit `Vec`-backed work-stack rather than a literally recursive `async fn`, since Rust cannot size a self-referential `async fn`'s generated state machine without heap-boxing every recursive call (would otherwise require a `futures`/`BoxFuture` dependency not currently in this crate). Traversal order (stack/DFS vs. queue/BFS) is immaterial to correctness here — every reachable node below a clean edge is still visited exactly once, and the plan's acceptance criteria only assert entry membership/parent, not global ordering.
- Chose `VerifySubtreeOutcome { is_dirty, frontier }` (mirroring TS's `{ isDirty, frontier }`) over an alternative sentinel/enum design, since it is the smallest change that lets `rotate_read_from_node`'s one call site branch on the correct boolean while keeping `frontier: Vec<DirtyFrontierEntry>` fully compatible with all downstream code in that function that already iterates/`len()`s `frontier` unchanged.
