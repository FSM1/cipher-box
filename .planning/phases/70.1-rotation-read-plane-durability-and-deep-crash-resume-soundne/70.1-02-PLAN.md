<objective>
Collapse the web durable anti-rollback floor plane from TWO IndexedDB object stores (`generation-high-water`, `seq-high-water`) into ONE combined per-nodeId record written atomically, and fold the SC#3 ECIES wrapped-key checkpoint into that SAME record (SC#4/D-06/D-07). Add the `persistWrappedKey`/`getWrappedKey`/`deleteWrappedKey` accessor functions the client-side keyCheckpoint callbacks (Plan 07) will delegate to.

Grounding (RESEARCH Sharp Question 3, confirmed live):
- `rotation-state.service.ts` today opens ONE IndexedDB DB (`cipherbox-rotation-state`, `:32-33`, `DB_VERSION = 1`) with TWO object stores (`GENERATION_STORE_NAME`/`SEQ_STORE_NAME`, `:34-56`). `idbPut` (`:90-111`) is ALREADY correct max-preserving-within-one-transaction — the fix is a schema consolidation, not new atomicity logic.
- `rotation-high-water.ts` `enforceResolved` (`:182`, and the `bumpFloor(generationStore)` THEN `bumpFloor(seqStore)` sequence its own doc calls out at `:35-47` as a "DOC-ONLY residual") does two sequential cross-store bumps — D-06 collapses these into one combined-record write.
- D-07 (resolved): the wrapped-key checkpoint lives in the per-nodeId high-water plane (this plane), NOT the per-rootNodeId job-checkpoint plane.

Purpose: one coherent durable-write machinery underpins BOTH the anti-rollback floor (SC#4) and the ECIES key checkpoint (SC#3) on the web/TS side; a partial-failure divergence window becomes structurally impossible.
Output: a single combined object store + migration + wrapped-key accessors, gated by atomicity + migration-preservation unit tests. Implements D-06, D-07 (and the TS half of the SC#3 durable plane).
