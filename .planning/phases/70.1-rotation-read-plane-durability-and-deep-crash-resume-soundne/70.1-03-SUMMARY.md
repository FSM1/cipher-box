# Phase 70.1 Plan 03: Combined Fail-Closed Rotation Floor Store Summary

**Collapsed the Rust rotation high-water floor into ONE combined-per-node JSON sidecar record with a fail-closed `put`, replacing the swallow-on-write-failure bug and the two-independent-files divergence window.**

## Performance

- **Duration:** ~45 min
- **Completed:** 2026-07-08
- **Tasks:** 3
- **Files modified:** 7 (floor_store.rs, rotation/high_water.rs, adapter.rs, lib.rs, listing.rs, emit.rs, crates/fuse/src/fs.rs)

## Accomplishments

- `CombinedFloorRecord { generation, seq, wrapped_key_checkpoint }` now persists in ONE sidecar file (`rotation-high-water.json`) instead of two independent files (`rotation-high-water-generation.json` / `rotation-high-water-seq.json`) — `for_generation`/`for_seq` are now both views (tagged by an internal `FloorField` enum) onto the same combined record (D-06).
- `HighWaterStore::put` now returns `Result<(), RotationError>`; a durable write failure — including the "refuse to overwrite a corrupt sidecar" path — surfaces as `RotationError::PersistFailed`, never a log-and-return-Ok swallow. `bump_floor`/`bump_generation`/`bump_seq`/`seed_from_grant`/`enforce_resolved` all propagate it via `?` (D-08).
- A device upgrading from the old two-file shape has both legacy files folded forward into the combined record on first read, so neither floor resets to zero (Pitfall 4).
- `JsonSidecarFloorStore::persist_wrapped_key`/`get_wrapped_key`/`delete_wrapped_key` added on the same combined record, fail-closed on persist — the concrete durable target the FUSE `RotationDeps` adapter (Plan 09) will delegate to (D-07 Rust half).
- Consumer sweep across the plan's declared 9-file blast radius: 5 files needed real edits (MemStore test fixtures + call sites in `listing.rs`, `emit.rs`, `crates/fuse/src/fs.rs`, plus `adapter.rs`/`lib.rs` doc/export updates); `content_ops.rs`, `inode.rs`, `events.rs`, `replay.rs` needed none (confirmed via a clean `cargo check`).

## Decisions Made

- `for_generation`/`for_seq` share one physical file (tagged by `FloorField`), each keeping its own `Arc<Mutex<()>>` — safe because `RotationHighWater::bump_lock` already serializes every real mutating call path, and `write_map_atomic_blocking`'s rename is independently atomic against unsynchronized reads.
- Extended D-08 to the "refuse to write over a corrupt sidecar" path too (previously log-and-Ok, now `Err`) since a blind overwrite there is exactly as dangerous as a genuine I/O failure.
- `get_wrapped_key` returns `None` on a corrupt/absent sidecar (not a fail-closed sentinel) — the generation/seq floor gate already fails closed and blocks any resolve on a corrupt device before a wrapped-key checkpoint would be consulted.
- `content_ops.rs`/`inode.rs`/`events.rs`/`replay.rs` needed no edits — verified via a clean `cargo check -p cipherbox-fuse --features fuse --tests` rather than editing speculatively.
