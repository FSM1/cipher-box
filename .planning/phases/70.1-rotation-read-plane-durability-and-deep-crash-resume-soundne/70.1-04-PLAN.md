<objective>
Land the Rust rotation-engine STRUCTURAL catch-up (D-12) that must ship BEFORE the consumption fix (Plan 06) can compile meaningfully. The Rust twin (`crates/sdk/src/rotation/engine.rs`) is structurally naiver than the TS engine even before this phase.

Grounding (RESEARCH Sharp Question 6.1/6.2, confirmed live):
- `DirtyFrontierEntry` is the NAIVE 2-field shape (`:782`): `{ ipns_name, node_id }` — no `parent_ipns_name`, no key. It cannot express a depth>=2 dirty edge's parent — widen it FIRST.
- `verify_subtree_clean` (`:806-853`) is depth-1-only and NON-recursive: `for child_ref in node_children(&root_node)` resolves immediate children only (`:838-850`) and never descends into a clean folder child. Port the TS `collectDirtyFrontier` (`engine.ts:648-704`) recursion CONTRACT (recurse below clean edges, stop below dirty), NOT a line-for-line port (different return types).
- Missing-root-treated-as-clean (`:813-815`): `let Some(root_resolved) = ... else { return Ok(frontier); }` returns an empty ("converged") frontier when root has no record. The TS engine returns `{ isDirty: true, frontier: [] }` for a missing root — Rust needs a distinct `RootMissing`/`is_dirty` signal since an empty `Vec` conflates "clean" and "root gone." The resume-branch re-fetch of root (`:961-965`) already errors on missing root — make the two consistent.

Purpose: without a `parent_ipns_name`-carrying frontier and a recursive/missing-root-aware verify, the Plan 06 SC#1/SC#2 consumption fix has no valid depth>=2 frontier to consume.
Output: widened frontier type + recursive verify + missing-root-dirty, gated by new `FakeDeps` tests. Implements D-12 (part of SC#7).
</objective>
