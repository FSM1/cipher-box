<objective>
Fix the two depth-1-only CONSUMPTION paths in the TypeScript rotation engine so a mid-walk crash on a depth>=2 tree resumes correctly (SC#1/SC#2). The dirty-frontier COLLECTION is already depth-aware (Phase 70 shipped `collectDirtyFrontier` recursion); only the two consumption paths are buggy.

- **SC#1 (Bug A, dirty-resume branch `engine.ts:1401-1442`):** the branch ignores `frontierItem.parentIpnsName` and does `rootNode.children.find(...)` (`:1403-1405`), only finding depth-1 children. For depth>=2 it hits the fail-closed branch at `:1406-1412`, decrementing the ROOT's `pendingChildCount` for a node that is not root's child, then drops the item. Fix: build/reuse a real `ParentTrackingState` per DISTINCT `parentIpnsName` in the frontier (generalize the root-only seed at `:1382-1399`), stop attributing decrements to the root.
- **SC#2 (Bug B, normal-branch ordering `:1523-1524`, `:1559`, `:1568`):** root's children are enqueued first then all `preRotationDirtyFrontier` items are appended regardless of depth, so a deep dirty node can dequeue before its parent's `parentTracking` entry exists; the `if (parentState)` guard (`:1569`) silently skips re-seal+decrement, and the later `if (!result.skipped)` guard (`:1559`) drops the decrement a second time on the idempotency hit — parent never republishes. Fix: guarantee a parent's `parentTracking` entry exists before its dirty child is dequeued (depth-ordered enqueue or lazy placeholder creation via the same resolve+unseal primitive Bug A needs).

Purpose: Phase 70's soundness claim is proven only for depth-1/childless-root; this makes it sound for multi-level trees — the availability/durability core of the phase.
Output: A corrected `engine.ts` consumption path + a shared "resolve arbitrary parent → ParentTrackingState" helper, gated by new depth-2/3 dirty-resume unit tests.

This plan implements SC#1/SC#2 (no D-NN decisions — SC#1/SC#2 are the structural, no-discretion items per CONTEXT.md; RESEARCH Sharp Question 1 is the authoritative trace).
</objective>
