# Plan 38-04: Delete deprecated services and clean up barrel exports

<objective>
Delete `folder.service.ts` (1,059 lines) and `bin.service.ts` (971 lines), and remove their exports from the barrel file. This is the final cleanup after all callers have been migrated in plans 01 and 02.
</objective>

<must_haves>

- `folder.service.ts` is deleted (file does not exist)
- `bin.service.ts` is deleted (file does not exist)
- `services/index.ts` does not export `folder.service`
- No file in `apps/web/src/` imports from either deleted service
- `pnpm typecheck` passes
- `pnpm build` for the web app succeeds
  </must_haves>

## Tasks

<task id="38-04-01">
<title>Verify no remaining imports and delete service files</title>

<read_first>

- apps/web/src/services/index.ts (barrel file to clean up)
- apps/web/src/services/folder.service.ts (file to delete — confirm no remaining callers)
- apps/web/src/services/bin.service.ts (file to delete — confirm no remaining callers)
  </read_first>

<action>
1. **Pre-flight check: verify zero remaining imports.** Run:
   ```bash
   grep -r "from.*['\"].*folder\.service" apps/web/src/ --include="*.ts" --include="*.tsx" | grep -v "folder.service.ts" | grep -v "node_modules"
   grep -r "from.*['\"].*bin\.service" apps/web/src/ --include="*.ts" --include="*.tsx" | grep -v "bin.service.ts" | grep -v "node_modules"
   ```
   If either returns results, STOP — there are still callers that need migration first (go back to plans 01/02).

2. **Clean up barrel file** — Edit `apps/web/src/services/index.ts`:
   - Remove the line: `export * from './folder.service';`
   - Do NOT remove other exports (delete.service, download.service, file-crypto.service, file-metadata.service, streaming-crypto.service, ipns.service, upload.service, search-index.service remain).
   - Note: `bin.service` is NOT in the barrel file (it was always imported directly), so no barrel change needed for it.

3. **Delete the deprecated service files:**

   ```bash
   rm apps/web/src/services/folder.service.ts
   rm apps/web/src/services/bin.service.ts
   ```

4. **Verify nothing breaks:**

   ```bash
   pnpm typecheck
   ```

   If typecheck fails, some file still references the deleted services. Fix the remaining import before proceeding.

5. **Also check for indirect references** via the barrel export. Some files might import from `../services` (the barrel) and use folder.service exports. Run:
   ```bash
   grep -r "from.*services['\"]" apps/web/src/ --include="*.ts" --include="*.tsx" | grep -v "node_modules" | grep -v "__tests__"
   ```
   Review the output — callers using barrel imports like `import { fetchAndDecryptMetadata } from '../services'` will break after removing the re-export. These must be updated to import from `@cipherbox/sdk-core` directly.
   </action>

<acceptance_criteria>

- `test ! -f apps/web/src/services/folder.service.ts && echo "DELETED" || echo "STILL EXISTS"` outputs "DELETED"
- `test ! -f apps/web/src/services/bin.service.ts && echo "DELETED" || echo "STILL EXISTS"` outputs "DELETED"
- `grep "folder\.service" apps/web/src/services/index.ts` returns zero matches
- `grep -r "folder\.service\|bin\.service" apps/web/src/ --include="*.ts" --include="*.tsx"` returns zero matches (excluding node_modules)
- `pnpm typecheck` exits 0
  </acceptance_criteria>
  </task>
