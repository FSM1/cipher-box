**Remove these old actions entirely:** `startUpload`, `setEncrypting`, `setUploading`, `fileComplete`, `setRegistering`, `setSuccess`, `setError`, `cancel`.

**Action implementations:**

- `addFile(id, filename, targetFolderId, file)`: Creates a new `PerFileUpload` entry in the `files` Map with `status: 'encrypting'`, `progress: 0`, `error: null`, `cancelSource: axios.CancelToken.source()`, `file: file`.

- `updateFileProgress(id, progress)`: Updates the file's progress value and sets status to `'uploading'` if not already. Uses `new Map(state.files)` spread to trigger re-render.

- `setFileStatus(id, status, error?)`: Updates a file's status and optional error string. For `'complete'` status, sets progress to 100.

- `setFileComplete(id)`: Sets status to `'complete'`, progress to 100. Does NOT remove the file -- Plan 02's UI component handles the 1000ms green flash timer before calling removeFile.

- `removeFile(id)`: Deletes the file entry from the Map. Used after cancel (immediate) or after completion animation (delayed by UI).

- `cancelFile(id)`: Calls `file.cancelSource?.cancel('Upload cancelled by user')`, then sets status to `'cancelled'`. Does NOT remove from Map -- the UI layer calls removeFile on cancelled status per D-08 (immediate removal).

- `retryFile(id)`: Resets the file's status to `'encrypting'`, progress to 0, error to null, creates a new `cancelSource`. The actual re-upload is triggered from the UI component (Plan 02).

- `reset()`: Cancels all active uploads' cancel sources, then replaces `files` with a new empty Map and clears `pendingReplacements`.

**Keep `PendingReplacement` type and its actions exactly as-is.** The `setPendingReplacements` and `clearPendingReplacements` actions remain unchanged.

**IMPORTANT:** Export `PerFileUpload` type so the UploadListItem component (Plan 02) can import it.

Rewrite the hook to derive batch-equivalent fields from the per-file `files` Map:

```typescript
export function useFileUpload() {
  const files = useUploadStore((s) => s.files);
  const reset = useUploadStore((s) => s.reset);

  const { usedBytes, limitBytes, remainingBytes, canUpload, fetchQuota } = useQuotaStore();
  const { vaultKeypair } = useAuthStore();

  // Derive batch-level status from per-file Map
  const fileEntries = Array.from(files.values());
  const hasActiveUpload = fileEntries.some(
    (f) => f.status === 'encrypting' || f.status === 'uploading'
  );
  const hasError = fileEntries.some((f) => f.status === 'error');
  const activeFile = fileEntries.find((f) => f.status === 'encrypting' || f.status === 'uploading');

  const upload = useCallback(
    async (filesToUpload: File[]): Promise<UploadedFile[]> => {
      if (!vaultKeypair) {
        throw new Error('No keypair available - please log in again');
      }
      await fetchQuota();
      return uploadFiles(filesToUpload, vaultKeypair.publicKey);
    },
    [vaultKeypair, fetchQuota]
  );

  return {
    // State (derived from per-file Map)
    status: hasError ? 'error' : hasActiveUpload ? 'uploading' : 'idle',
    progress: activeFile?.progress ?? 0,
    currentFile: activeFile?.filename ?? null,
    totalFiles: fileEntries.length,
    completedFiles: fileEntries.filter((f) => f.status === 'complete').length,
    error: fileEntries.find((f) => f.error)?.error ?? null,
    isUploading: hasActiveUpload,

    // Quota
    usedBytes,
    limitBytes,
    remainingBytes,
    canUpload,

    // Actions
    upload,
    cancel: () => {
      // Cancel all active uploads
      for (const f of files.values()) {
        if (f.status === 'encrypting' || f.status === 'uploading') {
          useUploadStore.getState().cancelFile(f.id);
        }
      }
    },
    reset,
  };
}
```

This preserves the hook's return type signature so any future consumers would still work. The `cancel` function now cancels all active per-file uploads.
