## Interaction Contract

### Upload Row States

Each uploading file renders as an `UploadListItem` within the file list. The row occupies the same grid layout as `FileListItem` (3-column: name, size, date).

| State          | Visual Description                                                                                                                                                                                                                                                                      |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Encrypting** | Row icon: `[^]` (up-arrow glyph) in `var(--color-green-dim)`. Filename displayed. Size column: `--`. Date column: `--`. Thin 3px progress bar below the filename, indeterminate pulsing animation using `var(--color-green-primary)` at 40% opacity. Cancel button [x] in actions area. |
| **Uploading**  | Row icon: `[^]` in `var(--color-green-primary)`. Progress bar fill advances 0-100% in `var(--color-green-primary)`. Cancel button [x] visible. No percentage text (D-03, D-04).                                                                                                         |
| **Complete**   | Progress bar fills to 100% and turns `var(--color-green-primary)` at full opacity for 1000ms (D-05). After 1000ms, row transitions to a normal `FileListItem` with actual size/date data. Transition uses `opacity` crossfade over 200ms (D-06).                                        |
| **Error**      | Progress bar fill turns `var(--color-error)`. Row icon changes to `[!]` in `var(--color-error)`. Retry button and dismiss button appear. Row persists until user acts (D-09, D-10).                                                                                                     |
| **Cancelled**  | Row removed immediately from file list with no animation (D-08).                                                                                                                                                                                                                        |

### Progress Bar Specification

| Property            | Value                                                            |
| ------------------- | ---------------------------------------------------------------- |
| Container height    | 3px (inherited from existing `.upload-item-progress-bar`)        |
| Container color     | `var(--color-border-dim)` (`#003322`)                            |
| Fill color (active) | `var(--color-green-primary)` (`#00D084`)                         |
| Fill color (error)  | `var(--color-error)` (`#EF4444`)                                 |
| Fill transition     | `width 0.2s ease`                                                |
| Position            | Directly below the filename text, spanning the name column width |
| Border radius       | 0 (terminal aesthetic)                                           |

### Encrypting Pulse Animation

```css
@keyframes upload-inline-pulse {
  0%,
  100% {
    opacity: 1;
  }
  50% {
    opacity: 0.4;
  }
}
```

Applied to progress bar fill during encrypting state. Duration: 1.5s, timing: ease-in-out, iteration: infinite.

### Completion Flash + Swap

1. Progress bar reaches 100% (fill width: 100%).
2. Hold green fill for 1000ms.
3. Crossfade: `UploadListItem` opacity transitions from 1 to 0 over 200ms while the real `FileListItem` fades in from 0 to 1 over 200ms.
4. After swap, the upload entry is removed from the upload store.

### Button Specification

| Button  | Label | Style                                                                                                                                                         | Position                                        |
| ------- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| Cancel  | `[x]` | `var(--font-family-mono)`, `var(--font-size-xs)` (10px), `var(--color-text-secondary)`, transparent background, no border, hover: `var(--color-text-primary)` | Right side of row, overlapping date column area |
| Retry   | `[R]` | Same as cancel but `var(--color-green-primary)` text, hover: `var(--glow-green)`                                                                              | Right side of row (error state)                 |
| Dismiss | `[x]` | Same as cancel styling                                                                                                                                        | Right side of row, after retry (error state)    |

All buttons require `aria-label` with action context (e.g., "Cancel upload of photo.jpg", "Retry upload of photo.jpg", "Dismiss failed upload of photo.jpg").

### Keyboard Accessibility

- Cancel/retry/dismiss buttons: focusable via Tab, activated by Enter or Space.
- Upload rows are not selectable (no checkbox), not draggable, not navigable by double-click.
- Upload rows do not participate in Shift+click range selection.
- Focus-visible style: `outline: 1px solid var(--color-green-primary); outline-offset: 1px` (existing project pattern).

### Reduced Motion

```css
@media (prefers-reduced-motion: reduce) {
  .upload-inline-progress-fill {
    animation: none;
    transition: none;
  }
}
```

## Sorting Integration

Upload-in-progress entries are merged into the file list sorted alphabetically alongside real files (D-01, D-02). Sorting logic:

1. Folders first (existing behavior).
2. Upload entries sorted as files (they are files being uploaded).
3. Within files, alphabetical sort by name (case-insensitive, existing `localeCompare` pattern).
4. Upload entries use a synthetic `FolderChild`-compatible shape with `type: 'file'` and a unique temporary ID (e.g., `upload-{filename}-{timestamp}`).

## Upload Store Shape Changes

The existing `useUploadStore` tracks a single `currentFile` and batch-level progress. For inline per-file rows, the store needs per-file tracking. Claude's discretion area (from CONTEXT.md).

**Recommended store extension:**

Add a `files` map alongside existing fields:

```typescript
type PerFileUpload = {
  id: string; // upload-{filename}-{timestamp}
  filename: string;
  status: 'encrypting' | 'uploading' | 'complete' | 'error' | 'cancelled';
  progress: number; // 0-100
  error: string | null;
};

// New field on UploadState:
files: Map<string, PerFileUpload>;
```

Actions to add: `addFile`, `updateFileProgress`, `setFileStatus`, `removeFile`.
Actions to keep: `cancel` (per-file via file ID), `reset` (clears all).
Actions to remove: `setEncrypting`, `setUploading` (replaced by per-file equivalents).

The batch-level `progress`, `totalFiles`, `completedFiles` fields can remain for backwards compatibility or be derived from the `files` map.
