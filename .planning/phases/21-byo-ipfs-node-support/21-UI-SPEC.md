## Interaction Contracts

### Tab Navigation

- **Pattern:** Extend existing `SettingsPage` tab navigation. Add `'storage'` to `TAB_IDS` array and `SettingsTabId` union type.
- **Tabs render order:** `LINKED METHODS | SECURITY | STORAGE`
- **Keyboard:** ArrowLeft/ArrowRight cycles between tabs, Home/End jump to first/last tab. Already implemented in `handleTabKeyDown`.
- **ARIA:** `role="tab"`, `aria-selected`, `aria-controls`, `tabIndex` roving pattern. New tab: `id="tab-storage"`, panel: `id="panel-storage"`, `aria-labelledby="tab-storage"`.

### Pinning Mode Radio Selector

- **Pattern:** Standard `<fieldset>` with `role="radiogroup"` and native `<input type="radio">` elements.
- **Visual:** Each radio option is a row. Selected option: green text (`--color-text-primary`), green radio indicator. Unselected: dim text (`--color-text-secondary`).
- **Hint text:** Below each radio label, smaller dim text (`--font-size-xs`, `--color-text-dim`).
- **Behavior:** Selecting "cipherbox only" hides the provider config section. Selecting "external only" or "dual-pin" reveals the provider config section with a CSS transition (`max-height` or conditional render).
- **ARIA:** `aria-describedby` linking each radio to its hint text.

### Provider Configuration Fields

- **Endpoint URL:** `<input type="url">` with existing input styling (transparent bg, dim border, green border on focus, glow on focus). Matches `.email-login-input` pattern.
- **Auth Token:** `<input type="password">` with same styling. Show/hide toggle not needed (terminal aesthetic keeps it minimal).
- **Change indicator:** Modified fields show `*` prefix on their label (e.g., `*endpoint url`). Labels use `--color-warning` when modified.
- **Validation:** Endpoint must be a valid URL (HTML5 `type="url"` validation). Auth token is optional for Kubo (some nodes have no auth).

### Connection Test Button and Result

- **Button:** `[--test connection]` -- follows existing terminal button pattern (text in brackets with `--` prefix, monospace, border on hover).
- **Loading state:** Button text changes to `[--testing...]`, a 14px spinner appears inline (reuse existing `mfa-spin` keyframe animation). Button is disabled during test.
- **Result display:** Appears below the button in a `<div>` with monospace font.
  - **Success:** Green text, format: `> connected (420ms) // detected: kubo rpc v0.34.0`. Uses `--color-text-primary`.
  - **Failure:** Red text, format: `> failed: {error message}`. Uses `--color-error`.
  - **CORS failure:** Red text with error message, followed by a `<pre>` block with configuration instructions. `<pre>` styled with `--color-border-dim` border, `--spacing-sm` padding, `--font-size-xs` font size.
- **Timeout:** 10 seconds via `AbortSignal.timeout(10_000)`.
- **Re-test:** Result clears when endpoint or auth token changes. User can click test again at any time.

### Save/Discard Pattern

- **Dirty tracking:** `isDirty` state tracks whether any field differs from the saved/initial value.
- **Save button:** `[--save]` -- green fill background (`--color-green-primary`), black text. Disabled (opacity 0.3) when: (a) not dirty, or (b) mode requires external config but connection test has not passed.
- **Discard button:** `[--discard]` -- ghost button, dim text (`--color-text-dim`), dim border. Resets all fields to saved values, clears dirty state and test result.
- **Buttons appear only when dirty** -- conditionally rendered below the form.
- **Save action:** Encrypts BYO config into vault metadata blob and publishes to IPFS. Shows brief loading state on button.
- **Block save until test passes:** When mode is `external` or `dual` and no successful connection test exists, save button shows `cursor: not-allowed` and `opacity: 0.3`.

### Advisory Quota Display

- **Location:** Existing `StorageQuota` component in sidebar.
- **Advisory badge:** When user's pinning mode is `external` or `dual`, display `ADVISORY` badge next to the quota text. Badge styled: `--font-size-xs`, `--color-warning`, `text-transform: uppercase`, `letter-spacing: 0.1em`, border `1px solid --color-warning`, padding `4px 8px`.
- **Tooltip/hint:** Below quota bar, dim text: `storage is managed by your node. this total is approximate.`
- **Enforced vs advisory:** No visual change to the quota bar itself -- same green fill. Only the badge and hint text differ.

### Migration Progress

- **Location:** Bottom of STORAGE tab panel, shown only when an active migration exists.
- **Progress bar:** Full-width bar matching existing `storage-quota-bar` pattern (6px height, `--color-border-dim` background, `--color-green-primary` fill). Width = `(migratedCids / totalCids) * 100%`.
- **Progress text:** Below bar: `migrating: {migrated}/{total} pins` in `--font-size-xs`, `--color-text-secondary`.
- **Failed count:** If `failedCids > 0`, show `{failed} pins failed` in `--color-error` on a new line.
- **Pause button:** `[--pause migration]` -- ghost button. Changes to `[--resume migration]` when paused.
- **Cancel button:** `[--cancel migration]` -- ghost button with dim text. On click, shows inline confirmation (same pattern as recovery phrase regeneration confirmation).
- **Complete state:** Progress bar at 100%, text changes to `> migration complete. {total} pins transferred.` in green.
- **Polling:** Migration status polled every 5 seconds from API while migration is active.

### Notification Toast for Dual-Pin Failures

- **Pattern:** Reuse existing `NotificationToast` component.
- **Content:** `mirror to {provider} failed -- will retry`
- **Style:** Non-blocking, auto-dismiss after 5 seconds. Warning color (`--color-warning`).
- **Frequency:** Deduplicated -- only one toast per upload, not per failed pin attempt.

## State Interactions

### STORAGE Tab State Machine

```
idle (cipherbox mode) ──[select external/dual]──> configuring
configuring ──[test connection]──> testing
testing ──[success]──> test-passed
testing ──[failure]──> test-failed
test-failed ──[edit fields]──> configuring
test-passed ──[save]──> saving
test-passed ──[edit fields]──> configuring (clears test result)
saving ──[success]──> saved
saving ──[failure]──> save-error
saved ──[edit fields]──> configuring
save-error ──[retry save]──> saving
any state ──[discard]──> idle (revert to saved config)
```

### Migration State Machine

```
no-migration ──[switch provider with existing pins]──> migration-prompt
migration-prompt ──[start migration]──> migrating
migrating ──[pause]──> paused
paused ──[resume]──> migrating
migrating ──[cancel]──> cancel-confirm
cancel-confirm ──[confirm cancel]──> no-migration
cancel-confirm ──[dismiss]──> migrating
migrating ──[complete]──> migration-complete
migrating ──[auth failure]──> migration-paused-auth
migration-paused-auth ──[update token + resume]──> migrating
```

## Accessibility Requirements

- **Pinning mode radio group:** `<fieldset>` with `<legend>` (visually hidden via `.sr-only` if needed). Each `<input type="radio">` has associated `<label>`. Hint text linked via `aria-describedby`.
- **Connection test result:** `role="status"` and `aria-live="polite"` on the result container so screen readers announce the result.
- **Progress bar:** `role="progressbar"` with `aria-valuenow`, `aria-valuemin="0"`, `aria-valuemax="{total}"`, `aria-label="Pin migration progress"`. No `tabIndex` (read-only).
- **Save button disabled state:** `aria-disabled="true"` when connection test hasn't passed (in addition to `disabled` attribute).
- **Tab keyboard handling:** Already implemented via `handleTabKeyDown` -- ArrowLeft/Right, Home/End.
- **Focus management:** When switching to STORAGE tab, focus moves to the tab panel content.
- **CORS instructions code block:** `<pre>` with `aria-label="CORS configuration commands"`.

## Responsive Behavior

- **Breakpoint:** Follow existing responsive pattern from `apps/web/src/styles/responsive.css`.

- **Desktop (>=768px):** No width constraint on STORAGE tab content -- it fills the settings panel width (matches existing LINKED METHODS and SECURITY tab behavior).
- **Progress bar:** Full width within the settings section at all breakpoints.
