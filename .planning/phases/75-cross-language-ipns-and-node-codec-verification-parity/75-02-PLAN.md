Bind ValidityType == 0 (EOL) before treating the IPNS Validity as an expiry timestamp on the Rust side, and eliminate the classifier drift that made todo #9 latent by deleting the hand-duplicated binding logic in the vector test in favor of the real bind_verified helper.

Output: A Rust verifier that rejects the 4 new fixture cases identically to TS, with no duplicated binding logic.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| IPNS relay → client verifier | Signed CBOR record bytes are relayed by the (zero-knowledge) API; bind_verified is the client-side chokepoint that decides accept/reject |
| production verifier ↔ test classifier | classify_vector must apply the exact same binding as bind_verified or the KAT gives false assurance |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-75-03 | Tampering | Validity misread as EOL when ValidityType != 0 | high | mitigate | bind_verified fails closed unless ValidityType == 0 before treating Validity as expiry; decode_ipns_cbor_validity surfaces the value with duplicate-key rejection |
| T-75-04 | Repudiation | classify_vector drift from bind_verified (gap #9) | high | mitigate | Delete the duplicated binding; classify_vector calls the single pub bind_verified so the test can never silently fall behind the implementation again |
| T-75-05 | Tampering | cross-language parser differential at signature-verified boundary | high | mitigate | Rust verdict pinned against the same 12-case shared vector that Plan 03's TS verifier asserts, forcing identical accept/reject |
</threat_model>
