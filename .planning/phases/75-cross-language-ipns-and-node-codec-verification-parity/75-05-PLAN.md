<objective>
Collapse the TS and Rust UUID acceptance domains for the AAD builder onto a single canonical-only (Option A) policy and lock it with a new cross-language KAT, so a non-canonical node_id can never be accepted by one language and rejected by the other at the AES-GCM AAD boundary.

Purpose: RESEARCH Pattern 4 / the Phase 61 LOW-1 finding — TS uuidToBytes accepts simple-32-hex and loose-hyphen forms Rust rejects, while Rust Uuid::parse_str accepts braced/urn forms TS rejects. Both are fail-closed in isolation, but the phase premise is "a byte mismatch is silent total decryption failure," so the acceptance domains must be identical. Tightening to canonical-only is verified safe: no production caller or existing test in this repo passes a non-canonical form.
Output: Both languages accept only canonical 8-4-4-12 hyphenated UUIDs, proven by a shared vector.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| node_id string → AES-256-GCM AAD | buildNodeAad/build_node_aad turn a UUID string into 16 AAD bytes; a divergent acceptance domain is a theoretical AAD-transplant surface and a silent-decryption risk if a non-canonical node_id ever appears |
| TS AAD builder ↔ Rust AAD builder | Must accept/reject the identical set of node_id forms or the two produce different AAD for the same logical node |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-75-12 | Tampering | UUID acceptance-domain divergence (TS accepts simple-32-hex/loose-hyphen; Rust accepts braced/urn) | medium | mitigate | Canonical-form-only (Option A) on both sides closes the surface entirely rather than syncing two looser domains; locked by the shared oracle |
| T-75-13 | Tampering | a crafted non-canonical node_id encoding differently per language | medium | mitigate | Both boundaries reject every non-canonical form; verified by identical verdicts over uuid-acceptance.json |
| T-75-14 | Spoofing | regression re-loosening one side unnoticed | low | mitigate | Cross-language KAT in the dedicated vector-parity path (cross_language.rs + build-node-aad.test.ts) fails if either side's domain drifts |
</threat_model>
