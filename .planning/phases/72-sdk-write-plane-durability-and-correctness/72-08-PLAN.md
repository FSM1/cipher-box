<objective>
Deliver the core of SC#6: consolidate the divergent write-chain hop-walk spellings and the multiple writeKey-validity spellings into one designed primitive + one predicate — behavior-preserving, gated by the full existing test suite (refactor-under-test).

This is DESIGN-FIRST, not a mechanical extract (RESEARCH §"Write-Chain Hop Walk" + deep_work_rules). The 8 `unsealChildWriteKey` call sites disagree on fail-open vs fail-closed BY DESIGN. The primitive needs an explicit 3-mode parameter (string literals, per project convention — never a TS enum):
- 'require' — missing-ref throws + validation throws (sites 3, 4, 6: resolveFileWriteChainKeys, resolveShareEncryptedWriteKey, moveInSharedFolder reachable branch)
- 'skip' — missing-ref skips (caller handles null) + validation throws (sites 1, 2, 7 and the dominant case; also the posture Plan 03's deleteItem drop and Plan 05's restore re-home follow)
- 'nullable' — missing-ref returns null + validation returns null (site 8 only: resolveSharedSubfolderWriteKey — the sole outlier that swallows AEAD failures by design)

Documented exception (RESEARCH Assumption A2): site 5 (`updateSharedFile` inline walk) has a bespoke fallback-to-legacy-key-lookup shape that fits none of the three modes. Before folding it, grep whether its `getFileIpnsKeyFn` fallback is itself dead; if dead, note it as a follow-up (out of the locked 9-todo scope to remove here); if live, leave site 5 as a documented exception and do NOT force it into a mode.

Purpose: One correct primitive so the fail-open/fail-closed contract per site is explicit and cannot silently drift.
Output: `walkChildWriteKey` + `hasRealWriteKey`, all sites re-pointed, full suite green.
</objective>
