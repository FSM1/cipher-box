<objective>
SC1: make navStack entries carry the derived `writeKey`, not only `folderKey`, so a write into a deep shared subfolder succeeds after navigate-up / breadcrumb restore. Today the only correct subfolder-writeKey source (`resolveSharedSubfolderWriteKey`) runs on DESCENT and its result is discarded; restore seeds `writeKey: undefined` -> a zero buffer (shared-folder-projection.ts:102) for every non-root depth, failing the next write's GCM auth. Capture the current depth's writeKey, thread it through the stack, and re-seed it from the plan-73-06 restore helper — replacing the `isRootDepth ? resolveSharedRootWriteKey(...) : null` branch with a read of the stored writeKey (root becomes just another stack entry). This EXTENDS a key buffer's in-memory lifetime, so it comes with a strict D-09 zero-on-every-exit-path audit.

Purpose (SC1): nested write-share retains write capability across restore; a genuine security-grade zeroization story for the new long-lived buffer.
Output: writeKey-carrying nav stack + audited zeroization + a passing descend-2/up-1/write e2e case.
</objective>
