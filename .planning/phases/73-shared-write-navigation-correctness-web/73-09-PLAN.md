<objective>
SC2: stop the nav-stack from restoring frozen child snapshots. `navigateToSubfolder` pushes `children: p.folderChildren` by reference; the projection subscription only ever updates the CURRENTLY-ACTIVE depth, so a `sharedFolder:updated` for a depth the user navigated away from is dropped and restore serves a stale listing. Fix by reusing existing plumbing: after `seedActiveSharedFolder` re-seeds the target depth in the plan-73-06/73-07 restore helper, immediately call `getSdkClient().refreshSharedFolder(currentShareId)` — it re-resolves the just-seeded depth and, if the sequence is fresher, emits `sharedFolder:updated`, which the already-wired projection subscription applies. The stack's cached `children` become an optimistic first paint corrected within one round trip. No new invalidation data structure.

Purpose (SC2): nav-stack restore reflects fresh children after a remote mutation. Additive to existing freshness machinery; monotonicity-guarded; write-envelope freshness (item-4) already closed by plan 73-05.

</objective>
