<objective>
Replace the non-atomic `findOne→gate→save` publish path with one atomic conditional UPDATE (D-03) that fuses the sequence CAS (TEE-04), the forward-only `generation` gate (TEE-07), and the tombstone gate into a single statement; wire the tombstone state machine (write + resolve-410, WRITE-04 server enforcement); and split the `parseCachedRecord` null case so a shared-folder row applies a seq floor while a CID mismatch fails closed (TEE-05). Resolves all three open research questions (parseCachedRecord return-type union; first-publish INSERT vs forward UPDATE; tombstone authz default `user_id = req.user.id`).

Purpose: TEE-04/TEE-05/TEE-07 — the publish/resolve plane becomes integrity-authoritative with no TOCTOU and no ungated network fall-through.
Output: atomic CAS publish, `tombstoneRecord` + `POST /ipns/tombstone`, 410 marker contract, resolve case-split.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-66-T1 | Tampering | concurrent publishes at same seq | high | mitigate | Atomic UPDATE `WHERE sequence_number = :expected`; `affected === 0` ⇒ 409; no lost update |
| T-66-T2 | Tampering | replay of old lower-seq signed record | high | mitigate | CAS seq gate + embedded-seq anti-rollback parse rejects stale seq |
| T-66-T3 | Tampering | generation regression (stale-generation content) | high | mitigate | `generation <= :incoming` predicate rejects regression server-side (TEE-07) |
