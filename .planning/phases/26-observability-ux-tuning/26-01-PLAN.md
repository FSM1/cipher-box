Create the `docker/grafana/alerts/` directory and five JSON alert rule files. Each file defines a Grafana-managed alert rule suitable for POSTing to the Grafana Alerting Provisioning HTTP API (`POST /api/v1/provisioning/alert-rules`).

**Common structure for all alert rules:**
- `folderUID`: Use placeholder `"GRAFANA_ALERTS_FOLDER_UID"` (to be replaced at provisioning time by the script)
- `ruleGroup`: `"CipherBox Performance"`
- `noDataState`: `"OK"` (prevents false alerts during low-traffic periods when histogram_quantile returns NaN)
- `execErrState`: `"OK"`
- `for`: `"5m"` (sustained threshold breach for 5 minutes before firing)
- `labels.service`: `"cipherbox"`

**1. ipns-resolve-latency.json** -- Two alert rules in array format:
  - **Warning rule:**
    - `title`: `"IPNS Resolve p95 Warning"`
    - PromQL query (refId A): `histogram_quantile(0.95, sum(rate(cipherbox_ipns_resolve_duration_seconds_bucket{source="network", outcome="success"}[5m])) by (le))`
    - Threshold condition (refId B, type `threshold`): `> 0.3` (300ms -- Phase 18 server-side network resolve p95 = 284ms + headroom)
    - `labels.severity`: `"warning"`, `labels.operation`: `"ipns-resolve"`
    - `annotations.summary`: `"IPNS resolve p95 latency exceeds threshold (>300ms)"`
    - `annotations.description`: `"IPNS resolution latency (network source, p95 over 5m window) has exceeded the baseline threshold. Check Someguy health, DHT connectivity, and Kubo status."`

  - **Critical rule:**
    - `title`: `"IPNS Resolve p99 Critical"`
    - PromQL query: same histogram but `histogram_quantile(0.99, ...)`
    - Threshold: `> 0.6` (600ms -- 2x p95 threshold, Phase 18 p99 = 488ms)
    - `labels.severity`: `"critical"`, `labels.operation`: `"ipns-resolve"`

**2. ipfs-pin-latency.json** -- Two alert rules:
  - **Warning:** `histogram_quantile(0.95, sum(rate(cipherbox_ipfs_ipns_duration_seconds_bucket{operation="pin"}[5m])) by (le))` > 0.05 (50ms -- Phase 18 p95 = 18ms + generous headroom for small variance)
    - `title`: `"IPFS Pin p95 Warning"`, `labels.severity`: `"warning"`, `labels.operation`: `"ipfs-pin"`
    - `annotations.summary`: `"IPFS pin p95 latency exceeds threshold (>50ms)"`
  - **Critical:** same histogram, `histogram_quantile(0.99, ...)` > 0.1 (100ms -- Phase 18 p99 = 31ms, 2x p95 = 100ms)
    - `title`: `"IPFS Pin p99 Critical"`, `labels.severity`: `"critical"`, `labels.operation`: `"ipfs-pin"`

**3. api-endpoint-latency.json** -- Warning + Critical for each of five critical routes (10 rules total):
  - **POST /ipfs/upload [201]:** Warning > 0.1 (100ms, p95=45ms), Critical > 0.25 (250ms, p99=50ms but 2x p95 = 100ms, use 250ms for upload headroom)
    - PromQL: `histogram_quantile(0.95, sum(rate(cipherbox_http_request_duration_seconds_bucket{method="POST", route="/ipfs/upload", status_code="201"}[5m])) by (le))`
  - **GET /ipfs/:cid [200]:** Warning > 0.025 (25ms, p95=10ms), Critical > 0.05 (50ms)
    - PromQL: `histogram_quantile(0.95, sum(rate(cipherbox_http_request_duration_seconds_bucket{method="GET", route="/ipfs/:cid", status_code="200"}[5m])) by (le))`
  - **GET /ipns/resolve [200]:** Warning > 0.3 (300ms, p95=245ms), Critical > 0.6 (600ms, p99=467ms)
    - PromQL: `histogram_quantile(0.95, sum(rate(cipherbox_http_request_duration_seconds_bucket{method="GET", route="/ipns/resolve", status_code="200"}[5m])) by (le))`
  - **POST /ipns/publish [201]:** Warning > 0.6 (600ms, p95=477ms), Critical > 1.2 (1200ms, p99=871ms)
    - PromQL: `histogram_quantile(0.95, sum(rate(cipherbox_http_request_duration_seconds_bucket{method="POST", route="/ipns/publish", status_code="201"}[5m])) by (le))`
  - **GET /vault [200]:** Warning > 0.025 (25ms, p95=9ms), Critical > 0.05 (50ms, p99=10ms)
    - PromQL: `histogram_quantile(0.95, sum(rate(cipherbox_http_request_duration_seconds_bucket{method="GET", route="/vault", status_code="200"}[5m])) by (le))`
  - `labels.operation`: per-route (e.g. `"api-upload"`, `"api-download"`, `"api-ipns-resolve"`, `"api-ipns-publish"`, `"api-vault"`)

**4. ipns-publish-latency.json** -- Two alert rules:
  - **Warning:** `histogram_quantile(0.95, sum(rate(cipherbox_ipns_publish_duration_seconds_bucket{outcome="success"}[5m])) by (le))` > 0.6 (600ms -- Phase 18 p95 = 519ms)
    - `title`: `"IPNS Publish p95 Warning"`, `labels.severity`: `"warning"`, `labels.operation`: `"ipns-publish"`
  - **Critical:** same histogram, `histogram_quantile(0.99, ...)` > 1.2 (1200ms -- Phase 18 p99 = 904ms, 2x p95 = 1200ms)
    - `title`: `"IPNS Publish p99 Critical"`, `labels.severity`: `"critical"`, `labels.operation`: `"ipns-publish"`

**5. db-fallback-rate.json** -- One alert rule:
  - `title`: `"IPNS DB Fallback Rate High"`
  - PromQL (refId A): `sum(rate(cipherbox_delegated_routing_fallbacks_total{operation="resolve"}[10m])) / sum(rate(cipherbox_delegated_routing_requests_total{operation="resolve"}[10m]))`
  - Threshold (refId B): `> 0.2` (20% -- per CONTEXT.md locked decision)
  - `for`: `"5m"`
  - `labels.severity`: `"warning"`, `labels.operation`: `"ipns-db-fallback"`
  - `annotations.summary`: `"IPNS DB fallback rate exceeds 20%"`
  - `annotations.description`: `"More than 20% of IPNS resolutions are falling back to database cache. Indicates Someguy or DHT health degradation. Check Someguy container, Kubo connectivity."`

**Data source UID:** Use placeholder string `"GRAFANA_CLOUD_DATASOURCE_UID"` in all `datasourceUid` fields. The provisioning script will sed-replace this at deploy time. For expression nodes (threshold conditions), use `"__expr__"` as datasourceUid.

**Rate window:** Use `[5m]` for all latency alerts (10 data points with 30s scrape) and `[10m]` for the DB fallback rate alert (more stable ratio calculation).

Create `docker/grafana/scripts/provision-alerts.sh` -- a bash script that:

1. Accepts three arguments: `GRAFANA_URL`, `API_KEY`, and `DATASOURCE_UID`
   - Usage: `./provision-alerts.sh <grafana-url> <api-key> <datasource-uid>`
   - Example: `./provision-alerts.sh https://myorg.grafana.net glsa_xxxx abc123def456`

2. Validates all three arguments are provided, prints usage and exits 1 if missing.

3. Discovers or creates the alerts folder:
   - `GET /api/folders` -- search for folder with title "CipherBox Alerts"
   - If not found, `POST /api/folders` with `{"title": "CipherBox Alerts"}` to create it
   - Extract `uid` from the response for use in alert rules

4. For each `.json` file in `docker/grafana/alerts/`:
   - Read the file content
   - Replace `GRAFANA_CLOUD_DATASOURCE_UID` with the provided `$DATASOURCE_UID` argument using `sed`
   - Replace `GRAFANA_ALERTS_FOLDER_UID` with the discovered/created folder UID using `sed`
   - POST to `$GRAFANA_URL/api/v1/provisioning/alert-rules` with:
     - `Authorization: Bearer $API_KEY`
     - `Content-Type: application/json`
     - `X-Disable-Provenance: true` (allows editing rules in Grafana UI after provisioning)
   - Print success/failure per rule (HTTP status code)
   - If any file contains an array of rules (multiple rules per file), iterate over each array element and POST individually using `jq`

5. Print summary: number of rules provisioned successfully vs failed.

6. Set the script as executable (`chmod +x`).

The script should require only `curl`, `jq`, and `sed` (standard Unix tools). Include a check at the top for `jq` availability since it's the least common.

Add a `--dry-run` flag that prints the processed JSON to stdout instead of POSTing to the API. This is useful for verifying placeholder replacement before deploying.
