<objective>
Close VERIFICATION Gap 1 (BLOCKER): the fail-closed anti-rollback gate is inert because no live code path calls it with a real rotation context, and the SDK client's own pre-mutation resolve (`reconcileFolderSequence`) bypasses even the web `enforceResolved` wrapper by calling `sdkCore.resolveIpnsRecord` directly.

This plan makes the M1 defense a live system property (ROADMAP SC#4) by (1) injecting the existing IndexedDB-backed `RotationHighWater` into `CipherBoxClient` and gating the SDK-internal `reconcileFolderSequence` resolve through `enforceResolved`, (2) threading a real `ResolveRotationContext` into the live `handleSync` resolve in `apps/web` (closing the in-code TODO), and (3) upgrading the 68-10 durability spec so the fail-closed rejection is proven by a genuine UI-driven mutation rather than direct module invocation.

Purpose: A relay serving a rolled-back generation/sequence to any live folder mutation must be rejected fail-closed, not silently accepted (the opposite of today's behavior).
Output: A live, reachable fail-closed gate covering every revocation-triggering mutation plus the background sync resolve, with a UI-driven web-e2e proof.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| relay/delegated-routing → client | An IPNS record served to the client is untrusted; a colluding or lagging relay may replay an older (rolled-back) generation/sequence record after a newer one was published. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-68-11-01 | Tampering | reconcileFolderSequence resolve (SDK-internal) | critical | mitigate | Route the resolve through RotationHighWater.enforceResolved (durable IndexedDB seq/generation floor); throw SequenceRegressionError/GenerationRegressionError fail-closed on regression instead of publishing/mutating against a rolled-back record. |
| T-68-11-02 | Elevation of Privilege | revoked reader retains read access | high | mitigate | The live gate ensures a rolled-back record cannot silently re-expose pre-rotation state during a live mutation; regression is rejected, not applied (ROADMAP SC#4). |
| T-68-11-03 | Repudiation | silent acceptance of stale data (no user signal) | medium | mitigate | Regression errors propagate to useMutationFailureUx's D-05 classifier → visible 'Stale data from server rejected.' toast; not swallowed by the reconcile network-error catch. |

No new package-manager installs are introduced by this plan (no npm/pip/cargo additions), so no package-legitimacy checkpoint applies.
</threat_model>
