<objective>
Hoist the durable anti-rollback CORE LOGIC into the SDK so it is unit-tested with Vitest, per docs/TESTING.md (apps/web is NOT unit-tested — its IndexedDB adapter is a thin, untested layer covered only by web-e2e). This plan builds the pure, browser-free state machine and the fail-closed resolve enforcement behind a small injected `HighWaterStore` seam:

1. **Durable high-water state machine (SC#1 / ROT-07):** `createRotationHighWater(generationStore, seqStore)` — monotonic-max `{nodeId → highestGeneration}` and `{nodeId → highestSeq}` floors over an injected `HighWaterStore` (`get(nodeId)` / `put(nodeId, value)`), with `seedFromGrant` (owner-vouched first-contact seed) and read-value validation (non-negative safe integer, else treat as absent — V5 fail-closed).
2. **Resolve enforcement (SC#4 / D-05 / §7.3 test 13/14):** `enforceResolved({ nodeId, seq, generation, versionFloor })` compares a freshly-resolved seq/generation against the stored floors; throws a distinguishable `SequenceRegressionError` / `GenerationRegressionError` on regression, applies the cold-device `versionFloor` gate on first contact, else bumps monotonic-max.

The IndexedDB implementation of `HighWaterStore` and the `resolveIpnsRecord` wiring live in `apps/web` (68-06) as a thin adapter with no unit test. The "restart" durability semantics are unit-proven here by constructing a fresh state machine over the SAME in-memory backing store; the REAL browser-reload durability proof is the 68-10 web-e2e spec (an in-memory-only claim is rejected at review).

Purpose: Put the phase's core security logic (ROT-07) at the unit-tested SDK tier, not in an untested web module.
Output: A pure SDK module + full Vitest coverage (monotonic-max, seed, validation, restart-persistence, fail-closed regression, cold-device versionFloor).

Covers: ROT-07, SC#1 (logic), SC#4 (logic), D-05, D-07 (seed), §7.3 tests 13/14.
