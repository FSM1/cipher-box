<objective>
Build the ROT-07 durable client-side anti-rollback floor (design §4.3 M1 + §6.5) and enforce it at the web resolve chokepoint. Two coupled pieces:

1. **Durable high-water store (SC#1 / D-07 / D-08):** a new `rotation-state.service.ts` following the hand-rolled raw-`indexedDB` pattern (`identity.ts` / `search-index.service.ts` — NO `idb` package). Two object stores keyed by `nodeId`: `{nodeId → highestGeneration}` and `{nodeId → highestSeq}`, monotonic-max on write, seeded from the grant's `rootGeneration` on first contact. Payload validation (reject non-numeric/negative as absent — V5). Call-site try/catch degradation to an in-memory session floor + one-time warning when IndexedDB is unavailable/cleared (D-08).
2. **Enforce at resolve (SC#4 / D-05):** wrap `resolveIpnsRecord` in `ipns.service.ts` (today a pure passthrough) to compare the resolved `sequenceNumber`/generation against the stored high-water; on regression throw a distinguishable fail-closed error (surfaced as the D-05 "stale data from server rejected" toast by 68-09), else bump monotonic-max and return. Keep this a pre-unseal gate — do NOT feed the high-water into `unsealChildReadKey`'s AAD generation (Pitfall 5).

Purpose: Close the colluding-relay stale/replayed-record residual — the phase's core security deliverable (ROT-07).
Output: Durable store service + resolve enforcement + full test coverage (survives-restart, monotonic-max, regression-rejected, cold-device versionFloor, degradation).

Covers: ROT-07, SC#1, SC#4, D-05, D-07, D-08, §7.3 tests 5/13/14.
</objective>
