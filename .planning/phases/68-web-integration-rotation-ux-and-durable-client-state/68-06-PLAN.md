<objective>
Supply the CONCRETE, browser-only IndexedDB adapter behind the 68-01 SDK `HighWaterStore` seam and wire the SDK `enforceResolved` gate into the web resolve path. Per docs/TESTING.md this is a thin `apps/web` adapter with NO unit test — the monotonic-max / fail-closed logic is already unit-proven in the SDK (68-01), and the real-reload durability + fail-closed-toast behavior is proven by the 68-10 web-e2e spec. Two coupled pieces:

1. **Durable HighWaterStore adapter (SC#1 / D-07 / D-08):** `rotation-state.service.ts` following the hand-rolled raw-`indexedDB` pattern (`identity.ts` / `search-index.service.ts` — NO `idb` package). One DB, two object stores (`generation-high-water`, `seq-high-water`) keyed by `nodeId`, each wrapped as a 68-01 `HighWaterStore` (`get`/`put`). Read-value validation (reject non-numeric/negative as absent — V5, matching the SDK guard). Call-site try/catch degradation to an in-memory session-floor `Map` + one-time `warnedOnce` when IndexedDB is unavailable/cleared (D-08). Construct a shared `createRotationHighWater(genStore, seqStore)` instance (from `@cipherbox/sdk`) and expose `seedFromGrant`/`enforceResolved` through it.
2. **Enforce at resolve (SC#4 / D-05):** wrap `resolveIpnsRecord` in `ipns.service.ts` (today a pure passthrough) to call the SDK `enforceResolved` after `resolveIpnsRecordCore` returns, passing the resolved seq/generation + the parent `SealedChildRef.versionFloor`. On regression the SDK throws `SequenceRegressionError`/`GenerationRegressionError` (surfaced as the D-05 toast by 68-09); else the SDK bumps monotonic-max and the record returns. Keep this a pre-unseal gate — do NOT feed the high-water into `unsealChildReadKey`'s AAD generation (Pitfall 5).

Purpose: Provide the real durable store + resolve wiring so the SDK-tier ROT-07 logic (68-01) actually persists to IndexedDB and gates every web read.
Output: A thin IndexedDB HighWaterStore adapter + resolve enforcement wiring (no apps/web unit test; covered by 68-10 web-e2e).

Covers: ROT-07 (web wiring), SC#1 (durable store), SC#4 (resolve enforcement), D-05, D-07, D-08.
</objective>
