<objective>
Wire scope-exit read-key rotation and reconcile-before-publish into the single SDK chokepoint (RESEARCH.md Pitfall 1 — this is `packages/sdk/src/client.ts`, NOT the web hooks). Three coupled changes to the four mutation methods `renameItem` (L495), `moveItem` (L554), `deleteItem` (L689), `deleteToBin` (L1451):

1. **Reconcile-before-publish (SC#3 / D-04):** immediately before triggering a rotation publish, re-resolve the target folder's current `sequenceNumber` and compare against the in-memory `FolderTree` entry. On ANY mismatch (either direction — local stale OR network lagging), throw a distinguishable `ReconcileStaleError` and do NOT publish the rotation ("defer, never skip"). This closes the `#489`/`#494` silent-missed-revocation class.
2. **Scope-exit rotation (SC#2 / SC#4):** call `maybeRotateOnScopeExit(CoverageParams, { rotate })` from `packages/sdk-core/src/rotation/scope.ts`; when `hasCoveringGrant` is true, `deps.rotate` invokes `rotateReadFromNode`; when false, zero rotation publishes occur.
3. **Move-publish-durability (D-12):** fold the Phase 64 OUT-tagged `sdk-client-move-publish-durability` work into `moveItem` — destination-before-source publish ordering + unreadable-descendant enumeration.

The concrete grant state, durable job persistence, and progress are provided via an **injection seam** (transport-decoupled callback pattern, Phase 63–65) so client.ts never imports apps/web. 68-08 supplies the concrete callbacks.

Purpose: The security core of SC#2/SC#3/SC#4 lives at the one chokepoint every host reuses.
Output: Rotation-wired mutation methods + ReconcileStaleError + injection seam + a mock-driven test suite.

Covers: SC#2 (rotate-on-scope-exit), SC#3 (reconcile-defer), SC#4 (zero-rotation invariant), D-02 (synchronous root cut), D-04 (defer-never-skip), D-12 (move-publish-durability).
</objective>
