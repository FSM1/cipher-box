<objective>
Turn the fail-closed errors thrown by the SDK/resolve layer into the exact UI-SPEC failure UX, entirely web-side. The security decisions were already enforced upstream (68-05 defers, 68-06 rejects regressions); this plan only classifies and surfaces them, and implements the bounded-backoff retry:

- **Reconcile defer (D-04/D-06/SC#3):** on `ReconcileStaleError`, show `Syncing latest state…` (info) and auto-retry the mutation with bounded backoff (~5 attempts / ~30s — exact curve is Claude's discretion per D-06). On exhaustion, show terminal `Couldn't complete securely — retry.` (error) with a `Retry` action button; the mutation is NOT applied and NOTHING is queued (no durable retry queue — explicit D-06 scope boundary).
- **Regression rejected (D-05):** on `SequenceRegressionError`/`GenerationRegressionError`, show `Stale data from server rejected.` (error), per-mutation, not a page block.
- **Offline/stale co-writer (D-01/WRITE-03):** on a write failure due to a stale/rotated write descriptor, show `Write failed — access may be out of date.` (error) with a `Refresh access` action that re-resolves the writeDescriptorRef; if the co-writer was actually rotated out, escalate to terminal `Write access revoked.` (error, no action).
- **IndexedDB unavailable (D-08):** show `Secure cache unavailable — falling back to server verification.` (warning) at most once per session (reads the 68-06 `warnedOnce` flag).

Purpose: Deliver the phase's fail-closed-with-clarity UX contract without re-implementing any security check.
Output: A reusable failure-UX hook wired into the three mutation hooks.

Covers: D-01, D-04, D-05, D-06, D-08, SC#3 (defer surfacing), WRITE-03.
</objective>
