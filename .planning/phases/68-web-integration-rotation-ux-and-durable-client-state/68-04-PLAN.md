<objective>
Build the narrow UI surface from the approved UI-SPEC — five notification/status states reusing existing primitives, no new component library. Two pieces:

1. Extend the `Notification` type with an optional `action?: { label: string; onClick: () => void }` and render it in `NotificationToast.tsx` as a small text button (matching the `[x]` dismiss styling) before the dismiss button — supports D-01 (`Refresh access`) and D-06 (`Retry`).
2. Add a `rotation.store.ts` (Zustand, string-literal `status`) and a `RotationStatusBadge.tsx` mounted in `AppHeader`'s `.header-right` before `UserMenu`, rendering the D-02/D-03 badge states (`Revoking access…`, `Finishing revocation…`, `Resuming revocation…`, hidden when idle).

This plan builds the primitives and store; the drivers that set the status / dispatch the toasts are wired in 68-08 (badge lifecycle) and 68-09 (mutation-failure toasts).

Purpose: Establish the reusable UI state + components so downstream driver plans only wire behavior, never rebuild chrome.
Output: Extended notification store/toast + new rotation store + badge + header mount.

Covers: D-01 (action affordance), D-02, D-03, and the toast host for D-04/D-05/D-06/D-08 (copy per UI-SPEC).
</objective>
