<task type="auto">
  <name>Task 2: Initial CVM deployment and endpoint configuration</name>
  <files></files>
  <read_first>
    - apps/tee-worker/docker-compose.phala.yml (CVM compose file from 35-03)
    - .github/workflows/deploy-staging.yml (updated workflow from 35-04)
  </read_first>
  <action>
Once the user provides the PHALA_CLOUD_API_KEY:

1. Install Phala CLI locally:

   ```bash
   npm install -g phala
   ```

2. Set the API key:

   ```bash
   export PHALA_CLOUD_API_KEY="(provided value)"
   ```

3. The TEE Docker image needs to be available on GHCR. Check if the latest image exists:

   ```bash
   docker pull ghcr.io/$(echo $GITHUB_REPOSITORY_OWNER | tr '[:upper:]' '[:lower:]')/cipherbox-tee-worker:latest 2>/dev/null
   ```

   If no image exists yet, build and push it:

   ```bash
   cd apps/tee-worker
   docker build -t ghcr.io/$(echo $GITHUB_REPOSITORY_OWNER | tr '[:upper:]' '[:lower:]')/cipherbox-tee-worker:latest .
   docker push ghcr.io/$(echo $GITHUB_REPOSITORY_OWNER | tr '[:upper:]' '[:lower:]')/cipherbox-tee-worker:latest
   ```

4. Prepare the compose file with real values:

   ```bash
   cd /Users/michael/Code/cipher-box-worktree-general/apps/tee-worker
   export GITHUB_REPOSITORY_OWNER=$(echo $GITHUB_REPOSITORY_OWNER | tr '[:upper:]' '[:lower:]')
   export TAG=latest
   export TEE_WORKER_SECRET="(get from GitHub secrets or ask user)"
   envsubst < docker-compose.phala.yml > /tmp/docker-compose.phala.yml
   ```

5. Deploy the CVM:

   ```bash
   phala deploy \
     -c /tmp/docker-compose.phala.yml \
     -n cipherbox-tee-staging \
     -e "TEE_WORKER_SECRET=${TEE_WORKER_SECRET}" \
     --wait
   ```

6. Get the CVM endpoint URL:

   ```bash
   phala cvms get cipherbox-tee-staging
   ```

   The endpoint will be something like `https://{app-id}-3001.dstack-prod5.phala.network`

7. Verify CVM health:

   ```bash
   curl https://{endpoint}/health
   ```

   Expected: `{ "healthy": true, "mode": "cvm", "epoch": 1, "uptime": ... }`

8. Get the CVM public key (to verify CVM keys differ from simulator):

   ```bash
   curl -H "Authorization: Bearer ${TEE_WORKER_SECRET}" https://{endpoint}/public-key?epoch=1
   ```

9. Report the endpoint URL to the user so they can set `PHALA_TEE_WORKER_URL` in GitHub staging environment variables.

10. If the staging `ipns_republish_schedule` table has existing entries, they were encrypted with simulator keys and won't be decryptable by CVM keys. Advise the user to clear the table:
    ```sql
    TRUNCATE ipns_republish_schedule;
    ```

NOTE: This task heavily depends on the user providing credentials and confirming infrastructure access. If any step fails, document the failure and propose alternatives.
</action>
