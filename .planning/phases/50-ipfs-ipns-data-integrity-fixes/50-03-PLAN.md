<objective>
Fix `collectSubtreeIpnsNames` (D-03, LOCKED — on-demand traversal). The current synchronous walk
returns early when a subfolder is not in the in-memory `folderTree`, so deleting a folder whose
subtree was never expanded leaves every descendant file/folder IPNS record un-unenrolled — the TEE
keeps republishing them until natural expiry. Convert the walk to fetch + decrypt the PERSISTED child
folder metadata on demand (mirroring the `ensureFolderLoaded` DFS), collecting ALL descendant IPNS
names regardless of in-memory load state.

Purpose: Close the nested-IPNS-unenroll leak (HARD-01). Locked to on-demand traversal — do NOT build a
reconciliation-job backstop (the rejected alternative, per D-03).
Output: A RED-first regression test asserting the unenroll batch covers the full subtree (not just
loaded nodes) and that one bad child does not abort siblings, then the async on-demand traversal that
makes it pass. The traversal must NOT mutate `folderTree` (Zustand/SDK desync), and a single
child fetch/decrypt failure must not abort the whole delete.
</objective>

<threat_model>

## Trust Boundaries

| Boundary                                  | Description                                                                                       |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------- |
| SDK client → IPNS (loadFolderMetadata)    | Client fetches + decrypts persisted child folder metadata it owns; server is zero-knowledge       |
| SDK client → CipherBox API (unenrollBatch)| Client sends descendant IPNS names so the TEE stops republishing deleted records                 |
| corrupt/undecryptable child metadata      | A single bad persisted child node must not abort unenrollment of the rest of the subtree          |

## STRIDE Threat Register

| Threat ID | Category               | Component                          | Disposition | Mitigation Plan                                                                                                  |
| --------- | ---------------------- | ---------------------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------- |
| T-50-05   | Information Disclosure | nested IPNS records left enrolled  | mitigate    | On-demand fetch+decrypt collects ALL descendant IPNS names so the TEE stops republishing deleted records (D-03). |
| T-50-06   | Denial of Service      | per-child fetch/decrypt failure    | mitigate    | Each child failure is caught independently; one bad node cannot abort the whole unenroll (Pitfall 4).            |
| T-50-07   | Tampering              | folderTree mutation during traversal | mitigate  | The traversal keeps no state in `folderTree`, preventing the Zustand/SDK desync (stale-sequence 409 / resurrected deletes). |
| T-50-08   | Cryptography           | subfolder key unwrap               | mitigate    | Uses `unwrapKey` from `@cipherbox/crypto` (ECIES), never a hand-rolled crypto path.                              |

</threat_model>
