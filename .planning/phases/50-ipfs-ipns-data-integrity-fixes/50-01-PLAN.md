<objective>
Eliminate the integer-overflow in the guardedUnpin advisory-lock hash (D-01 / WR-01, HIGH). The
current SQL `pg_advisory_xact_lock(abs(hashtext($1))::bigint)` applies `abs()` to the `int4` result
of `hashtext()` BEFORE the bigint cast; for the CID whose `hashtext` is `INT_MIN` (-2147483648),
`abs(int4)` raises `ERROR: integer out of range`, making that file permanently undeletable via the
API and permanently sticking its quota row.

Purpose: Close a permanent-undeletability data-integrity defect (HARD-01). A negative lock key is
valid for `pg_advisory_xact_lock` (signed bigint), so the `abs()` is both wrong and harmful.
Output: A RED-first regression test proving an INT_MIN-hash CID stays deletable, then the fix
dropping `abs()` so the int4 hashtext sign-extends safely to bigint.
</objective>
