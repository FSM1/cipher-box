<objective>
Close finding S2 on the web client (D-02 / D-03): make `resolveIpnsRecord` in `apps/web/src/services/ipns.service.ts` fail-closed. Today it wraps verification in a try/catch that swallows failures into `logger.warn` and returns the CID anyway. The fix mirrors the canonical sdk-core behavior: throw on a present-but-invalid signature and on a pubKey→name mismatch; allow + flag (`signatureVerified=false`) + warn when signature fields are absent (legacy records, D-03); keep the outer catch narrow so only HTTP 404 → null and all other errors (including verification) propagate.

Purpose: a tampered IPNS record served to the web client must be rejected, not silently trusted. Absent fields remain allowed because the DB CID is authoritative (D-03), so legacy vaults are not locked out.
Output: rewritten verification block in the web `resolveIpnsRecord` plus a NEW vitest file proving the four behaviors.
</objective>
