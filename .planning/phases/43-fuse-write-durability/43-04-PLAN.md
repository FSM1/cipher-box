<objective>
Complete the durability loop on the desktop side: inject a stable app-data journal directory
and construct the `WriteQueue` at mount, run vault-scoped dependency-ordered replay on
mount, and surface parked-write failures as an OS notification + tray status via the
existing `SyncStatus` callback channel.

Purpose: The journal (Plan 01) and callback wiring (Plans 02-03) make writes durable, but a
durable entry is useless unless it is (a) stored somewhere that survives reboot, (b) replayed
on next mount, and (c) surfaced to the user when it permanently fails. This plan delivers all
three. Replay uses fetch-and-merge (never re-publish the stale snapshot) to avoid the
multi-device lost-update class.

Output: a `cb-journal` directory under the Tauri app-data dir (0o700); `WriteQueue::new`
wired into `CipherBoxFS`; a `replay_for_vault` step on mount that processes MkdirPublish
before UploadFile, merges each entry into current remote metadata, and CAS-publishes with
retry; and a `SyncStatus::WriteParked` bridge that fires a park notification when failures
exist. Ends with a human-verify checkpoint for the OS notification (not headlessly testable).
</objective>

<threat_model>

## Trust Boundaries

| Boundary | Description |
| -------- | ----------- |
| journal directory location | Must be stable app-data (survives reboot), not temp (cleared) |
| replay → remote IPNS state | Replay must merge into CURRENT remote, never stomp it with a stale snapshot |
| journal entry → vault identity | Replay must only touch entries belonging to the mounted vault |
| parked failure → user surface | Failures must be visible (notification), not swallowed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --------- | -------- | --------- | ----------- | --------------- |
| T-43-13 | Tampering / lost update | `replay_for_vault` publish | mitigate | D-06: fetch current parent metadata, `merge_folder_children`, CAS-publish with retry — never re-publish the captured snapshot (Pitfall 4) |
| T-43-14 | Information Disclosure / wrong-vault | replay scoping | mitigate | D-07: `load_all_for_vault(root_ipns_name)` only; foreign-vault entries (e.g. after account switch) stay untouched on disk |
| T-43-15 | Information Disclosure | `cb-journal` directory perms | mitigate | `0o700` on the journal dir at mount (mirrors temp_dir block); journal files themselves `0o600` from Plan 01 |
| T-43-16 | Repudiation / silent failure | parked write surfacing | mitigate | D-10: OS notification on `failed > 0`; entry kept on disk for manual retry; never silently dropped |

</threat_model>
