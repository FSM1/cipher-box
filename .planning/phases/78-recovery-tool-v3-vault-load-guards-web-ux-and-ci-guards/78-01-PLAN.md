<objective>
Stand up the SC1 recovery-tool build foundation and prove Open Question 1 (does the @cipherbox/crypto + @cipherbox/core stack bundle cleanly for a browser target via esbuild at an acceptable size, with no SDK/API/CDN dependency?). This plan adds the two devDependencies, creates the standalone `recovery-src/` entry point OUTSIDE `apps/web/src` (so the D-07 rule never has to special-case it), writes the esbuild build script, and creates the gateway HTTP transport layer plus a minimal but real `main.ts` entry that imports every primitive the full tool will use — enough to make the spike bundle representative.

Purpose: De-risk the largest task in the phase before the full v3 walk is written. If the bundle is unexpectedly huge or fails to build for the browser, we learn it here, cheaply, not after the walk rewrite.
Output: `recovery-src/build.ts`, `recovery-src/gateway.ts`, `recovery-src/main.ts` (spike-complete), esbuild + fflate as apps/web devDependencies.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| recovery tool → external IPFS/IPNS gateway (HTTP) | Untrusted gateway responses (IPNS records, IPFS bytes) cross into the browser tool |
| user → recovery tool | The pasted `privateKey` is the sole credential; stays client-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-78-01 | Tampering | gateway.ts IPNS resolve | high | mitigate | `verifyIpnsRecordSignature` on the primary rung (self-verifying against the name's embedded Ed25519 pubkey) — rejects a tampered IPNS record. A genuine hardening over the v2 tool, which had zero verification. |
| T-78-02 | Tampering | supply chain (bundled crypto/core, esbuild/fflate) | medium | mitigate | Bundle low-level libs only (D-03); esbuild + fflate audited `[OK]` in RESEARCH; no cdn.jsdelivr runtime fetch (Pitfall 1) — the shipped tool depends only on the user-configured gateway. |
| T-78-03 | Info Disclosure | private key in browser | medium | accept | Key stays client-side; no localStorage/sessionStorage persistence (CLAUDE.md Rule 1); carried forward to 78-02 UI. |
</threat_model>
