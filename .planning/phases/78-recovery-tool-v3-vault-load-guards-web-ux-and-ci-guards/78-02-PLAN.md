## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| recovery walk → external gateway (HTTP) | Every folder/file resolve fetches untrusted bytes from the configured gateway |
| sealed envelope → plaintext | AEAD unseal is the integrity boundary for all recovered content |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-78-04 | Tampering | walk.ts content decrypt | high | mitigate | `unsealNode` + `decryptAesGcm` AEAD auth-tag verification fails closed on any tampered IPFS content — inherent to correct reuse of the shipped codec (D-03), needs no new code. |
| T-78-05 | Tampering | walk.ts child unseal | high | mitigate | Parent-mirror generation (`childRef.generation`) preserves the exact AAD binding the API published; deviation fails closed (auth-tag mismatch), never silently mis-decrypts. |
| T-78-06 | Info Disclosure | privateKey in DOM | medium | accept | `autocomplete="off"`, no localStorage/sessionStorage, post-recovery clear-history note — carried forward from v2 unchanged (CLAUDE.md Rule 1). |
