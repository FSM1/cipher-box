## Decisions Made

- **IPFS uses direct axios/fetch, not api-client generated functions:** The generated `ipfsControllerUpload` function doesn't expose `onUploadProgress` callbacks. Direct axios calls via SdkContext provide full control over upload progress tracking and cancel tokens.
- **IPNS uses api-client generated functions:** The IPNS publish/resolve/batch functions map cleanly to the generated orval functions. This ensures type safety and consistency with the OpenAPI spec.
- **Pure metadata transforms are synchronous:** `renameInFolder`, `deleteFromFolder`, `moveItem`, `addFilePointerToFolder` are pure functions that operate on arrays and return updated arrays. This makes them trivially testable and composable. The caller handles IPNS publishing separately.
- **Upload takes Uint8Array, not File:** The browser `File` API is not available in Node.js. By accepting raw bytes, the upload function works in any JavaScript runtime. The web app converts File to Uint8Array before calling sdk-core.
- **BlobPart cast for Uint8Array:** TypeScript 5.9's strict Uint8Array type requires casting `encryptedData as BlobPart` when constructing Blobs. This is a TS-only concern with no runtime impact.
