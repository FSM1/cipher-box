### Human Verification Required

#### 1. End-to-end File Operations Flow

**Test:** Log into the web app (http://localhost:5173), then:

1. Upload a file to the root folder
2. Create a new subfolder
3. Move the file into the subfolder
4. Rename the subfolder
5. Delete the file to recycle bin
6. Open the recycle bin and verify the deleted file appears
7. Restore the file from the recycle bin
8. Verify it returns to the original folder

**Expected:** All operations complete without errors; folder tree updates automatically after each operation; no console errors related to SDK events or IPNS publishing.

**Why human:** The SDK event chain (client emits -> store subscribes -> React re-renders) involves timing-sensitive async state updates that unit tests mock. A real browser session running against the live API validates the full integration chain including IPNS sequence number management and optimistic update correctness.

#### 2. Logout and Re-login Lifecycle

**Test:** After completing operations above, log out and log back in with the same account.

**Expected:** All previously created folders and files are visible after re-login; no stale SDK state from the previous session.

**Why human:** The `destroySdkClient()` path zeros key material and clears the FolderTree. A second login calls `initSdkClient()` fresh. Correctness requires that no stale module-level state persists. This can only be confirmed in a live browser.
