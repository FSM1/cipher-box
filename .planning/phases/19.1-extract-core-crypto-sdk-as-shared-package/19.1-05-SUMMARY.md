## What was built

Rewired the web app's React hooks and Zustand stores to use `CipherBoxClient` SDK instead of calling service functions directly. All folder CRUD, file upload, download, text editing, delete-to-bin, and move operations now flow through the SDK.

## Key changes

### SDK Provider (`apps/web/src/lib/sdk-provider.ts`)

- `initSdkClient()` creates CipherBoxClient on vault load
- `destroySdkClient()` cleans up on logout (zeros key material)
- `ensureFolderRegistered()` bridges Zustand folder state to SDK's internal FolderTree
- `hasSdkClient()` / `getSdkClient()` for access

### Store Subscriptions

- `folder.store.ts` subscribes to `folder:loaded` / `folder:updated` / `folder:deleted` events
- `bin.store.ts` subscribes to `bin:updated` events
- Unsubscribe callbacks stored as module-level variables (not Zustand state) to avoid spurious re-renders

### Hook Rewiring

- `useFolderMutations.ts` — create, rename, move, delete all use SDK client
- `useDropUpload.ts` — file upload via `client.uploadFile()`, eliminating dual-path IPNS writes
- `useFileDownload.ts` — download via `client.downloadFromIpns()`
- `useBin.ts` — restore, permanent delete, empty bin via SDK
- `TextEditorDialog.tsx` — owner path uses `client.downloadFromIpns()`

### Auth Wiring (`useAuth.ts`)

- `setApiClientConfig()` called during SDK init for `@cipherbox/api-client`
- `client.loadBin()` called after old `initializeBin()` completes

## Issues encountered and fixed

1. **`setApiClientConfig()` not called** — all SDK IPNS operations silently failed
2. **Dual-path IPNS writes** — old upload service + SDK both wrote IPNS records with conflicting seq numbers (409). Fix: rewired upload to SDK
3. **Wrong folder ID** — `handleCreate` used ipnsName instead of UUID. Fix: SDK `createFolder` returns `id` (UUID)
4. **Download/edit decryption failures** — old download path used different IPNS resolution chain. Fix: added `downloadFromIpns()` to SDK
5. **Bin empty after delete** — SDK `loadBin()` returned null on fresh accounts. Fix: return empty BinState when no IPNS record exists
6. **IPNS 409 on rename after create** — `ensureFolderRegistered` overwrote SDK seq number. Fix: skip if SDK already has folder
7. **Invalid Ed25519 key on move** — `ensureFolderRegistered` passed empty publicKey. Fix: skip-if-has pattern

## Code review fixes applied

- `btoa(String.fromCharCode(...spread))` replaced with loop-based encoding in IPNS module
- Axios instance cached per config in api-client (was creating new instance per API call)
- `saveBinMetadata` accepts `BinOperationContext` directly (eliminated parameter sprawl)
- `BinNotLoadedError` typed error class replaces string matching
- Orphaned CID cleanup re-added on upload failure
- Dynamic imports hoisted before duplicate-file loop
- No-op `ensureFolderRegistered` calls removed from move loop
