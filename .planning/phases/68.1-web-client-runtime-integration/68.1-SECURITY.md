## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| client → CipherBox API / IPFS relay | Untrusted relay serves IPNS records + IPFS blobs; may serve stale/rotated-out/tampered/replayed nodes | AES-256-GCM sealed `PublishedNode` envelopes, encrypted content |
| client → API (zero-knowledge server) | Vault registration, share grants, item names — server must never see plaintext or unwrapped keys | `ownerPublicKey`+`rootIpnsName` only; ECIES ciphertext (`readDescriptorRef`/`writeDescriptorRef`, `item_name_encrypted`, `encryptedIpnsPrivateKey`) |
| grant descriptors → recipient | ECIES-wrapped read/write descriptors; only the recipient vault private key unwraps | `readDescriptorRef` / `writeDescriptorRef` (hex ECIES) |
| sharer → recipient (invite bridge) | Ephemeral secp256k1 private key lives ONLY in the URL fragment — never sent to server | fragment `#/invite/{token}?key={hex}` |
| client → TEE (enrollment) | `ipnsPrivateKey` ECIES-wrapped under `teePublicKey` before leaving the client | `encryptedIpnsPrivateKey` + `keyEpoch` |
| in-memory key material → GC/logs | Minted/derived keys zeroed at their terminal owner (D-09); caller-owned buffers never zeroed by callees; no key bytes logged | 32-byte AES keys, Ed25519/secp256k1 private keys |
| write plane (UUID `childId`) vs read plane (`ipnsName`) | Conflating identifier spaces would seal/unseal against the wrong node | `WriteChildRef.childId` (node UUID) vs `SealedChildRef.ipnsName` |
| SDK events → web store | Stale/empty/out-of-order events must never blank or rewind projected state | `folder:updated` / `sharedFolder:updated` children + sequence |
