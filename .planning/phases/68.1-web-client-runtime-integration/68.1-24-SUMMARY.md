**Retired the permanently-unreachable REQ-4 plaintext lazy-backfill (web `shouldBackfill`/`backfillSentShareItemNames`, API `PATCH /shares/:id/item-name`) and added a replacement web-e2e spec proving the already-shipped ECIES `itemNameEncrypted` pipeline end-to-end for both direct share and invite-link claim.**

## Accomplishments

- Removed the dead plaintext-backfill code path across web (`shouldBackfill`, `backfillSentShareItemNames`, the fire-and-forget call in `fetchAllSentShares`, the `sharesControllerUpdateShareItemName` import) and API (`updateShareItemName` controller handler + service method + `UpdateItemNameDto` + its barrel export), deleting the retired `update-item-name.dto.ts` and the now-impossible `share-itemname-backfill.spec.ts` (its own header comment already documented every assertion in it as permanently failing post-schema-cutover).
- Regenerated `packages/api-client` on the main tree via `pnpm api:generate`; the `item-name` path is gone from `openapi.json` and `sharesControllerUpdateShareItemName`/`UpdateItemNameDto` are gone from the generated client and model barrel (manually removed an orphaned model file `orval`'s no-clean tags-split mode left behind).
- Confirmed the encrypted item-name pipeline needed no further wiring: `ShareDialog.tsx` and `invite.service.ts` already ECIES-wrap `itemName` to the recipient/ephemeral public key at create/claim time and send only `itemNameEncrypted`; `useSharedNavigation.ts` already decrypts it client-side for recipient display (68.1-22).
- Added `tests/web-e2e/tests/share-itemname-encrypted.spec.ts`, replacing the deleted backfill spec: verifies the `POST /shares` and `POST /shares/invites` request bodies carry `itemNameEncrypted` hex ciphertext with no plaintext `itemName` key, verifies the `POST /invites/:token/claim` request re-wraps the ciphertext to the claimant's vault key, and verifies the recipient (Bob) sees the correctly decrypted name in `~/shared` for both the direct-share and invite-claim flows.

## Decisions Made

- Executed the recorded GAP-6 human product decision (VERIFICATION.md Round-2 Addendum) verbatim: remove, do not redesign — the encrypted pipeline it would have been redesigned into already ships.
- No code change needed for owner-side sent-share display: `ShareDialog.tsx`'s recipient rows render only the recipient's truncated public key + permission (never a per-row item name — the item name is shown once, in the dialog's own title, from the plaintext prop the owner already holds locally). - Manually deleted the orphaned `updateItemNameDto.ts` generated model and its barrel export after `pnpm api:generate` — `orval.config.ts` has no `output.clean: true`, so regeneration does not remove files for schema components that no longer exist. Logged as a deferred tooling improvement (not fixed, out of this plan's scope).
