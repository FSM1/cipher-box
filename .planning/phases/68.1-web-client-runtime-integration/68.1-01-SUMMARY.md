**Owned folders now publish with a sealed write-body (ipnsPrivateKey + writeChildren), ensureFolderLoaded DFS recovers the full key triple from root to any target, and publishEmptyRootNode gives new users a publishable empty root at seq 1n (D-03 resolved).**

## Accomplishments

- `updateFolderMetadataAndPublish` gains `writeKey`/`writeChildren` params and seals a real write-body when writeKey is supplied, preserving the zero-writeKey legacy path (no `writeSealed` field is produced when writeKey is absent)
- `publishEmptyRootNode` added to sdk-core vault module: kind:'root', children:[], write-body carrying the root ipnsPrivateKey, first publish hard-wired to sequenceNumber 1n (strict gate), TEE-enrollment fail-closed guards mirrored from createSubfolder
- `ensureFolderLoaded` stub replaced with a DFS that seeds the root FolderState from config (rootFolderKey + rootWriteKey + rootIpnsKeypair) and per hop: unseals the child readKey (parent-mirror generation AAD), recovers the child writeKey from the parent write-body (WriteChildRef by child UUID), unseals the child Node with both keys, and derives the ipnsKeypair from the recovered private key — registering every visited folder
- `FolderState.writeKey` + `CipherBoxClientConfig.rootWriteKey` added; FolderTree defensively copies and zeroes writeKey alongside folderKey; client destroy() zeroes internalRootWriteKey
- Every owned publish call site threads `writeKey` + current `writeChildren` via `getWriteBodyParams` (client.ts) / local mirror (bin/index.ts) so republished owned folders retain their write chain verbatim

## Decisions Made

- **rootWriteKey optional, not required:** the plan's artifact list implied `rootWriteKey: Uint8Array` (required), but making it required breaks the web host (useAuth wires it in 68.1-03) and every existing constructor call. Optionality mirrors `rootIpnsKeypair` — self-bootstrap needs BOTH, else ensureFolderLoaded returns null (pre-68.1 behavior preserved).
- **Zero-writeKey guard in getWriteBodyParams:** a legacy zero-fallback writeKey produces a write-body-less publish instead of sealing under a zero key — this is the T-68.1-01-03 mitigation made structural.
- **File-kind children are skipped during DFS descent** (cannot be FolderState targets; their write links are consumed by 68.1-07/09).
