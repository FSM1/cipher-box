# Phase 68.1 Plan 15: Shared-Folder Kind-Cache Wiring Summary

**Wired SharedFolderRow.tsx and SharedFileBrowser.tsx to the D-02 kind cache (isFileRef), closing the "wired upstream, hollow downstream" gap SC#4 flagged in 68.1-VERIFICATION.md — shared files now render/behave as files instead of every item mis-rendering as a folder.**

## Performance

- **Duration:** ~6 min (task edits + build/typecheck)
- **Started:** 2026-07-02T21:49Z (worktree base commit)
- **Completed:** 2026-07-02T21:55Z
- **Tasks:** 2
- **Files modified:** 2

## Accomplishments

- `SharedFolderRow.tsx` now reads `isFolder = !isFileRef(item)` (was hardcoded `true`), so a shared file renders with the file icon, no trailing slash, and no longer accepts internal drops or offers itself as a drop target (existing `isFolder`-gated drag-over/leave/drop handlers become correct automatically)
- Per-item drag payload type (`'file' | 'folder'`) is now derived from `isFileRef` per dragged item (both the single-item and multi-select branches), replacing an unconditional `'folder' as const` literal
- `SharedFileBrowser.tsx`'s in-folder `ContextMenu` `onDownload` prop is now `isFileRef(contextMenu.item) ? handleDownload : undefined` instead of an unconditional `undefined` stub — per-item Download works for files browsed inside a shared folder, mirroring the already-working top-level shared-list context menu
- `SharedFileBrowser.tsx`'s row `onDoubleClick` now only calls `navigateToSubfolder` when `!isFileRef(item)`; double-clicking a file inside a shared folder is a no-op (open remains a context-menu action: Preview/Edit/Download), matching the owned `FileListItem.tsx` behavior exactly

## Decisions Made

- Kept the `isFileRef` gate on `onDownload` explicit at the `SharedFileBrowser.tsx` call site (`isFileRef(contextMenu.item) ? handleDownload : undefined`) rather than relying solely on `ContextMenu.tsx`'s own internal `isFile && onDownload` gate, even though the latter would also work (it's exactly how the already-correct top-level list context menu at line 544 does it, passing `handleDownload` unconditionally). The explicit gate keeps the fix visible and independently grep-verifiable at this call site, and satisfies the plan's stated acceptance criteria (`isFileRef` count >= 2 in the file).
