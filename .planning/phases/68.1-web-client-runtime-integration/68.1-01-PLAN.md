<objective>
Establish the owned write-body foundation that every owned mutation and reload-recovery depends on (resolves design decision D-03). Today owned folders are published WITHOUT a write-body: `updateFolderMetadataAndPublish` (sdk-core/folder/registration.ts) seals a Node with only `children` and a zero writeKey fallback, and `ensureFolderLoaded` (client.ts:476) throws. In node/v3 the only schema-legal place to store a recoverable subfolder `ipnsPrivateKey`/`writeKey` is the sealed write-body (SealedChildRef carries no key-bearing field — NODE-03), so read-chain self-heal of an owned subfolder is impossible until owned folders persist a write-body.

Purpose: unblock `requireFolder`/`ensureFolderLoaded` (the chokepoint for ALL owned mutations) and new-user root init.
Output: sdk-core root-Node publish helper; owned write-body maintenance in `updateFolderMetadataAndPublish`; `ensureFolderLoaded` DFS recovery; `FolderState.writeKey` + `CipherBoxClientConfig.rootWriteKey`.

## Design decision D-03 — RESOLVED (owned FolderState write model)

**Chosen: Approach A — extend the owned model to carry the write-body, mirroring `SharedFolderState`.**

Rationale:
1. `ensureFolderLoaded`'s documented contract (self-heal ANY owned folder from root after a reload, dissolving the "Folder not loaded" class) requires recovering each subfolder's `ipnsPrivateKey`. In node/v3 that key lives ONLY inside the sealed write-body (`SealedChildRef` has no `ipnsPrivateKeyEncrypted`/`folderKeyEncrypted` — those fields were dropped in the v3 cutover). No write-body ⇒ no recovery ⇒ mutating a freshly-navigated subfolder is impossible.
2. It reuses the proven `shared-write.ts` helpers (`unsealParentWriteBody`, `walkChildWriteKey`, `buildChildWriteLink`) and the `sealNode`/`unsealNode` write-body path rather than inventing a parallel owner-only mechanism.
3. It makes owned and shared write paths symmetric, shrinking long-term divergence and matching how `rotateWriteFromNode` already walks the owned chain.

Blast radius (scoped to this plan + its dependents):
- `FolderState` gains `writeKey: Uint8Array` (types.ts). `CipherBoxClientConfig` gains `rootWriteKey: Uint8Array` (already vault-derived at login — see `apps/web/src/hooks/useAuth.ts:171-172`).
- `updateFolderMetadataAndPublish` seals a real write-body from supplied `writeKey` + `writeChildren` (defaulting to a preserved/empty writeChildren) instead of the no-writeBody/zero-writeKey current behavior.
- Owned call sites that publish (`renameItem`, owned `uploadFile`, `moveItem`, `deleteToBin`, `restoreFromBin`) thread `folder.writeKey` + the folder's current `writeChildren`. WriteChildRef INSERTION for new children is owned by the createFolder plan (68.1-02) and the owned-file-write plans (68.1-07/09); this plan only guarantees existing writeChildren are preserved on republish.
</objective>
