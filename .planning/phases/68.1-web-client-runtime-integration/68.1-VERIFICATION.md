### Addendum: post-verification live finding — child IPNS records are not durably registered

*Added by orchestrator 2026-07-02T21:10 after user-reported repro (logout→login → subfolder navigation dead). Supplements SC#3/GAP-2; evidence gathered live.*

**Repro evidence:** user's subfolder ipnsName `k51qzi5uqu5dmfuk8vodzaoowkxig5evfs5jdxlcbiq5qau0ecoj9uau9t02xl` is linked from its parent's SealedChildRef (renders in the file list) but (a) has NO `ipns_records` row, (b) has NO record in the mock-ipns-routing store (in-memory, wiped on container restart), so `GET /ipns/resolve` 404-loops (2×6 resolve attempts at 20:53/20:55) until `ensureFolderLoaded` exhausts retries. Sibling folders WITH `ipns_records` rows survive routing-store loss via the publish-time DB cache and remain navigable.

**Systemic findings (verified):**

1. `client.createFolder` publishes the child's first record WITHOUT `encryptedIpnsPrivateKey`/`keyEpoch` → no TEE republish enrollment; `ipns_republish_schedule` is EMPTY (0 rows) locally. Any record evicted from routing (restart locally; 48h TTL in production) is only recoverable via the DB-cache fallback.
2. The orphaned child (parent link with no DB row anywhere) was created at ~18:53 on the pre-triage-fix build — consistent with the `3f4af4304` folder-store id-desync (parent may link a name whose record/DB registration diverged), or with a bin delete→restore cycle unenrolling the record without re-registration on restore. Discriminating these needs the bin-restore path check: does restoreFromBin re-register the child's IPNS record after deleteToBin unenrolled it?
3. GAP-2's "IPNS propagation timed out" 404s were observed shortly after a mock-ipns-routing container restart (the mock is volatile by design, `tools/mock-ipns-routing/src/index.ts:8`); routing-store wipes convert any non-DB-backed record into a permanent cold-navigation failure. GAP-2 should be re-triaged with this mechanism in scope, not only retry-budget tuning.

**Gap-closure implications:** (i) every child mint (createFolder, per-file Node) must pass `encryptedIpnsPrivateKey`+`keyEpoch` so publish auto-enrolls republish; (ii) bin restore must re-register/re-publish restored children; (iii) consider persisting the mock's store (or restoring from `ipns_records` on boot) so local dev survives restarts.
