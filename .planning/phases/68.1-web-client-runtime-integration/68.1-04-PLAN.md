## Design decision D-02 — RESOLVED (kind discrimination)

**Chosen: resolve-and-cache kind at folder-load into an in-memory kind cache; `isFileRef`/`isFilePointer` read it synchronously.**

Rationale:
1. Keeps `isFileRef`/`isFilePointer` SYNCHRONOUS booleans — no async ripple through the component tree (they are called in render-time list mapping across many components).
2. No schema change — the frozen `SealedChildRef` (no `kind` field, NODE-03) is untouched; kind is a plaintext field on the child `PublishedNode` envelope, resolved once and memoized by ipnsName.
3. The read-chain already fetches child `PublishedNode`s on navigation; folder-load populates the cache with bounded concurrency, so the marginal cost is one resolve per direct child at load time.

Rejected: (b) lazy async icons (forces isFileRef async, large blast radius); (c) carry kind only in in-memory FolderState at create time (misses items loaded from a fresh session).

Blast radius: a new `apps/web/src/lib/kind-cache.ts` (Map keyed by ipnsName); the owned folder-load / navigation path calls `resolveKinds(children)` to populate it before rendering; `fileTypes.ts` reads it. The cache is best-effort — a miss resolves on demand and memoizes.
</objective>
