<objective>
Begin SHARE-WRITE-KEY closure (WEB-03 / SC#4, GAP-3). 68.1-11 documented that write-permission sharing is blocked because the shared item's own writeKey (sealed in the parent's write-body as WriteChildRef.writeKeySealed under the parent's writeKey) is never threaded to the web share UI — ShareDialog only receives folderKey (the parent read key). The backend ALREADY accepts writeDescriptorRef on CreateShare/CreateInvite (create-share.dto.ts:73, create-invite.dto.ts:104) — so this is a web+SDK wiring change, not backend work. This plan adds an SDK primitive that resolves+wraps the item's writeKey (keeping key material inside the SDK boundary) and wires WRITE create for shares and invites.

Purpose: owners can grant write access; the write-permission upgrade path and recipient-side write ops follow in 68.1-19.
Output: resolveShareWriteDescriptor (TDD) + ShareDialog/invite WRITE create.
</objective>
