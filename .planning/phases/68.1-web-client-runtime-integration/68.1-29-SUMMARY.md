## New Gap (documented, NOT fixed — needs its own plan)

### GAP: deep shared writes — writable-shares 8.2 "Bob uploads a file inside the subfolder he created"

- **Symptom:** upload inside a subfolder of a write-shared folder never appears (30s timeout); tests 8.3+ cascade-skip.
- **Root cause class:** the web's shared navigation seeds `SharedFolderState.writeKey` ONLY at the share-root depth (`resolveSharedRootWriteKey` — T-68.1-20-01 "root-depth-only writeKey re-derivation", `useSharedNavigationActions.ts`). Navigating into a subfolder re-seeds that depth with a zero writeKey, so any write op below the root fails.
- **Why not fixed here:** a per-depth write-chain walk (parent writeKey → child WriteChildRef → child writeKey) on shared subfolder navigation is a design change spanning the SDK API surface and the web navigation hooks — beyond this plan's small-targeted-fix budget. Same scope boundary 68.1-20 documented for `moveInSharedFolder`'s one-hop limitation.
- **State:** writable-shares 1.1–8.1 green at the fixed HEAD; 8.2 is the file's only first-failure.
