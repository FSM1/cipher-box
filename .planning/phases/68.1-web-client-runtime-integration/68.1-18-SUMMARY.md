# Phase 68.1 Plan 18: SHARE-WRITE-KEY Foundation Summary

**Added `CipherBoxClient.resolveShareWriteDescriptor` (TDD, 4 tests) to mint an ECIES-wrapped `writeDescriptorRef` from the owned write-chain without exposing raw writeKey to the web layer, and wired it into `ShareDialog.handleShare`'s write-permission path and `invite.service.createInviteLink`'s new optional write path — closing the 68.1-11-documented SHARE-WRITE-KEY web-wiring gap on the owner-create side.**

- **Completed:** 2026-07-02T22:41:00+02:00
- **Tasks:** 2
- **Files modified:** 4 (1 new test file, 3 modified)

## Accomplishments

- `client.ts`: `resolveShareWriteDescriptor(parentIpnsName, itemIpnsName, recipientPublicKey)` walks the owned write-chain the same way `resolveFileWriteChainKeys` does (parent writeKey → `WriteChildRef.writeKeySealed` → `unsealChildWriteKey` with the `(itemNodeId, itemKind, parent-mirror generation)` AAD triad), ECIES-wraps the item's writeKey for the recipient, hex-encodes, zeroes the derived key in `finally` (D-09), and returns hex only.
- Fails closed (throws, never returns an empty/zero descriptor) when the parent has no write-capable `writeKey` or the item has no `WriteChildRef` in the parent's write-body (T-68.1-18-01).
- `ShareDialog.handleShare`'s `permission === 'write'` branch now calls `getSdkClient().resolveShareWriteDescriptor(...)` and sends `writeDescriptorRef` on `sharesControllerCreateShare`, replacing the 68.1-11 `setError`-blocking behavior. `newShare.permission` is now derived from `result.writeDescriptorRef !== null` instead of hardcoded `'read'`.
- `invite.service.createInviteLink` gained an optional `permission?: 'read' | 'write'` param — when `'write'` is requested, it additionally wraps the item's writeKey for the SAME ephemeral public key used for the readKey and sets `writeDescriptorRef` on `shareInvitesControllerCreateInvite`.
- New `resolveParentIpnsName` helper (exported from `invite.service.ts`) translates `useFolderNavigation`'s `'root'` client-side sentinel into the real root IPNS name (`useVaultStore.getState().rootIpnsName`) that `resolveShareWriteDescriptor`'s `parentIpnsName` argument requires.

## Decisions Made

See `key-decisions` in frontmatter for the full list. Summary:

- `resolveShareWriteDescriptor` is a public `CipherBoxClient` method (mirrors `resolveFileIpnsPrivateKey`'s "thin public wrapper over a private write-chain walk" pattern) because the web layer has no independent way to derive write-chain keys under NODE-03's frozen `SealedChildRef` schema.
- `createInviteLink`'s new `permission` param is optional and unused by any current caller (`InviteLinkTab.tsx` has no read/write toggle yet, and is not in this plan's file scope) — the plumbing is unit-exercised at the service boundary and ready for a future UI wiring plan.
- `resolveParentIpnsName` lives in `invite.service.ts` (not `key-wrapping.ts`) since both `ShareDialog.tsx` and `invite.service.ts` need it and `invite.service.ts` already needed it internally, avoiding a new shared module outside this plan's declared file scope.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] `parentFolderId`'s `'root'` sentinel needed translation to a real IPNS name**

- **Found during:** Task 2 (ShareDialog wiring)
- **Issue:** `ShareDialog`/`InviteLinkTab`'s `parentFolderId` prop is `useFolderNavigation`'s `currentFolderId`, which uses the literal string `'root'` for the vault root instead of a real IPNS name. `resolveShareWriteDescriptor`'s `parentIpnsName` argument must be a real IPNS name the SDK client's `FolderTree` can `requireFolder()` against — passing the literal string `'root'` would throw `"Parent folder not loaded"` for every write-permission share/invite of a root-level item.
- **Fix:** Added `resolveParentIpnsName(parentFolderId)` which passes through any real IPNS name unchanged and resolves the `'root'` sentinel via `useVaultStore.getState().rootIpnsName`, throwing a clear error if the vault isn't loaded. Called at both new call sites (`ShareDialog.handleShare`, `invite.service.createInviteLink`) before invoking `resolveShareWriteDescriptor`.
- **Files modified:** `apps/web/src/services/invite.service.ts` (helper), `apps/web/src/components/file-browser/ShareDialog.tsx` (call site)
- **Verification:** `pnpm --filter @cipherbox/web exec tsc -b --pretty false` clean
- **Committed in:** `853c47e78`
