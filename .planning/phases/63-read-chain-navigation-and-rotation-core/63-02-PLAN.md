<objective>
Implement the read-grant issuance and invite-claim re-wrap crypto primitives in a new named file
`packages/sdk-core/src/share/grant.ts`. A read grant is a single ECIES-wrapped share-root readKey;
issuing one touches zero nodes and triggers zero republishes (READ-01 / design §3.2). The invite
claim re-wraps the share-root readKey from the URL-fragment ephemeral key to the claimer's key
(READ-05 / design §3.11). Both stay transport-decoupled behind injected callbacks, unit-tested
against a mocked API (D-05, D-07).

Purpose: O(1) sharing — any subtree or single file is shared by wrapping ONE key, replacing the
O(recipients) fan-out being deleted in Plan 06.
Output: `issueReadGrant`, `claimInviteReadKey` + full mocked-API unit coverage.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-63-05 | Information Disclosure | intermediate share-root readKey in claimInviteReadKey | high | mitigate | claimInviteReadKey is the terminal owner of the minted intermediate and zeros it in a finally block; caller-supplied ephemeral/claimer keys are never zeroed (D-09) |
| T-63-06 | Spoofing | invite link replay | medium | accept | A replayed ephemeral key re-wraps the same root readKey per claimer (design §3.11); revocation is rotation (Plan 03/05), not link invalidation — documented acceptable per ADR 0002 |
| T-63-07 | Information Disclosure | encryptedChildKeys fan-out leakage | high | mitigate | The SDK claim path emits a single re-wrapped root readKey and no per-child key array (D-07); the legacy fan-out is deleted in Plan 06 |
| T-63-08 | Tampering | grant payload integrity | low | accept | readDescriptorRef is ECIES ciphertext; tampering yields an undecryptable grant (fail-closed at navigate time, Plan 01) |
</threat_model>
