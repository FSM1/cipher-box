Add a `someguy` service to docker/docker-compose.staging.yml after the `ipfs` service definition. Use the following configuration per research:

```yaml
someguy:
  image: ghcr.io/ipfs/someguy:v0.11.1
  restart: unless-stopped
  environment:
    SOMEGUY_LISTEN_ADDRESS: 0.0.0.0:8190
    SOMEGUY_DHT: standard
    SOMEGUY_LIBP2P_CONNMGR_LOW: 50
    SOMEGUY_LIBP2P_CONNMGR_HIGH: 300
    SOMEGUY_LIBP2P_MAX_MEMORY: 512MB
    GOLOG_LOG_LEVEL: info
    GOLOG_LOG_FMT: json
  logging: *default-logging
  healthcheck:
    test: ['CMD-SHELL', 'wget -qO- http://localhost:8190/version || exit 1']
    interval: 10s
    timeout: 5s
    retries: 10
    start_period: 30s
  deploy:
    resources:
      limits:
        memory: 768M
        cpus: '0.5'
```

CRITICAL details per CONTEXT.md locked decisions and research pitfalls:
- `SOMEGUY_LISTEN_ADDRESS` MUST be `0.0.0.0:8190` (not default `127.0.0.1:8190`) for Docker inter-container networking
- `SOMEGUY_DHT=standard` for staging (accelerated mode uses 2GB+ memory, does full DHT crawl)
- Health check uses `/version` (Someguy has NO `/health` endpoint)
- Do NOT expose host ports -- Someguy only needs to be reachable from the `api` container within the Docker network
- Do NOT add `depends_on: someguy` to the `api` service -- the API handles routing failures gracefully (DB fallback), and a hard dependency would prevent API startup if Someguy is slow to initialize
- Reuse the `*default-logging` YAML anchor for consistency
  </action>
