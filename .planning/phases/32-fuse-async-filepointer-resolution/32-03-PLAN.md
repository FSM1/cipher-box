# Plan 32-03: Handle open/read for Unresolved FilePointers with Poll-Wait Fallback

<objective>
Add unresolved-FilePointer awareness to `handle_open()` and `handle_read()` in `read_ops.rs`. When a user opens or reads a file that is still an unresolved FilePointer (empty CID, `file_meta_resolved == false`), the handler should poll `drain_filepointer_completions()` in a short loop (up to 5 seconds) waiting for the async resolution to complete. If resolved in time, serve the data normally. If not, return EIO (Finder retries automatically). This implements CONTEXT decision D-07.
</objective>

<must_haves>

- `handle_open()` detects unresolved FilePointers (empty CID + `file_meta_resolved == false`) and polls for resolution
- `handle_read()` detects unresolved FilePointers and polls for resolution
- Poll loop runs for up to 5 seconds with 100ms sleep intervals between polls
- Each poll iteration calls `drain_filepointer_completions()` then re-checks the inode
- If resolved during polling: proceed normally with the now-resolved file data
- If still unresolved after 5s: return `libc::EIO`
- Log messages indicate when poll-wait is entered and its outcome
- `handle_getattr()` calls `drain_filepointer_completions()` so Finder stat-checks reflect resolved metadata
</must_haves>

```rust
    /// Maximum time to wait for an in-flight FilePointer resolution in open/read.
    /// Finder retries automatically on EIO, so 5s is a reasonable upper bound.
    const FILEPOINTER_POLL_TIMEOUT: Duration = Duration::from_secs(5);
    /// Interval between polls when waiting for FilePointer resolution.
    const FILEPOINTER_POLL_INTERVAL: Duration = Duration::from_millis(100);
```

2. In `handle_getattr()` (around line 178), add `fs.drain_filepointer_completions();` after `fs.drain_upload_completions();`:

```rust

        fs.drain_filepointer_completions();
```

This ensures that resolved FilePointer metadata is applied when Finder stat-checks files, so file sizes update promptly after async resolution completes.

4. In `handle_open()`, after extracting `file_info` (around line 210 where `let (cid, encrypted_file_key, iv, encryption_mode) = file_info.unwrap();`), add a poll-wait block for unresolved FilePointers:

```rust
        // If this is an unresolved FilePointer, poll-wait for async resolution
        let (cid, encrypted_file_key, iv, encryption_mode) = {
            let mut info = file_info.unwrap();
            if info.0.is_empty() {
                // Check if this file has an in-flight async resolution
                let is_unresolved = fs.inodes.get(ino)
                    .map(|i| matches!(&i.kind, InodeKind::File { file_meta_resolved: false, .. }))
                    .unwrap_or(false);

                if is_unresolved {
                    log::debug!("open: ino={} is unresolved FilePointer, polling for resolution...", ino);
                    let deadline = std::time::Instant::now() + FILEPOINTER_POLL_TIMEOUT;
                    while std::time::Instant::now() < deadline {
                        std::thread::sleep(FILEPOINTER_POLL_INTERVAL);
                        fs.drain_filepointer_completions();
                        if let Some(inode) = fs.inodes.get(ino) {
                            if let InodeKind::File { cid: ref c, encrypted_file_key: ref efk, iv: ref i, encryption_mode: ref em, file_meta_resolved: true, .. } = inode.kind {
                                if !c.is_empty() {
                                    log::debug!("open: ino={} resolved during poll-wait", ino);
                                    info = (c.clone(), efk.clone(), i.clone(), em.clone());
                                    break;
                                }
                            }
                        }
                    }
                    // Re-check after polling
                    if info.0.is_empty() {
                        log::warn!("open: ino={} still unresolved after {}s poll-wait, returning EIO", ino, FILEPOINTER_POLL_TIMEOUT.as_secs());
                        reply.error(libc::EIO);
                        return;
                    }
                }
            }
            info
        };
```

This replaces the existing line `let (cid, encrypted_file_key, iv, encryption_mode) = file_info.unwrap();`. The variable names and types remain the same, so the rest of handle_open continues to work unchanged.
