<objective>
Add the PURE `crates/core` write-plane emit primitives (P1a-core) so a caller can produce a `PublishedNode` carrying BOTH `read_sealed` and `write_sealed`. Today `crates/core/src/node/{encode,seal}` ship the read-body codec + `seal_node` (read-body only), and `PublishedNode.write_sealed` exists (69-01) but is never populated — no `encode_write_body` and no both-bodies seal exist. This plan lands exactly two new capabilities:

- **`encode_write_body`/`decode_write_body`** (encode.rs/decode.rs) — the deterministic plaintext codec for `NodeWriteBody{ipns_private_key, write_children}`, the Rust twin of `packages/core/src/node/encode.ts::encodeWriteBody`.
- **`seal_published_node(node, read_key, write_key, write_body: Option<&NodeWriteBody>)`** (seal.rs) — composes `encode_node`+`seal_node` (read-body, role 0x01/readKey) AND, when `write_body` is `Some`, `encode_write_body`+seal (write-body, role 0x01/writeKey) → populates `read_sealed`+`write_sealed`. Twin of `packages/core/src/node/seal.ts::sealNode(node, readKey, writeKey)`.

**Explicit-parameter design (HARD, research Pattern 1 / Landmine 2):** `write_body` is a function parameter, NOT a new `Node`-enum field. A field-add force-recompiles every `Node::{Folder,File,Root}` construction and collapses the D-02 split; the read chain never needs `write_body`. This keeps 69-15 to NEW FUNCTIONS ONLY and leaves the read-body KAT byte-identical.

**Additive proof:** new functions only; `seal_node`/`encode_node`/`decode_node`/`Node` unchanged; `crates/fuse` and legacy `crates/core::folder` untouched; `cargo check --workspace` green in isolation.

**A2 RESOLVED:** a write-body golden vector DOES exist — `tests/vectors/node-codec.json` `seal_vectors[0].expected_published_node.writeSealed` (fixed key + fixed IV). 69-15 conforms to it byte-for-byte, so cross-language write-body parity is covered here (no follow-up vector deferred).

Purpose: foundation for SC#1 (Unix symmetric unseal) + SC#4 write side + D-07 dual-keying; the primitive 69-16's sdk emit orchestration consumes.
Output: `encode_write_body`/`decode_write_body`, `seal_published_node`, the write-body KAT test.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| NodeWriteBody plaintext (carries ipns_private_key) → sealed write-body bytes | The Ed25519 signing seed crosses from plaintext into the AEAD-sealed write-body |
| write-body sealed under writeKey vs read-body sealed under readKey | Two distinct AEAD key/role domains that must not be cross-openable |
| Rust write-body seal ↔ TS oracle | Byte-level cross-language agreement gated by the frozen KAT |
