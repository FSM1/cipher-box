<objective>
The atomic D-04 clean cutover: DELETE the legacy `FolderMetadata`/`FileMetadata`/`FilePointer`/`FolderEntry` from `crates/core` and repoint every remaining consumer to the `Node` model — no coexistence, no bridge (Phase-62 style, greenfield single-codec doctrine). This lands AFTER 69-09 has already moved the FUSE read path onto the Node/listing API, so the remaining consumers are the crates/core internals (bin.rs, decrypt.rs, vault_blob.rs, file.rs) plus two FUSE files that still name the legacy types: `metadata.rs` (read-path helpers) and `journal_helpers.rs` (`JournalOp::MkdirPublish.parent_metadata`, Pitfall 6).

vault_blob.rs migrates to the NODE-06 two-key v3 blob (`ECIES(rootReadKey)`+`ECIES(rootWriteKey)`) — ECIES is RETAINED here (root wrap only). journal_helpers.rs gets a fail-closed (log + skip, not panic) replay path for a stale pre-cutover on-disk entry (Pitfall 6 — no prod journals exist, but a developer's mid-transition install could have stale entries).

This plan is atomic-by-necessity for a Rust workspace: deleting a shared type in crates/core forces every consumer to migrate in the same compile unit. `cargo check --workspace` is the boundary gate.

Purpose: SC#4 clean cutover (legacy types gone, single Node model).
Output: folder.rs legacy types deleted; all consumers on Node.
</objective>
