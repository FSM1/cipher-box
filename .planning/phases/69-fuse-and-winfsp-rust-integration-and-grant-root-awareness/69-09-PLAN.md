<objective>
The ATOMIC Unix FUSE node/v3 read+write data-model cutover (P1, wave A, flag-day). Flip the entire Unix `crates/fuse` in-memory `InodeKind` AND the on-IPNS wire format from the legacy ECIES/`FolderMetadata` model to the `node/v3` symmetric model, migrating READ (SC#1 unseal) and WRITE (Node + `SealedChildRef` emission) together in ONE compile unit. The mount is a WRITE-OWNER: the read path materializes each node's owned `{read_key, write_key, ipns_private_key}` through the gated `crates/sdk::listing::list_folder_owned` (69-17) — which recovers the write plane via `crates/core::node::seal::{unseal_child_read_key, unseal_child_write_key, unseal_node}` (69-04) — to fill `InodeKind`. The write path emits node/v3 (`Node` + the D-07 dual `SealedChildRef`/`WriteChildRef` via `emit.rs`, 69-16) and enqueues the node/v3-reshaped `crates/sdk::queue::JournalOp` (the enum SHAPE landed in 69-18); this plan migrates the fuse constructor sites (`journal_helpers.rs`) and the reader (`replay.rs`) onto that reshaped enum in the same unit. Legacy `crates/core` types are RETAINED-but-unreferenced-by-`fuse` at this plan's boundary — their deletion is 69-10 (P2).

Why atomic (research sections 2.1-2.5): read unwraps EXACTLY what write seals, and both pin the same `InodeKind` fields plus the same reshaped `JournalOp` shape (from 69-18). In Rust, a consumer of a reshaped shared type must change together with it or `cargo check --workspace` is red — so the `journal_helpers.rs` constructors + `replay.rs` reader (both in `crates/fuse`) migrate onto 69-18's reshaped `JournalOp` here, in one unit. Splitting P1 by read-vs-write reintroduces the exact blocker the 69-09 executor hit (research landmine 4). Therefore this plan is structured as three sequenced sub-layer tasks (1: `InodeKind` + write seal + reshaped-`JournalOp` construction; 2: read consumers via `list_folder_owned` + `replay.rs` reader; 3: glue + desktop sites + SC#6 gate), but the guaranteed-green checkpoint is the PLAN boundary — Tasks 1 and 2 compile RED mid-flip by design (research section 2.5). A clean flag-day is correct and safe: no prod vaults exist, D-04 mandates it, and the atomic plan keeps write+read format-consistent at its own boundary (research section 2.3).

Explicitly NOT here: `crates/core/src/folder.rs` deletion (69-10); the grant-gate / `revoke_shares_blocking` replacement (69-13 — P1 leaves the revoke call behavior as-is); the `spawn_file_meta_reencrypt` deletion (69-13, sequenced AFTER the Node model per Pitfall 5); `platform/windows/*` (69-14, `#[cfg(feature="winfsp")]`, excluded from the default build).

Purpose: SC#1 (Unix read symmetric unseal via the owned materialization) + SC#6 (single gated read entrypoint), with the write plane emitting Node + enqueuing the reshaped JournalOp so P2 can delete the legacy types.
Output: the full Unix `crates/fuse` on node/v3 (read via `list_folder_owned` + write via `emit.rs` + reshaped-`JournalOp` construction/replay), the SC#6 CI grep gate, `cargo check --workspace` green.
</objective>
