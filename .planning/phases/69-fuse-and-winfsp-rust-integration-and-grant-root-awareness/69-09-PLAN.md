<objective>
The ATOMIC Unix FUSE node/v3 read+write data-model cutover (P1, wave A, flag-day). Flip the entire Unix `crates/fuse` in-memory `InodeKind` AND the on-IPNS wire format from the legacy ECIES/`FolderMetadata` model to the `node/v3` symmetric model, migrating READ (SC#1 unseal) and WRITE (Node + `SealedChildRef` emission) together in ONE compile unit. The read path routes every node-to-node child/file-key hop through `crates/core::node::seal::unseal_child_read_key`/`unseal_node` (69-04) reached via the gated `crates/sdk::listing::list_folder` (69-06, SC#6). The cross-crate `crates/sdk::queue::JournalOp` field is repointed in the same unit (research landmine 1). Legacy `crates/core` types are RETAINED-but-unreferenced-by-`fuse` at this plan's boundary — their deletion is 69-10 (P2).

Why atomic (research sections 2.1-2.5): read unwraps EXACTLY what write seals, and both pin the same `InodeKind` fields plus the same `JournalOp::MkdirPublish.parent_metadata` type. In Rust, changing a shared type's shape is a single compile unit — every producer and consumer must change together or `cargo check --workspace` is red. Splitting P1 by read-vs-write reintroduces the exact blocker the 69-09 executor hit (research landmine 4). Therefore this plan is structured as three sequenced sub-layer tasks (1: `InodeKind` + write seal + `JournalOp`; 2: read consumers; 3: glue + desktop sites + SC#6 gate), but the guaranteed-green checkpoint is the PLAN boundary — Tasks 1 and 2 compile RED mid-flip by design (research section 2.5). A clean flag-day is correct and safe: no prod vaults exist, D-04 mandates it, and the atomic plan keeps write+read format-consistent at its own boundary (research section 2.3).

Explicitly NOT here: `crates/core/src/folder.rs` deletion (69-10); the grant-gate / `revoke_shares_blocking` replacement (69-13 — P1 leaves the revoke call behavior as-is); the `spawn_file_meta_reencrypt` deletion (69-13, sequenced AFTER the Node model per Pitfall 5); `platform/windows/*` (69-14, `#[cfg(feature="winfsp")]`, excluded from the default build).

Purpose: SC#1 (Unix read symmetric unseal) + SC#6 (single gated read entrypoint), with the write plane emitting Node so P2 can delete the legacy types.
Output: the full Unix `crates/fuse` on node/v3 (read+write), the `JournalOp` weld repointed, the SC#6 CI grep gate, `cargo check --workspace` green.
</objective>
