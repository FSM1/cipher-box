<objective>
Provide the GATED write-plane tree-materialization API (P1a-2) the FUSE cutover (P1b / 69-09) consumes. The FUSE mount is a read-WRITE vault owner: `crates/fuse/src/inode.rs` `InodeKind::{Root,Folder,File}` each store the node's WRITE material (`ipns_private_key` to SIGN this node's IPNS records, plus `folder_key`/`encrypted_file_key`), which legacy `populate_folder` recovers by ECIES-unwrapping each child's wrapped keys under the user's private key (inode.rs:434/451). The 69-16 gated listing (`list_folder`) is a read-only, keyless projection — `resolve_child` unseals the child read-key and IMMEDIATELY zeroizes it (listing.rs:307-324), and NEVER unseals the write-body. So flipping `InodeKind` to node/v3 requires a way to materialize per-node `{read_key, write_key, ipns_private_key}` for an EXISTING tree. This plan lands it, ADDITIVELY (crates/fuse UNTOUCHED):

- **`ResolvedOwnedChild`** (listing.rs) — `{ child: ResolvedChild, read_key: Zeroizing<[u8;32]>, write_key: Zeroizing<[u8;32]>, ipns_private_key: Zeroizing<Vec<u8>> }`. The mount is the terminal owner (D-09): these are returned RAW/Zeroizing to the caller; the SDK does NOT zero them. Redacting `Debug` (mirror `emit.rs` `FolderEmission`).
- **`resolve_owned_child`** (listing.rs) — mirrors the private `resolve_child` but recovers the write plane too: unseal `read_key` (under `parent_read_key`) + `write_key` (under `parent_write_key`, via `unseal_child_write_key` — the half `resolve_child` omits) + `unseal_node(published.write_sealed, child_write_key)` -> `decode_write_body` -> `NodeWriteBody.ipns_private_key`. Fail-closed on any unseal/length/missing-pair (Err, never panic). D-07 pairing: match `SealedChildRef` (read plane, ipnsName) with `WriteChildRef` (write plane, childId UUID) by the child node identity (`published.id == WriteChildRef.child_id`) — never conflate ipnsName and childId.
- **`list_folder_owned`** (listing.rs) — parallels `list_folder`, takes parent read+write keys, routes through the SAME `NodeFetcher` + `RotationHighWater::enforce_resolved` gate (SC#6: no raw resolve; `resolve_published_node` stays `pub(crate)`). Unseals the parent's read-body (`children: Vec<SealedChildRef>`) AND write-body (`write_children: Vec<WriteChildRef>`) so the D-07 pairing is possible, then resolves each child through `resolve_owned_child`.

**Zeroization (D-09 terminal-owner):** `parent_read_key`/`parent_write_key` are caller-supplied borrows — NEVER zeroed here. Only SDK-minted scratch is zeroed. An explicit test asserts the caller buffers are unchanged (mirror `emit.rs`).

Purpose: SC#1 (Unix symmetric unseal — the owned read path P1b builds `InodeKind` from) + SC#6 (single gated read entrypoint, now `list_folder`/`list_shared_folder`/`list_folder_owned`).
Output: `ResolvedOwnedChild`, `resolve_owned_child`, `list_folder_owned`; `cargo check --workspace` + `cargo test -p cipherbox-sdk` green, `crates/fuse` untouched.
</objective>
