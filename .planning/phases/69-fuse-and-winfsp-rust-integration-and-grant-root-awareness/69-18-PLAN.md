<objective>
Reshape the durable write journal's `JournalOp` wire format (P1a-3) off the legacy hex-ECIES-under-user-key model onto the `node/v3` symmetric model, and make replay fail-closed on stale entries. Today `crates/sdk::queue::JournalOp::{UploadFile,MkdirPublish}` carries hex-string, user-ECIES-under-`self.public_key` fields (`wrapped_key_hex`, `parent_ipns_key_hex`, `filename_encrypted_hex`, `child_folder_key_hex`, ...). Flipping `InodeKind` to node/v3 (69-09) requires a node/v3-shaped journal so a journaled write replays via the Node seal path, not ECIES.

**GREEN-vs-FOLD decision: GREEN (this plan stands alone at the crates/sdk boundary; it does NOT fold into 69-09).** Rationale — `JournalOp` lives in `crates/sdk/src/queue.rs`, a self-contained crate; its impl match arms and `#[cfg(test)]` round-trip tests all live in queue.rs, so this plan reshapes the enum and keeps `cargo test -p cipherbox-sdk` GREEN. The enum's *constructor* sites (`crates/fuse/src/journal_helpers.rs`) and *reader* (`crates/fuse/src/replay.rs`) are cross-crate in `crates/fuse`; reshaping the variant fields necessarily breaks them, and the D-04 clean-flag-day doctrine forbids the coexisting dual-variant set that would keep the workspace green — so those fuse sites migrate in 69-09's ATOMIC compile unit (the same "compiles RED mid-flip by design" pattern 69-09 already documents). Splitting cleanly on the crate seam — **69-18 owns the sdk enum shape; 69-09 owns the fuse construction/reading** — yields two well-scoped compile boundaries: `cargo test -p cipherbox-sdk` green here, `cargo check --workspace` green at 69-09. `cargo check --workspace` compiles RED between this plan and 69-09 by design (queue.rs is cross-crate with fuse — the research sanctions this).

This plan lands, in `crates/sdk/src/queue.rs` ONLY (crates/fuse UNTOUCHED, mirroring the 69-16/69-17 additive-sdk discipline):

- **Reshaped `JournalOp::UploadFile`/`MkdirPublish`** — replace the hex-ECIES key/metadata fields with node/v3 fields: the freshly emitted **child `PublishedNode` bytes** + the updated parent **`SealedChildRef`** (read plane, ipnsName + `read_key_sealed`) + **`WriteChildRef`** (write plane, childId UUID + `write_key_sealed`, D-07) + the parent node identity (`parent_folder_ipns_name`). KEEP the sidecar-ciphertext mechanism (D-01, WR-06: `sidecar_path`/`sidecar_sha256`/`legacy_ciphertext_b64` migration path) and the routing/timestamp fields (`file_meta_ipns_name`, `parent_folder_ipns_name`, `size`, `created_at_ms`) — only the KEY/metadata fields change shape.
- **Fail-closed replay skip** — a stale pre-cutover entry that fails serde under the new shape is `log::warn!` + SKIPPED by `load_all_for_vault` (D-04 clean flag-day, no prod vaults -> NO dual-format deserializer), reusing queue.rs's existing Err-skip idiom. The one-time `~/.cipherbox/journal` clear is documented in the SUMMARY.

Purpose: SC#4 (node/v3 write journal) + SC#6 (the node/v3 read/write model consolidated in crates/sdk) — the reshaped journal 69-09's FUSE write path enqueues and replay reinterprets.
Output: the node/v3-shaped `JournalOp`, its fail-closed stale-skip, `cargo test -p cipherbox-sdk` green (crates/fuse migrates in 69-09).
</objective>
