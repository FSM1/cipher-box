<objective>
Delete the `^0xA5` placeholder bridge from the desktop mount and feed the REAL node/v3 root read/write keys (recovered by 69-23 into KeyState by 69-22) into the mounted filesystem. Today `mount_filesystem` receives `root_folder_key` and re-derives fake node/v3 keys inline (`root_read_key = root_folder_key[..32]`, `root_write_key = read_key ^ 0xA5`, mod.rs:179-205), so the mount reads/writes under keys that never match a real vault (research §Q4 change-set 4/5).

This plan:
- **fuse/mod.rs**: adds `root_read_key`/`root_write_key` params to `mount_filesystem`, DELETES the inline `^0xA5` bridge, and feeds the passed keys into `InodeKind::Root`, `prepopulate_filesystem`, and `replay_for_vault` (all of which already accept the two keys).
- **commands/auth.rs**: `post_auth_finalize` reads `state.sdk.root_read_key`/`root_write_key` and passes them into `mount_filesystem` (one cfg-agnostic call site).
- **fuse/windows/mod.rs** (cfg(winfsp)): the same two params + drop its own `^0xA5` bridge for parity — edit-for-correctness, compiled/verified under the Windows CI gate and 69-14 (the default non-winfsp build never compiles it).

`crates/fuse` is untouched: `CipherBoxFS.root_folder_key` is still a live legacy field (fs.rs:112 + winfsp read_ops/dir_ops), so mount keeps threading `root_folder_key` into the struct; its removal is separate crates/fuse cleanup out of scope. Terminal-owner zeroization (D-09) preserved.

Purpose: SC-04 — the mount consumes the real persisted node/v3 root keys; the placeholder is fully retired.
Output: `mount_filesystem` (both platforms) wired to real root_read_key/root_write_key, `^0xA5` gone.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| KeyState (state.sdk.root_read_key/write) -> mount_filesystem -> InodeKind::Root | The recovered real keys cross into the FS root; a fabricated key here silently breaks read/write of a real vault |
| root_read_key/root_write_key -> prepopulate + replay | The two keys drive the node/v3 read chain + journal replay; conflating them corrupts the write plane |
| mount (borrower) vs KeyState (owner) of the keys | Terminal-owner boundary — mount must not zero the caller-owned state keys (D-09) |
