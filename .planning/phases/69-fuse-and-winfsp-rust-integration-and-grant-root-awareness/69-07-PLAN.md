<objective>
Create the net-new grant-root scope module `crates/fuse/src/write_ops/grant_scope.rs` — the ONE piece with no TS analog (TS never had a mounted filesystem tree to walk). It has two halves:

1. **Ancestor walk (genuinely novel):** compute a mutated inode's leaf-first ancestor IPNS-name chain by walking `parent_ino` up to `ROOT_INO` in the already-mounted inode table (`crates/fuse/src/inode.rs` `fs.inodes`), collecting `InodeKind::Folder{ipns_name}`/`InodeKind::Root{ipns_name}` — O(depth), purely local, NO network call (design §3.9; anti-pattern: resolving ancestry over the network).
2. **Grant-set source (Pitfall 2):** a local sent-shares cache on the `CipherBoxFS` state, refreshed on mount / periodically from `list_sent_shares` (69-03), NOT a synchronous per-mutation query. `has_covering_grant` (69-05, imported from `crates/sdk`, NOT reimplemented) reads `active_grant_root_ipns_names` + `local_grant_record` from this cache.

Hoist this module so BOTH the Unix write handlers (69-11) and the Windows write handlers (69-14) consume the SAME ancestor-walk + `has_covering_grant` call site — never a per-platform copy (Pitfall 1). This plan is additive (new module + cache field); it does not yet rewire delete/rename (that is 69-11).

Purpose: SC#3 scope-computation building block, shared by both platforms.
Output: `crates/fuse/src/write_ops/grant_scope.rs` + a sent-shares cache on FS state.
</objective>
