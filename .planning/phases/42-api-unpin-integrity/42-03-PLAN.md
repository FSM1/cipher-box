<objective>
Implement `VaultService.guardedUnpin(userId, cid)` — the security core of the phase. This single method enforces ownership (D-01), serializes concurrent deletes with a per-CID Postgres advisory lock (D-04), decrements quota by deleting the caller's `pinned_cids` row inside a transaction (D-03), reference-counts across all users and only queues a physical unpin via the `pending_unpins` outbox when the count hits zero (D-05), emits cross-user audit telemetry (D-02), and best-effort attempts the inline Kubo `pin/rm` after commit (D-03 ordering).

Purpose: This is the fix for both audit todos — it converts the unauthenticated "any CID, any user" unpin into "delete my reference; physically unpin only if I was the last reference." The controller (42-05) and worker (42-06) are thin wrappers around this method.
Output: `guardedUnpin` method on `VaultService`, `DataSource` + `IPFS_PROVIDER` + `MetricsService` + `PendingUnpin` repo injected, `vault.module.ts` wired, comprehensive spec.

<threat_model>

## Trust Boundaries

| Boundary | Description |
| -------- | ----------- |
| authenticated caller → guardedUnpin(userId, cid) | userId from verified JWT; cid is an untrusted public identifier — knowledge of it must NOT confer deletion authority |
| guardedUnpin → Postgres transaction | concurrent deleters of the same deduped CID race on refcount; serialized by advisory lock |
| guardedUnpin → Kubo pin/rm | external service call; must be post-commit and best-effort |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --------- | -------- | --------- | ----------- | --------------- |
| T-42-06 | Tampering | cross-tenant unpin via CID knowledge (the core vuln) | mitigate | Ownership check: caller must own a `pinned_cids(userId, cid)` row before any Kubo call; no-row path touches nothing (D-01). |
| T-42-07 | Information Disclosure | CID-existence oracle via response divergence | mitigate | guardedUnpin returns void on ALL no-row sub-cases; controller returns identical `{success:true}`; cross-user vs unknown distinction lives only in server-side telemetry, never the response (D-01). |
| T-42-08 | Tampering | refcount race enabling premature/double global pin/rm | mitigate | `pg_advisory_xact_lock(abs(hashtext(cid)))` as first statement serializes all concurrent deletes for a CID; orIgnore on outbox insert dedupes (D-04, Pitfall 5). |
| T-42-09 | Denial of Service | quota inflation via failed deletes | mitigate | Row delete (= quota decrement) is in the committed transaction; Kubo failure is post-commit and never rolls back the quota credit (D-03). |
| T-42-10 | Denial of Service | BYO advisory row blocking a foreign physical unpin | accept | Equal-refcount semantics (D-07): a BYO row can only delay (over-retain) a physical pin/rm, never force one; over-retention self-heals when the BYO user deletes. |
| T-42-11 | Tampering | upload/unpin race leaving row-but-no-pin | accept | D-13: requires identical ciphertext + sub-second window (cryptographically negligible); drift report (42-06) detects; documented at the compensation path (42-05). |
| T-42-SC | Tampering | npm installs | accept | No new packages; typeorm/prom-client/@nestjs/bullmq already installed (RESEARCH audit). |

</threat_model>
