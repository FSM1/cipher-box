# CipherBox v2 — Ubiquitous Language

Glossary only. Design detail lives in `blueprint/`; the as-built v1 spec corpus, ADRs, and decision history live in [FSM1/cipher-box-next](https://github.com/FSM1/cipher-box-next).

## Read-plane key model (seeded derivation)

- **Node seed** — the per-node secret from which a node's keys derive, flat within a scope: `nodeSeed(X) = KDF(scopeSeed, X.id)`. Location-independent, so intra-scope moves are pure relinks; membership is the envelope's epoch tag.
- **Scope** — a derivation domain: the set of nodes keyed from one scope seed — random, except the vault root's first epoch, which derives from the login secret so a first-run mint is idempotent (ADR 0007). The vault root is the initial scope; every grant on an interior folder and every rotation creates or re-seeds one.
- **Scope root** — the node a scope is anchored at, carrying its grant blobs, owner blob, ascent link, and history links. Granting an interior folder makes it a scope root (with a subtree sweep into the new scope).
- **Content key** — a random per-version key stored inline in the sealed read-body. Rotation re-wraps it for free via the metadata re-seal and never re-encrypts content bytes; the next version is fresh-keyed. There is no pending-re-key state.
- **Version history** — a file's sealed list of content versions, newest first; its head is the file's current content and every other entry is a **prior version**. A version is named by its `contentCid`, the only identifier the list carries. The vault's **version retention** rule — the member's `keepLatestVersions` setting — bounds the list where it grows, and a retained version's root stays registered under the file's own name, which is what keeps orphan GC off it. Restoring a prior version publishes a new record whose head is that version and never rewinds history; deleting one drops its entry and retires its blocks.
- **Cross-scope move** — moving a node between scopes re-seals the moved subtree at the destination scope's epoch (and is a scope exit for the source when the source is granted). The crossing is classified once, when the op is journaled, and the **journaled crossing** is a plan, never the authority: the drain re-derives it from the two planes its own pass proved and owes the source cut from that pair, so a boundary the journaling session had not yet proved still re-seals the moved subtree and cuts the scope it left.
- **Override seed** — the fresh random seed minted at a scope root by a rotation, replacing its derived (or prior override) seed and starting a new epoch.
- **Epoch** — a scope-relative rotation counter. Every sealed body carries a plaintext, AAD-bound **epoch tag** `{scope, epoch}`.
- **Ascent link** — the current override seed sealed to an asymmetric keypair derived from the _parent's_ node seed (never the child's own): the public half rides plaintext in the scope root's envelope so any writer can re-seal the link; unsealing requires the parent seed, so only ancestor-scope readers descend. Ancestor readers re-derive the expected keypair and reject a mismatched public half. Deliberately unreadable to holders of the scope's own prior seed.
- **Owner blob** — the current override seed HPKE-sealed to the vault owner's enc subkey, present at every scope root and maintained by whoever rotates. The owner is an implicit, permanent, unrevokable grantee of every scope. An accelerator for owner entry — the canonical path is the owner seed cache; cross-checked against the ascent link and actual unseals, with disagreement raised as attributable abuse.
- **Owner write blob** — the write-plane mirror of the owner blob: the scope's `writeScopeSeed` HPKE-sealed to the owner's own enc subkey, payload `{writeEpoch, writeScopeSeed}`, AAD bound to the writeEpoch. The seed is random and a KDF non-edge at every scope and epoch but one — the vault root's first epoch derives it from the login secret (ADR 0007), and the first write rotation replaces it with a drawn one. Authored at every write-scope root the owner owns, beside the write-body; it is the owner's cold-start recovery of a write-plane input they otherwise cannot re-derive, so a fresh device can source `write_name_signer` and renew the owner's own records.
- **Owner seed cache** — the owner's self-authored `{seed, epoch}` per granted scope, kept in the owner's own vault share list and refreshed on every confirmed owner read. The canonical owner entry into any scope; a rogue rotator can withhold at most the epochs minted since the owner's last visit.
- **History link** — the previous epoch's seed sealed under the current one; the key-regression ratchet. Current-seed holders walk backward to read not-yet-resealed nodes; old-seed holders can never walk forward. So a new grantee of a scope reads every earlier epoch ([ADR 0026](https://github.com/FSM1/cipher-box-next/blob/main/decisions/0026-a-scope-root-takes-many-grants.md) D6).
- **Lazy wave** — post-rotation re-sealing of a scope's interior nodes at the new epoch, carried by ordinary writes and/or a background sweep rather than an eager cascade. Descendant scope roots are eager-set members and never ride it ([ADR 0003](https://github.com/FSM1/cipher-box-next/blob/main/decisions/0003-sweep-population-and-below-floor-scope-roots.md)).
- **Epoch lag** — a node whose envelope epoch is behind its scope's current epoch; readable via history links, queued for the lazy wave. Replaces v1's "dirty edge".
- **Eager set** — the nodes a revocation rotation must republish before it counts as cut: the rotated scope root plus every transitively-reachable descendant scope root, each fully rotated — the live-grant qualifier is retired, since a revokee may hold cached descendant seeds (grant-less scopes are cheap: an empty blob set). A grantee scope-exit rotation revokes nobody and stays flat. Interior nodes ride the lazy wave.
- **Epoch-converged** — a subtree with no epoch-lagged nodes. A fresh mint requires converging the subtree first (a new grantee cannot regress through an ancestor scope's history); an append to an existing scope root does not converge (ADR 0026 D1).

## Write-plane key model

- **Write seed** — the write plane's parallel derivation, flat within a write scope: `writeSeed(X) = KDF(writeScopeSeed, X.id)`. A node's Ed25519 IPNS keypair, its `ipnsName`, and its `writeKey` all derive from its write seed. Read grants carry read seeds only; write grants carry both.
- **Write-scope cut** — granting write on an interior folder anchors a fresh write scope there: flat derivation means one node's write seed cannot derive its children's, so the grant mints a write scope seed and runs a name wave over the subtree. An upgrade of a grantee to write on a folder that is not a write scope yet runs one first ([ADR 0025](https://github.com/FSM1/cipher-box-next/blob/main/decisions/0025-revocation-under-the-link-first-model.md) D6).
- **Name wave** — the background, child-first republish of a write-rotated scope under freshly derived names, root re-pointed last. Survivor write-grantees derive new names locally; read-only survivors follow republished mirrors (root re-point via the scope pointer; mailbox and old-name tombstone as accelerators).
- **Forgery window** — accepted residual: during the name wave a revoked writer can still seal plausible old-epoch records at not-yet-rotated old names. Wave-bounded for write-grantee survivors (they derive every new name locally); for read-only survivors, at most ~one pointer-consult interval past the re-point publish (a sync-timing-profile constant). The bound applies to **insertion**: an inserted record keeps its old epoch label until the lazy wave reaches the node, and the label attests nothing about who sealed the body ([ADR 0017](https://github.com/FSM1/cipher-box-next/blob/main/decisions/0017-the-epoch-tag-is-a-key-selection-label-not-an-attestation.md)). Old names retire from the republisher inventory (tombstones advisory only).

## Envelope and grants

- **Envelope** — the published plaintext wrapper of a node: format version, node id, epoch tag, the sealed bodies, and (at scope roots only) the grant section. Kind-uniform: whether a node is a file or a folder is sealed inside the read-body.
- **Write-body** — the sealed write-plane payload, present only at scope roots: the grant ledger plus the write-plane history link. Interior nodes publish none; all their write material is derived.
- **Blinded tag** — the opaque per-pair label a grant blob is keyed by, derived from an owner–recipient shared secret and the scope root's name. Observers learn only blob count; the recipient self-locates their blob.
- **Grant blob** — a scope's current seed(s) sealed to one recipient and keyed by their blinded tag, carried in the scope root's envelope. Read grants carry the read seed; write grants carry both seeds.
- **Grant ledger** — the authoritative record of a scope's grants, `(recipient, permission, tag)`, sealed in the scope root's write-body. A scope root holds any number of rows, link rows and personal rows together (ADR 0026 D1–D3). Writers re-wrap blobs for the recorded set during re-seals but cannot change the set; grant changes are owner-only. A re-seal takes every recipient encryption key off the grant-set commitment, never off a row, so a row with a swapped recipient misdirects nothing; the row's `recipientIdentityPk` is a field no commitment entry covers, and a re-mint drops it unless the row's own owner signature attests it. Each row carries an owner signature over `{ipnsName, recipientEncPk, recipientIdentityPk, tag}`, plus the **via-link reference**, the **grantee name** and its name source flag, each in the preimage only when present ([ADR 0023](https://github.com/FSM1/cipher-box-next/blob/main/decisions/0023-the-invite-link-is-the-primary-sharing-path-and-conversion-runs-by-itself.md) D2, [ADR 0027](https://github.com/FSM1/cipher-box-next/blob/main/decisions/0027-a-grantee-name-is-not-an-identity.md) D3). That signature is transferable: a co-writer can extract it and prove to anyone holding the owner's contact code that a given identity is a grantee of this scope root. Grant membership is non-deniable **within the grant set**: a co-writer reads the ledger, grantee names included, and any grantee or link holder of the scope unmasks the commitment's recipients under the scope `pointerReadKey` — which the invite link URL carries, so the URL alone unmasks them ([ADR 0024](https://github.com/FSM1/cipher-box-next/blob/main/decisions/0024-a-link-holder-reads-at-once-from-the-link-blob.md) E4). It stays invisible outside that set, since the ledger lives inside the sealed write-body and the commitment names nobody without the scope key.
- **Grant-set commitment** — the owner-signed `(tag, maskedRecipientEncPk, permission, pseudonymPk)` list in the scope root's envelope, plus the owner's own pseudonym key. Each entry may also carry the owner-signed optional fields `kind` (`personal` or `link`; absent means `personal`) and, on a **link entry** only, the `deadline`, the conversion permission and the admission cap (ADR 0023 D2, D9, ADR 0024 D4). Recipients verify their tag is committed before trusting a grant. Binds tag membership, recipient keys, writer pseudonyms and those entry fields only — never blob contents. A tag appears at most once. Every re-seal and every cut names its recipients from here, so a committed write grantee cannot swap the recipient of its own ledger row and leave a cut naming nobody. Carries no read epoch, so grantee-triggered rotation needs no owner signature, and a **cut epoch** so a pre-cut set is still refusable.
- **Masked recipient** — a grant-set commitment entry's `recipientEncPk` XORed with `committedRecipientMask(pointerReadKey, tag)`. The grant section is published in the clear and an encryption subkey is a global identifier, so the owner commits the recipient without naming it: the owner, every grantee, and anyone who holds an invite link URL of the scope hold the scope's `pointerReadKey` and recover the key, and no other observer does ("Grant ledger", ADR 0024 E4). The blinded tag is the mask's message, so one recipient masks to unrelated bytes at every scope root — the same unlinkability the tag itself buys, extended to the field the owner must sign.
- **Cut epoch** — the counter inside the grant-set commitment that the owner steps at every cut of a scope's grant set, and at nothing else — one step per owner revoke, whatever the number of rows it removes (ADR 0025 D4). The adoption gate refuses any commitment below the newest cut epoch that scope already adopted, so a committed write grantee cannot restore a pre-cut set by republishing the root, and a device learns the boundary from the record rather than only from its own memory of the cut.
- **Writer pseudonym** — the per-(scope, writer) signing keypair; its public key rides the grant-set commitment. A grantee's derives from the same pairwise ECDH secret as the blinded tag; the owner's derives from `ownerPseudonymSeed`, its own catalog edge, so the owner's signing authority does not ride its encryption subkey. Any envelope holder verifies committed-write authorship; only ledger readers map a pseudonym to an identity; observers see nothing linkable across scopes.
- **Structure signature** — the rotator's detached pseudonym signature over a seed-bearing structure's ciphertext and context `{scope, epoch, structure tag, recipient tag}`, carried by grant blobs, the owner blob, the owner write blob, ascent and history links, and the write-body. A missing or invalid signature is a whole-record trust violation at the adoption gate.
- **Encryption subkey** — the sealing key each user derives from their login secret, published signed by their identity key. The identity key only signs; the subkey only seals.
- **Contact label** — the fixed-width device-local label of a contact identity key, `contactLabel(contactLabelSeed, identityPk)`. Keys durable local state that would otherwise name a third party in the clear. Deterministic on one device and unlinkable off it, since the seed derives from the login secret; never published, or it becomes the cross-scope correlator the blinded tag exists to deny.
- **Name label** — the fixed-width device-local label a durable sequence-namespace floor key takes, `nameLabel(contactLabelSeed, key)`. It hides which record a durable floor bars replay on from a reader of local storage, and it is account-wide rather than per-contact, so one name keeps one sequence ratchet whichever view raises it.
- **Scope pointer** — the owner-keyed stable IPNS name every shared scope carries, `pointerKey(scope) = KDF(ownerPointerSeed, scope.id)`. Its record holds the re-point object; consulted on the sync tick for open shared scopes, on access for cached ones, and first on cold start.
- **Re-point object** — the owner-identity-signed `{scopeId, currentRootName, writeEpoch, minReadEpoch, prevRootName}` payload, published at the scope pointer (canonical) and mirrored to the mailbox and the old name's tombstone as accelerators. The cold-start floor anchor: `minReadEpoch` is bumped only by owner-triggered read rotations, so grantee rotations need no owner signature yet revocation boundaries cannot be rolled back.
- **Floor law** — floors advance only on an AAD-confirmed unseal and cold-seed from the re-point object's owner-vouched epochs, never from a raw blob field; a grant blob's epoch field is an advisory routing hint. One exception, and the list of them is closed: the cut epoch of a grant-set commitment that passed the adoption gate's stage 2 whole raises that scope's cut-epoch floor with no unseal, under the sharer-scoped key. The owner signs that field and the signed preimage names the scope root it is presented under, so it is not a claim the network authored.
- **Revocation floor** — the engine's durable per-scope, per-recipient record that the owner cut that recipient's grant **at that scope**. It is what an owner re-key consults to tell a descendant the owner cut from one it granted independently; an ancestor's cut never carries down on its own. The cut epoch is the scope-wide complement: it refuses the whole pre-cut set at the gate, while this floor withholds one recipient's blob at a re-key. Device-local, and it only rises except by the clear below; unlike the epoch and sequence floors it has **no cold-seed anchor**: no owner-signed record carries it, so a device that holds no floor yet takes the first commitment it is served. An owner-signed commitment that commits the recipient again, at a cut epoch not below the one this device recorded for its cut, clears this device's floor for that recipient (ADR 0025 D3). The clear removes this device's recorded cut for the recipient; the grant floor does not change, because a re-key withholds a blob only when a recorded cut is newer than the grant floor. A device that did not make the cut raises the cut epoch from the first post-cut record it resolves, whether or not it can adopt that record.
- **Vault pointer** — the indexed IPNS name chain derived from the owner's login secret, `pointerKey_i = KDF(secret, "vault-pointer" ‖ i)`, index 0 default; its record carries the root scope's re-point object. The cold-boot entry point; root write rotation re-points it. Clients probe one index past the highest known and adopt the highest valid owner-signed payload; an owner-side index bump is the pointer-key-compromise recovery; a first-run walk tolerates a failed endpoint once the registry confirms the name is unregistered (ADR 0022).
- **Vault settings record** — the owner's own client configuration (self-hosted node endpoints and the like), sealed HPKE-to-self under the encryption subkey and published at a dedicated IPNS name derived from the login secret, `settings-ipns-keypair`. Server-free by construction: it resolves at cold start with no CipherBox infrastructure, so a self-hosting owner never needs CipherBox to find their own node.
- **Bin index** — the one owner-sealed, vault-level record of every soft-deleted node, published at `bin-index-ipns-keypair` and sealed symmetrically under `bin-index-seal-key`. Owner-only by construction: no grant carries either key, so a scope's grantees never see the owner's bin.
- **Bin rung** — one of the frozen sizes a bin index body pads up to before the seal, so the published record's length discloses which rung the body reached and nothing finer. Without it the ciphertext length would count the owner's soft deletes, and the share of them that came from a shared scope. Each rung has a **cap**, the largest unpadded body it admits, which is what makes the rung a body takes rise with the body rather than jump at a padding gap.
- **Bin entry** — one soft-deleted node in the bin index: `nodeId`, `ipnsName`, `kind`, `originParent`, `originName`, `deletedAt`, `scopeId`, and an optional bin-held key. The `ipnsName` is the only remaining route to a record no folder names; `originParent` and `originName` are what a restore puts back.
- **Soft delete** — a delete that unlinks the node and writes a bin entry instead of retiring the record. The owner's bin retention setting chooses it; retention 0 keeps the hard delete.
- **Bin-held key** — the key a soft delete re-keys the doomed subtree under, from the `bin-held-key` edge. It sits outside every scope's derivation, which is the access cut key regression cannot give. Scope-seed shaped: every node of the subtree keys at `readKey(nodeSeed(held, nodeId))`, so the one key the entry carries opens the whole subtree.
- **Restore** — putting a soft-deleted node back into the tree. It re-seals the whole subtree at the destination scope's current epoch, which both returns the node to that scope's grantees and ends the bin-held key's hold on it, then relinks the node and drops the bin entry.
- **Purge** — destroying a soft-deleted node: the reclamation the soft delete deferred, then the bin entry. Irreversible, and refused unless the node is proven unlinked.
- **Bin expiry** — the poll tick queueing a purge for every entry whose `deletedAt` is older than the owner's bin retention, measured on the injected clock. It is what makes retention enforced rather than advisory, and the only thing that frees space under the bin index body's ceiling.
- **Owner capture** — the owner's engine binding an unlink it observes on the poll tick but did not author, and re-keying the node at that adoption. Without it a grantee who unlinks a node in the owner's scope leaves the owner nothing to restore, and keeps the node's read key.

## Sharing

- **Invite link** — the primary sharing path: a bearer, multi-claim URL whose fragment carries the invite secret, the owner contact code, the scope pointer name, the stable `pointerReadKey`, and the owner and folder names under an owner signature. It reads at once and writes only after conversion (ADR 0023 D1–D2, ADR 0024 D1, ADR 0027 D5).
- **Link entry** — a grant-set commitment entry of kind `link`, with its ledger row. Always committed at `read`, whatever permission conversion grants, and it carries the link's deadline, conversion permission and admission cap (ADR 0023 D2, D9, ADR 0024 D4).
- **Link holder** — a person who reads a scope through a link's keys and is not converted yet. Every holder of one link shares one key (ADR 0024 E3).
- **Grantee** — a converted or directly granted person, with a personal row and a personal blob. A link holder becomes a grantee when its personal blob first opens (ADR 0024 D2).
- **Claim** — the link holder's side of an invite link: the sealed, ephemeral-key-signed mailbox request that carries the claimant contact code, the scope pointer name and a suggested grantee name (ADR 0023 D2, ADR 0027 D1).
- **Conversion** — the owner's side: any owner engine, on its tick or when the share dialog opens, mints a claimant a personal row from owner-signed record fields, with no click and no approve step. It never changes an existing row (ADR 0023 D1–D4, ADR 0026 consequence 5).
- **Deadline** — the owner-signed time on a link entry by which an owner device must convert a claim. Conversion checks it once, at the ack, and stores the verdict. A link holder's read checks it at the join and on every refresh pass. The claimant stops its re-posts at it. An owner sweep cuts a link whose deadline has passed (ADR 0023 D3, D6, ADR 0024 D5, ADR 0025 D2).
- **Admission cap** — the owner-signed limit on the live rows whose via-link reference names one link; conversion refuses a claim at the cap, and a revoke frees a slot (ADR 0023 D9).
- **Grantee name** — the owner-signed, owner-editable name on a grantee's ledger row. A claimant's name is only a suggestion, flagged `claimant` until the owner edits it; it is not an identity, and every owner act binds to the identity key (ADR 0027 D3, D6).
- **Preview mode** — a read-only mode of the link read in the signed-in session engine: it posts nothing, persists nothing, deposits no seed and raises no floor (ADR 0028 D3).

## Sync and refresh

- **Sync timing profile** — the environment-scoped bundle of sync timing policy: record TTL, poll cadence, staleness thresholds, escalation window. A named constant set, so a per-device measured byte count belongs to the storage policy instead. Records always set TTL explicitly; TTL is independent of EOL.
- **Storage policy** — the per-device split of the host's measured storage headroom, computed once at construction and injected: the staging budget bounding staged upload bytes, and the read-cache ceiling reserved off headroom before the staging fraction. Never a live host query inside a staging read-modify-write. A host that cannot measure headroom yields an _unmeasured_ policy — the same zero budgets, since there is no floor-up, but reported as unmeasurable rather than full.
- **Focus window** — the set a poll tick refreshes: the vault pointer, the open folder, and its ancestor chain to root. Everything else refreshes on access.
- **Manual refresh** — a host-forced sync pass, brought forward onto the tick loop by `Command::ManualRefresh` rather than run beside it. Resolves nocache: the pass reads no snapshot cache, so its verdict is only what the record plane served it — never a success repainted off cached bytes, though a failed pass leaves the host's last-known-good view standing. Requests coalesce onto one pass, and the command reports every read leg that pass forced, the focus window included — an unreachable record fails it, a rejected one is a trust violation.
- **Pending-op overlay** — the client state law: rendered state is the last-known-good remote snapshot with queued ops applied on top; the op queue is the only local divergence.
- **Op queue** — the durable FIFO journal of intent ops every mutation rides. Offline replay and online CAS rebase re-apply ops through the same path.
- **Op record** — one durable queue entry: `v ‖ ownerTag ‖ contentRootCid? ‖ sealed(op)`. The body seals HPKE-to-self; the header stays clear so a version routes before an open, ownership routes before decryption, and orphan GC expands a staged root keylessly. The clear-header framing is frozen across format versions.
- **Owner tag** — the owner's `enc-subkey` public half verbatim, stamped on every op record. The op queue is per origin, not per account; the tag names exactly the key that opens the body, and is compared byte-for-byte **before** any decode.
- **Retained record** — a durable queue entry this session holds but does not act on: another identity's, one written at a format version this build does not implement, or one whose seal opened but whose intent body is a grammar this build does not implement. Never replayed, never surfaced as this account's, never removed, and its staged root still counts as referenced so orphan GC leaves its bytes alone. Only an _undecodable_ record — one that fails to decode at all — is dead-lettered and removed; retention is what stops a second account's login, a format bump, or a newer build's op from destroying an unpublished queue.
- **Adoption gate** — the trust pipeline every resolved record passes before adoption: signature verify, commitment verify, structure signatures against committed write pseudonyms (scope roots), strictly-newer sequence vs floor, epoch at or above the scope floor, except for an interior record that one of the three sanctioned lagging readers opens under the scope root's ratchet, unseal success. A failure is a fail-closed trust violation, never mere staleness. The one exception is a lagging reader's record whose epoch the scope root's ratchet does not reach: it is reported unreachable, not as a trust violation ([ADR 0021](https://github.com/FSM1/cipher-box-next/blob/main/decisions/0021-a-read-opens-an-epoch-lagged-interior-record.md) D5). A **preview** checks against the floors the session already holds and raises none ([ADR 0028](https://github.com/FSM1/cipher-box-next/blob/main/decisions/0028-the-invite-page-previews-before-join.md) D3).
- **Conditional delete** — a delete op snapshots its target's own record sequence; on rebase it is dropped if the target advanced. Edit wins in both directions: a rebased edit resurrects a concurrently deleted node.
- **Observed repair** — cleanup of an invariant violation noticed at read time by any write-capable client, e.g. removing the losing link of a dual-linked child.
- **Dual-link** — one child linked in two parents, the benign crash residue of a dest-first move; repaired deterministically via the child ref's monotonic link counter.
- **Dead-letter** — a queued op that terminally fails rebase, surfaced to the user with any staged content preserved rather than silently dropped.
- **Withheld-update escalation** — the shared-scope warning raised when a name stays pinned past a profile window while other resolves succeed; the reader-side signal for a stale-view pin.

## Core crate

- **KDF edge catalog** — the frozen enumeration of every key-derivation edge (context string + input layout) in `crates/core`; nothing derives a key outside it. Per-node material is `keyed_hash(key = derive_key("<edge context>", seed), message = id16)` — ids are fixed-length message input, never variable context.
- **Structure tag** — the domain-separation registry entry naming each sealed/signed structure (read-body, write-body, grant-blob, owner-blob, ascent-link, history-link, pointer-payload, mailbox-payload, owner-write-blob, op-record, settings-record, content-key, owner-local, write-history-link, bin-index); bound into the AAD and the structure-signature preimage.
- **KAT manifest** — the machine-checked enumeration of every frozen encoding and the vector files locking each; tests and CI consume it, so the KAT'd surface is auditable rather than folklore.
- **Acceptance domain** — the part of the frozen contract covering what a codec rejects: reject-vectors (duplicate keys, non-canonical encodings, transplants, bad signatures) ship alongside accept-vectors from day one.
- **Separation KAT** — the mechanical assertion that no two KDF edges produce equal output for equal inputs, run over the whole edge table.

## API residual surface

- **Name inventory** — the per-account `(account, ipnsName)` registry feeding the republisher. Membership derives from pin registration on the publish path, never from a side-channel.
- **Register-first** — the fail-closed ordering law: a name/CID batch registers before its first publish, and publish blocks on it. Live-but-uninventoried is structurally impossible; the residual failure is a registered-never-published orphan, alert-GC'd.
- **Union liveness** — a name stays in the republish inventory while any account holds a row for it; it leaves when the last row retires. Physical unpin fires at global refcount zero.
- **Advisory pin row** — a BYO account's registration: counted for union liveness and the inventory, never quota-enforced; the bytes live on the user's own provider.
- **Root linger** — after a write rotation, the old scope-root name stays registered serving the owner-signed `movedTo` record until the migration window closes; interior old names retire at wave completion.
- **Read accelerator** — CipherBox's token-authed Kubo trustless gateway. A member convenience on the read path; any public trustless gateway is the no-auth fallback.
- **Accelerator token** — the read accelerator's credential: an opaque, read-scoped per-session pseudonym minted beside the access token and rotating with it. Never the session JWT, and never identity-bearing, so the gateway tier can attribute nothing it observes. Valid only while its refresh family is, so every session revocation revokes it too.
- **Recovery endpoint** — authenticated fetch of non-canonical cached record bytes by name; the revival aid after a >EOL liveness lapse, on no client resolve path.
- **Contact code** — the self-authenticating bundle `{identityPk, encSubkey, bindingSig}` exchanged out-of-band (QR/URL); binding verification at import is mandatory and fail-closed. Replaces any people directory. A contact-code grant is the advanced sharing path; the invite link is the primary one (ADR 0023 D1). The device-local **contact book** caches grantee names to pre-fill them and is no trust input: conversion and revoke read only the record (ADR 0025 D3, ADR 0027 D4).
- **Mailbox** — the API's integrity-untrusted sealed-pointer transport: post to a recipient pubkey, poll, ack-deletes; bounded until-acked retention. The ack answers whether that call removed the item, which is the lock that lets one owner device convert a claim (ADR 0023 D5). Every payload is sender-identity-signed inside the seal, verified against the contact-code-anchored key; unauthenticated items are dropped. Carries discovery and courtesy traffic only, nothing load-bearing for safety.
