### What landed
`Command::Move { node, new_parent, new_name, replacing }` → `OpKind::Move { from_parent, new_parent, new_name, replacing: Option&lt;Replaced&gt; }`, staged as **one** durable op-queue entry. `crates/fuse`'s `OperationCore::rename` collapses onto it; the three-op `Delete`/`Relink`/`Rename` sequence is gone. ### Rebase rule chosen
`rebase_move` = the relink rule's races, then the rename rule's collision resolution, over a destination it **vacates first** (that's what makes a replace land under the entered name instead of `target (2).txt`). The vacate is conditional on the replaced node still being the one holding the contested name — same parent, name collates equal, and not advanced past the conditional-delete anchor. So a concurrent edit still wins (mover auto-suffixes), and a node renamed or moved away is a bystander that survives untouched. Name resolution happens before any mutation, so a `SuffixExhausted` dead-letter leaves the working base clean.

### Publish plan
Rename, relink, and move now share one `publish_ref_move` driven by a `MovePlan`. Same-folder source/dest collapses the whole replace into a **single record**. `compensate_dest_add` restores the vacated ref, but only in the versioned-safe branch.

**Branch** `feat/867-drain-failure-policy` · **PR** [#898](https://github.com/FSM1/cipher-box/pull/898), left in **draft** as instructed. Two commits.

### What landed

**The failure valve** (`crates/engine/src/sync/drain.rs`) — a single `Halt` enum classifies whatever stops a pass: `Unclassified` (retried indefinitely, charged nothing), `Attempt` (a publish that reached the record plane and did not confirm — charged against a 5-attempt budget, ending in `AttemptsExhausted` with no retire), `Permanent` (dead-letters with the retire), `Blocked` (holds the head, not a failure).

**The `Blocked` class** — `ApiError::Status` learned the `code` discriminator #848 ships. Positive evidence only: `QUOTA_EXCEEDED` holds the head with its staging reservation, left solely by a `GET /account/quota` probe on a later tick (`pre_flight_quota_check`'s first production caller). Read out of `SnapshotView`, never an event.

**Abandonment retire** — the gate-passing base decides, not the attempt count: a name a published record already references is never retired, one nothing references always is. The drain deletes no staged bytes.

**Dead letters reach the host** — `DeadLetterReason` crosses `SnapshotView.dead_letters`, `Event::DeadLetter`, and the wasm/worker boundary into `packages/client`.

**Over-budget reasons** — `EngineError::OverBudget { cause }`; `crates/fuse` drops its duplicate enum for the engine's; `blueprint/desktop.md` stops collapsing `EDQUOT` into `ENOSPC`.

**How the ledger prevents over-admission:** a reservation is the version's *whole sealed total*, taken at `beginWrite` and held until release — not spent as bytes arrive. Two handles opened before either stages anything therefore see each other's reservations in `staged + reserved`, so the second is refused with `budget - (staged + reserved)`. `pushChunk` never re-checks.

**Suffix invariant under a mid-upload crash:** leaves are removed only on a confirmed upload, so still-staged blocks are a suffix; the root is uploaded last but held until the record publishes, so a retry always has the manifest to re-derive from. Reviewers found the original inference unsafe — an absent leaf *before* the first present one was assumed uploaded, so a partially-evicted store would silently publish a version whose manifest names blocks nothing holds. Progress is now durable (`UPLOAD_MARK_KEY`); an absence past the mark is loss and dead-letters.

**The two rule-8 guards** are structural, not checked: `NewNodeBody`/`NewNode` make a folder-with-content unrepresentable in both the wire authoring and the op grammar; `SealedContent` carries `content_cid`/`size`/`leaf_cids` from one decoded manifest and yields the `Version`. Both are covered by plain `#[test]`s (`a_new_child_agrees_with_its_parent_ref_on_kind_for_every_kind`, `a_published_version_carries_its_own_manifests_size`) that fire in release.

## PR

## The surface I decided

`POST /content/upload` carries the caller's content address in an **`X-Content-Cid` header**; the pin store writes the block with `block/put?cid-codec=&lt;from the declared CID&gt;&amp;mhtype=blake3&amp;mhlen=32&amp;pin=false`, compares Kubo's returned `Key` to the declared string, and only then pins it **direct** (`pin/add?recursive=false`). `PinStore.hash` is deleted — the API computes no content address of its own.

Three decisions worth flagging:

- **Header, not query param.** The crypto review caught that a CID in the URL reaches edge/proxy access logs, while the registry's `contentCids` already travel in JSON bodies. Content addresses correlate across accounts (same CID in two accounts = shared content), so this was a real exposure widening. The header also removed URL interpolation from the engine client entirely.
- **Direct pins, not `block/put --pin`.** I verified against the local Kubo v0.42.0 that `--pin` creates a *recursive* pin, and a `dag-cbor` block whose bytes are not decodable CBOR then **aborts repo GC for the whole node** — any authenticated account could have parked one. Direct pinning also makes Kubo itself reject such a block at `pin/add`.
- **Codec by CID prefix in TS, not a decoder.** `bafkr4i`→`raw`, `bafyr4i`→`dag-cbor`. This cannot be a trust hole: the codec is embedded in the address Kubo returns, so a wrong mapping just fails the comparison. Both reviewers independently confirmed the prefixes are correct and unambiguous over all 128 single-byte codecs.

I confirmed `block/put` supports this against the local Kubo before writing any code.

## What the contract assertion proves

The load-bearing proof is a **gateway round-trip**, not the echoed CID — the API answers with the address it was handed, so equality alone is tautological. `upload_pins_under_the_caller_computed_content_address` fetches `/ipfs/&lt;declared&gt;?format=raw` back and byte-compares, for a `raw` leaf and a real `assemble`d `dag-cbor` root. It also proves a mismatched declaration is a permanent 400 with the quota charge compensated, and that a non-canonical or wrong-codec CID never leaves the client. Runs in the existing merge-blocking `contract-suite` job (new `CONTRACT_GATEWAY_URL`; the leg fails loudly if it's missing — verified by unsetting it).

## Review gates — real findings folded back

- **HIGH, both reviews:** `block/put` persists before the address can be checked, and unpinned blocks are never reclaimed (the daemon runs without `--enable-gc`). A caller declaring a wrong CID grew the datastore ~120 MiB/min *with its quota charge refunded*. Now every non-pinning path `block/rm`s the block; verified Kubo refuses to remove a pinned block, so the cleanup can't touch another account's content.
- `MAX_UPLOAD_BYTES` was 50× the 2 MiB `block/put` ceiling, turning a permanent size failure into a retryable 503 that wrote a fresh orphan per attempt. Now defaults to the block ceiling → permanent 413.
- A `block/put` response with no `Key` blamed the caller with a 400 for a store fault; narrowed the client-side codec guard to the two the ingress accepts; compensation failure now logs at `error`; fixed `HeadCidMismatch`'s doc, which claimed something no longer true.

- Drain classification of a 400 (`Halt::Unclassified`) — only reachable from a client bug, belongs to the content-write slice.
