```rust
impl GatewaySource {
    /// The only way to attach a credential: TLS or no token.
    pub fn accelerator(base_url: impl Into&lt;String&gt;, bearer: SessionBearer) -&gt; Self {
        let base_url = base_url.into();
        if carries_credentials_safely(&amp;base_url) { Self { base_url, bearer } }
        else { Self::public(base_url) }
    }
}
```

### 1. Header injection — clean, both layers agree

`packages/client/src/media/range.ts:61` — `ATTR_CHAR = /[A-Za-z0-9!#$&amp;+\-.^_\`|~]/` is **exactly** RFC 8187 `attr-char` (ALPHA / DIGIT / `!#$&amp;+-.^_\`|~`). `^` is not in leading position so it is literal; `\-` is literal. Everything else — `"` `;` `,` space CR LF `*` `'` `=` and every byte ≥ 0x80 — is percent-encoded (`range.ts:63-68`, encoding UTF-8 bytes, so multi-byte names are handled correctly). No second parameter, no second header, no change of disposition type is reachable from a name.

`packages/client/src/sw/pipe.ts:392` — `SAFE_DISPOSITION` is anchored `^…$` (JS `$` does *not* match before a trailing `\n`, unlike Python/Ruby), and has a single `*` over a flat character class inside one optional group — linear, no catastrophic backtracking. Two ports appending two `content-disposition` headers is also handled: `Headers.get` joins with `", "`, which fails the regex and clamps to bare `attachment`.

The only divergence between the two: the worker's class adds `%` unconditionally (`pipe.ts:392`), so it accepts `%`/`%ZZ` sequences the encoder would never mint. Harmless — `%` is not a delimiter, and a decoded `%3B` lands inside the filename value after parameter parsing, not in the header grammar.

Residual (unchanged by this PR): the decoded filename can still contain `/`, `..`, NUL, or an RTL override — defense is the browser's download-filename sanitizer, exactly as it was for the old `&lt;a download&gt;` attribute. Not a regression.

### 2. Render path — not weakened

`apps/web/src/hooks/useFilePreview.ts:62` calls `streamTicket` with four args, so `downloadName` is `undefined` and `range.ts:83` pushes no header. The player never gets a disposition. `nosniff`, `default-src 'none'; sandbox` and the `safeMimeType` clamp in `pipe.ts:378-381` are applied identically on both paths; the disposition is additive.

One thing this design now depends on that it did not before: **CSP `sandbox` on the response is what keeps the frame unreadable.** If the pipe ever serves a ticket body without a disposition, the response commits as a document *inside a same-origin frame the app owns*; `sandbox` gives it an opaque origin so `frame.contentDocument` is null. Dropping that header from `sealed()` would turn the hidden frame into readable plaintext. Worth a comment at `pipe.ts:381` — it is currently justified only as anti-execution.

### 3. The iframe — no new exposure

The ticket URL was already in the DOM as `link.href`, and any same-origin script can `fetch()` it regardless. The frame adds nothing an XSS did not already have. A cross-origin embedder cannot read either. The frame never commits a document (the response is a download), so there is no history entry and nothing to read out of it. `finally` at `useFileDownload.ts:94-100` removes the frame on every path — success, failure, refusal, and throw — and `saveTicketToDisk` is called outside the `try` only to build it, so there is no window where a frame exists without a teardown scheduled.

### 4. Ticket lifetime — no truncation; two bounded overstays

`whenIdle` (`packages/client/src/media/broker.ts:153-176`) resolves only when no cursor holds the ticket, and a reader *between windows* still counts, so a stalled or paused download cannot be revoked out from under itself. `revoke` (`broker.ts:200`) therefore only ever fires after the worker's body already closed — the remaining bytes are the browser's. No truncation path found.

The inverse holds in two edges, both pre-existing in `whenIdle` and now also holding a DOM node:
- a download the user pauses keeps `cursors &gt; 0`, `expire` re-arms indefinitely, and the ticket stays a live capability for the duration;
- worker death is recovered — `MediaBroker.serve` calls `close()` (`broker.ts:117`), which re-arms every waiter with a fresh 30 s deadline — so that path does not leak.

### 5. DoS — bounded

`saveAll` awaits each `save` (`useFileDownload.ts:121-126`), so at most one frame, one ticket and one pin exist at a time, and `refused` breaks the loop. Concurrent clicks are bounded by user actions and each cleans up in its own `finally`. Nothing accumulates.

### 6. FINDING — a second open tab breaks every save

`install.ts:115` passes `event.clientId` to the pipe. Per the Service Worker spec, `clientId` is set only for **subresource** requests; a navigation carries `""` (the new client is `resultingClientId`). The old `&lt;a download&gt;` was a subresource-ish fetch that never reached the worker at all; the new frame navigation reaches it **anonymously**.

`pipe.ts:298-305` then routes anonymous requests to the *newest adopted port* — not the saving tab's. With two vault tabs open, tab A's save is offered to tab B's port, whose registry never minted that ticket, so the broker answers `404` (`broker.ts:341-345`), the frame gets no download, and `whenStreamIdle` sits the full 30 s before returning `refused` → "the browser did not start the download". `saveAll` then aborts the whole batch.

It fails closed — no cross-tab plaintext, and the innocent tab's port is not discarded (a `404` head returns rather than calling `discardPort`) — so this is availability, not confidentiality. But it defeats the per-client isolation the suite explicitly asserts at `packages/client/src/sw/pipe.test.ts:551`, and the e2e test is single-tab so it cannot catch it. The fix is to key the lookup off `event.resultingClientId` for navigations, or to make the pipe fall back to *broadcasting* the open and taking the port that recognises the ticket.

Please confirm the `clientId === ""` premise with a two-tab manual save before acting on it — everything downstream follows from it, and I could not exercise a real browser here.

### 7. The e2e spec

`tests/web-e2e/tests/save-path.spec.ts` is strong for the defect it targets: it asserts the URL is `/stream/` (rejects the blob fallback, line 30), the `suggestedFilename` (line 33 — Playwright derives this from `content-disposition`, so a clamped-to-bare `attachment` would yield the ticket segment and fail), and byte equality against the upload (line 36 — rejects the `index.html` shell).
