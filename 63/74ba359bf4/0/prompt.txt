6. Through extensive analysis, I identified the root cause:

The bug is in the server's `upsertFolderIpns` method in `apps/api/src/ipns/ipns.service.ts`. When creating a NEW IPNS entry (first publish for a given IPNS name), the server initializes `sequenceNumber: '0'` and does NOT increment it. But when UPDATING an existing entry, it increments by 1. The client always assumes each publish increments the sequence by 1 (`newSeq = params.sequenceNumber + 1n`).

This causes a mismatch:
- After first publish to a new IPNS name: Server DB has seq='0', Client stores seq=1n (0+1)
- On the second publish: Client sends expectedSequenceNumber="1", Server has "0" → 409 Conflict!

The retry mechanism (resync then retry) SHOULD theoretically work because:
1. resyncFolder resolves IPNS → gets seq='0' from DB
2. Updates store with seq=0n
3. Retry sends expectedSeq="0" → matches server's "0"
