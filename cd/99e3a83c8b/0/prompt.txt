### Key Findings

1. **The primary parallelization opportunity is between steps 2 and 3 of the upload flow.** The file IPNS batch publish and folder metadata update (pin + IPNS publish) have no data dependencies on each other. 2. **Steps 1a and 1b (ciphertext pin + file metadata pin) CANNOT be parallelized** because the file metadata embeds the CID from the ciphertext pin. The baselines document incorrectly suggested pins 1+2 could be parallelized -- the actual dependency chain makes only steps 2+3 parallelizable.

3. **Kubo pebbleds is the recommended datastore alternative to flatfs** if per-pin latency needs further reduction. Badgerds is explicitly deprecated and scheduled for removal. PebbleDB (LSM-tree) has faster write throughput than flatfs, though at the cost of higher memory usage and read amplification. No published benchmarks exist for pebbleds vs flatfs v0.40.0, so empirical testing is needed.
